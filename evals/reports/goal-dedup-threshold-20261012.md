# GD3：GLM 目标去重“可能重复”门槛标定

结论：按规划者预先登记的规则，选择 **0**，将 `goal_dedup_judge.possible_min_similarity` 的临时默认值从 0.6 调回 0。所有正门槛都会损失应合并识别，不能在保持识别率的同时减少标记。默认 0 下不应合并中标可能重复仍为 **22/39（56.41%）**，标记偏多的问题尚未解决。C2 模型判断继续默认开启，自动合并规则不变。

## 输入与方法

- 基线：`4e70ee65691a445a8a64883643703e2a136805fb`，包含 #90、#96 及 2026-10-12 保留 GLM 的决定。只读公开 `evals/goal_dedup_v1.json`，没有改语料、提示词、评分或 runner，没有寻找或读取隐藏集。
- 67 例：merge 28、separate 29、uncertain 10。incoming 为 host 49、internal 18；本集没有 incoming admin。每例用隔离数据库与语料固定时钟，按 origin 走真实宿主注入或学习写入路径，internal 提交后调用真实 `Goals.review`。原有管理员不自动合并的规则由产品测试覆盖。
- GLM `glm-5.3-flash`，reasoning high，C2，runner **60 秒测量预算**。先在门槛 0 收集一轮完整判断；串行、案例间等待 2 秒。38 次实际调用全部 HTTP 200，无 429、降级、无效轮或重跑。没有运行 CPU 压测。
- 按 GD3 授权，使用一次真实收集加离线网格，代替 GD2 旧计划中的逐格双轮。网格固定为 0／0.4／0.5／0.6／0.7／0.8／0.9，选择基线在真实运行前写定为 **0（未过滤的旧行为）**，不把尚未标定的临时 0.6 造成的识别损失当作可接受基线。
- 仓库外脚本导入原 runner，七个格点各重新建立 67 个隔离数据库，使用同一批模型原始正文通过 `httpx.MockTransport` 回放。回放禁用真实网络和配置加载，逐次核对模型 messages、purpose、调用次数及自动合并结果完全相同；0 格点还逐例核对最终去重决定与可能重复目标和真实轮一致。469 次案例回放、266 次本地传输，新增真实调用 **0**。
- 相似度仍为 `normalize_claim` 后的 `SequenceMatcher.ratio()`；使用产品真实创建／补判代码计算，而非按标签推断结果。门槛只过滤弱标记，原始序列冲突和 uncertain 等歧义仍阻止自动合并。七格点的 13 次自动合并逐例、目标 ID 均相同。
- “不应合并中标可能重复”按 separate＋uncertain 共 39 例计；应合并识别按正确自动合并或指向正确目标的可能重复计。误合并分母为实际自动合并次数，没有用 0/0 宣称达到。

## 选择与失败类型

规则要求误合并为 0、识别率不低于基线，再最小化不应合并中的标记率，并列取较小门槛。本轮基线 28/28；唯一符合识别约束的是 **0**，因此它也满足“所有正门槛都降识别时，取不降识别的最大门槛”的兜底规则。0.4 虽少标 2 个不应合并案例，却漏掉 3 个应合并案例，不能采用。0.6 相比 0 少标 7 个，但漏掉 12 个，也不能保留为标定默认。

所有识别损失均来自 C2 数字／否定序列冲突配对的弱标记被正文相似度过滤；它们仍不进入自动合并。最低正格点 0.4 已漏掉：

| 案例 | 类型 | 相似度 | 表达差异 |
| --- | --- | --- | --- |
| GD006 | 换说法 | 0.322581 | 核对游记公里数／检查里程有没有写错 |
| GD008 | 换说法、补充日期 | 0.322581 | 存播客备份／备份指定日期的原始音频 |
| GD043 | 询问 | 0.387097 | 是自己修好的吗／是不是亲手修的 |

0.5／0.6／0.7 分别累计损失 9／12／14 例，0.8 与 0.9 仍损失同样的 14 例。简单正文相似度无法在此集区分有必要保留的改写提示与多余标记；本步不改候选、序列保护、提示词或模型决策来弥补。隐藏集仍由规划者复核；单轮模型输出加确定性重放不能估计模型跨轮随机性。

## 调用、耗时与产品改动

实际 38 次调用，输入 32,534 token，输出 3,057 token（其中服务商报告 reasoning 2,158，不重复相加）。真实轮墙钟 **212.69 秒**，包含案例间等待；67 例创建／补判耗时 P50／P95 **1.337／2.501 秒**，host 49 例 P50／P95 **1.008／1.925 秒**。这些是本轮诊断数据；LN 同期运行学习评测，不作独占性能验收或产品 5 秒预算结论。

产品仅修改 `src/iris/goal_dedup_judge.py` 中运行设置默认常量 0.6 → 0；该模块是 `runtime_settings.goal_dedup_judge` 缺省值的实际定义位置。没有改变自动合并、补判调度、5 秒同步预算或 30 分钟兜底。已显式持久化的设置（包括 0.6）仍优先，不自动覆写；需要切到标定值时使用现有 `Goals.configure_dedup(possible_min_similarity=0, actor="admin")`。既有可能重复关系不批量改写。
