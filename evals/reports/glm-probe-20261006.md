# GLM 探测：推理开关、耗时与内容安全信号（2026-10-06）

火山引擎方舟上的 glm-5.3-flash 不能关闭推理，可以用 `reasoning_effort="low"` 降低强度。现有参数对应默认 max 档，learning_v3 的单次学习耗时 P50 为 90.32 秒，6/16 次超过 120 秒，最长 344.03 秒；low 的 P50 为 6.31 秒、最长 18.81 秒。v3 学习总 token 从 143,034 降至 44,835，输出 token 减少 94.31%。两组均完成全部 15 批，但默认档发生一次长度截断并修复。

速度收益伴随本轮质量下降：精确率 70.37%→66.67%，证据正确率 85.19%→78.57%，归属正确率 88.89%→71.43%，别名精确率 100%→42.86%。**应实现可配置的 GLM 推理档位并补做对照，不宜仅凭耗时直接把 low 设为产品默认。**这是每档 10 段 dev、各一次独立盲判的观察，尚未重复验证，不作因果退化或门槛结论。

160 次学习请求均返回 HTTP 200，没有学习总超时或 429；另有一次 embedding 读超时。9 个 sensitive 样本在两档中各产生 24 次学习调用，均为 HTTP 200 / stop，没有实际内容拒绝。拒绝分类依据官方文档，不能据这些样本宣称过滤功能已验证。

## 服务商接口与官方依据

仅通过 `IRIS_TEST_MODELS` 加载配置并提取对话 `base_url` 的主机名识别服务商：**火山引擎方舟**。报告不保存配置端点、主机名或密钥。以下是 2026-10-06 查阅的官方资料；实测使用配置中的 `glm-5.3-flash`，文档通常写作 `glm-5-3-flash-260828`。不能只因参数被接口接受，就认定底层强制执行了该功能。

- [深度思考](https://docs.volcengine.com/docs/ark/deep-thinking?lang=zh)：GLM-5.3-Flash 始终启用思考，不能 `thinking.type=disabled`；`reasoning_effort` 默认 `max`，`none/minimal/low` 映射为 `low`，`medium/high` 映射为 `high`，`xhigh/max` 映射为 `max`。因此本次 B 是低强度推理，不是关闭推理。
- [Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)：推理可在 `choices[0].message.reasoning_content` 返回；用量路径为 `usage.completion_tokens_details.reasoning_tokens`。`completion_tokens` 已包含推理，`total_tokens=prompt_tokens+completion_tokens`。该页通用字段的模型列表并不完整，具体 GLM 返回以本次实测补充。
- 同一 [Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1) 的通用说明将 `max_tokens` 定义为回答上限，另列 DeepSeek 例外；`max_completion_tokens` 控制回答加推理，二者不能同时设置。**本端点实测与通用说明不完全一致**：维持现有 `max_tokens=16000` 的默认档 F010 首次调用，在 `completion_tokens=16000`、其中 `reasoning_tokens=15776`、正文为空时返回 `finish_reason=length`。后续良性小请求分别验证 `max_tokens=64` 与 `max_completion_tokens=64`，两者均被接受，默认档都在包含推理的总输出 64 token 处截断；不能假定 GLM 的回答另有独立预算。完整学习仍用原有字段和 16000 上限，没有验证替换预算字段后的完整质量。
- [结构化输出](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=zh) 要求按模型能力使用 `response_format`，`json_object` 提示中也应要求 JSON；[模型列表](https://docs.volcengine.com/docs/82379/1553576?lang=zh) 的 GLM-5.3-Flash 行未标结构化输出能力。此次接口接受 `response_format={"type":"json_object"}`，但这不足以证明有约束解码保证；必须分别统计严格 JSON 和现有宽松解析器的成功率。PR #6 已有 4/189 次非严格 JSON 的反例。

### 内容安全与错误语义

[方舟错误码](https://docs.volcengine.com/docs/ark/error-codes?lang=zh) 使用 `error` 对象中的 `code`、`type`、`message`，不能按 MiniMax 的 `base_resp` 或两个 sensitive 布尔值推断。以下为文档格式，不是本次人为构造拒绝得到的结果。

| 场景 | HTTP / 文档错误类型 | code | message 的典型片段或含义 | finish_reason |
| --- | --- | --- | --- | --- |
| 输入文本审核 | 400 / BadRequest | `SensitiveContentDetected`、`InputTextSensitiveContentDetected`；可能带细分后缀 | `input text may contain sensitive information`；可附请求 ID | 错误体通常没有 choices，未提供 |
| 输出文本审核 | 400 / BadRequest | `OutputTextSensitiveContentDetected` | `output may contain sensitive information` | 错误体未提供 |
| 附加风控产品命中 | 400 / BadRequest | `InputTextRiskDetection`、`OutputTextRiskDetection` | 文本命中内容风控，可能附 CSD 请求 ID／标签 | 错误体未提供 |
| 风控服务故障 | 400 / BadRequest | `ContentSecurityDetectionError` | 风控产品调用发生内部错误 | 未提供；不能当成已判定内容违规 |
| 成功响应路径中的输出过滤 | 正常 completion 响应 | 不要求 error.code | 不要求 error.message；内容可能为空或不完整 | `content_filter` |

最后一行来自 [Chat API 的 finish_reason 定义](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)。文档同时定义 `stop`、`length`、`tool_calls`；`content_filter` 即使带有部分正文也应识别为内容拒绝，不能进入学习写入或 JSON 修复。未实际观察到拒绝时，不对本端点究竟采用 400 还是 completion 过滤路径作进一步推断。

表中的 BadRequest 是错误码表的分类，不保证响应的 `error.type` 必定填这个字符串。[内容安全护栏的官方错误体示例](https://docs.volcengine.com/docs/ark/content-safety-guardrails?lang=en) 含 `error.code/message/param/type`，其中 `param`、`type` 可为空字符串；分类应主要依据 code，不能依赖 type 必填。GLM 属于三方模型，护栏文档说明此类模型有基础过滤机制及可选的自定义审核；本次没有检查或修改服务端审核配置。

[错误码表](https://docs.volcengine.com/docs/ark/error-codes?lang=zh) 还区分：

| 错误 | 建议分类与动作 |
| --- | --- |
| 400 `InvalidParameter` / `MissingParameter`；404 模型或端点不存在 | 配置错误；修参数，不盲重试。关闭推理的小探测实际命中了第一项。 |
| 401 `AuthenticationError`；403 权限拒绝 | 鉴权／授权错误。 |
| 400 `InvalidSubscription`、401 `InvalidAccountStatus`、403 `AccountOverdueError` / `OperationDenied.ServiceOverdue` | 账户或订阅问题；不能仅依 HTTP 码归入配置／鉴权。 |
| 429 RPM／TPM／并发上限类；`ServerOverloaded` / `RequestBurstTooFast` | 可重试的限流／容量问题；降速并退避。 |
| 429 `QuotaExceeded` / `SetLimitExceeded` | 结合具体语义区分额度用尽、周期限额、排队数超限；前两者不能按瞬时限流反复重试。 |
| 500 `InternalServiceError` 与传输错误／总超时 | 可重试；保留分类及诊断，超时不等于内容拒绝。 |

[上线常见问题](https://docs.volcengine.com/docs/ark/go-live-faq?lang=zh) 与 [突发流量实践](https://docs.volcengine.com/docs/ark/traffic-burst-handling-best-practices?lang=zh) 建议平滑增长、排队、重试，并说明同模型资源池共享。客户端指数退避加随机抖动、尊重有效 `Retry-After` 是本报告的实现建议；并非本次已验证服务端必定发送该 header。若使用官方排队 header，须把排队时间计入总超时，并受调度层累计预算约束。

## 调度分支合入后的适配建议

1. **显式配置推理档位，暂缓默认切换。**支持 `reasoning_effort=low/high/max`，将档位写入评测指纹与报告；保持默认 max 作为对照，先让 low 成为 dev 选项。不要发送不支持的 `thinking.type=disabled`，不要把 none 称为关闭推理。本轮速度收益很大，但证据、归属和别名精确率下降，需两档各重复一次并按既定规则比较平均值，再决定默认档；high 可作为后续待测折中，当前没有其耗时或质量证据。
2. **按档位设置超时。**low 的本轮全部 79 次学习请求最长 20.641 秒，dev 可继续用 120 秒总超时，无数据要求升到 180／240 秒。默认 max 的 v3 有 3/16 次超过 240 秒，单纯升到 180／240 仍截断长尾；需要保留 max 的诊断与离线评测使用显式 600 秒覆盖，本轮足够但不保证未来全部完成。不要把 600 秒直接设成所有产品调用默认值。调度层给学习、修复及网络重试共同设置有界预算和取消机制，分别记录原因，避免一个批次反复占槽。
3. **维持评测并行 4，允许降到 1。**小样本中并行 4 减少墙钟等待，未见 429；无需因本次数据改为串行，也无依据提高到更多并行。增加按模型／端点共享的限速、并发上限、退避和观测；参考有效 Retry-After，加指数退避与抖动，并限制重试次数及累计时长。配额／余额／长期限制进入等待恢复或需用户处理，不能套瞬时重试循环。
4. **错误分类优先看方舟 code，再看 HTTP。**已知输入／输出审核码和 `finish_reason=content_filter` 为内容拒绝，即使带部分正文也禁止学习写入或 JSON 修复。`InvalidParameter` 为配置错误；鉴权、权限、余额／订阅、周期配额分别保留原因。RPM／TPM／并发／暂时过载、服务端及传输失败可有界重试。`ContentSecurityDetectionError` 归审核服务故障，不当作内容违规。保留脱敏 code/type、HTTP、请求 ID、Retry-After 的有界诊断，避免原始消息回显凭据或用户正文；不再用 HTTP 400 一概代表配置错误。
5. **推理只计诊断，不进入记忆。**解析仅使用 `message.content`；另记 reasoning 字段是否出现、字符数及 usage 推理 token。常规日志不保存推理全文；usage 缺失标未知，completion 已含推理，不能重复相加。严格 JSON、宽松解析、模型修复、length 分开统计。总输出预算继续维持本次完整验证的 `max_tokens=16000`；若要采用语义更明确的 `max_completion_tokens`，先单独回归。两个字段不能同时传，不能假设现有 max_tokens 只约束可见回答。
6. **v5 有局部调整依据，但先固定参数并复测。**重点核对完整正文与全部证据对应、按说话人定义立场、多人反馈仅归纳为“我”的推断且保留参与者范围、about 仅含实际相关主体、别名须本人明确声明，以及排除瞬时状态和重复记忆。先用冻结 v5 完成参数重复对照，再小范围改提示词并用独立执行会话判分，避免参数与提示词同时变化。保持独立事实分开；不为得分改公开样本、放宽评分或强迫合并事实。复合 must 与原子记忆的边界如需修订，另列逐条理由，不能追改本报告得分。

后续仍需全部公开样本的独立双判、规划者隐藏验收和真人抽查。本轮未实现以上建议，不修改调度、网关、学习提示词或任何产品行为；不作 M1 最终通过结论。
