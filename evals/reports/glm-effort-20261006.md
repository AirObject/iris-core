# GLM 推理档位对照：low／high（2026-10-06）

**按 2026-10-06 的预定规则，推荐默认档位 `low`。** 三项质量指标的提升均未严格超过 3 个百分点，因此按预定规则选 low。 两轮算术平均的 high−low 差值为：记忆精确率 +1.99 个百分点、证据正确率 -1.99 个百分点、归属正确率 +2.31 个百分点。high 两轮合并的全部 406 次学习调用 P95 为 24.07 秒，最大 72.97 秒，超过 180 秒为 0。

这是全部 86 段公开 dev、每档两次学习、每份结果单判的参数选择证据，不作 M1 门槛结论。学习顺序为 low-1 → high-1 → low-2 → high-2，单作业、案例并行 4、每次调用总超时临时设为 600 秒。提示词仍为 v5，评分仍为 scoring_v3。

选择依据见 [DECISIONS.md](../../DECISIONS.md) 的「GLM 推理档位按对照结果选择」及 [对照规则](../README.md)。本轮在 [前次探测](glm-probe-20261006.md) 的脚本上只增加 `high`；没有修改产品代码、测试、迁移、提示词、评分说明或语料。

### 对后续 v5 迭代的建议（本次未修改提示词）

1. 优先强调分句级证据完整性：复合记忆中的每个事实都要有对应证据；把他人原话、转述、角色自身输出与推断分开，禁止把角色推断或承诺归给消息发送者。
2. 分别核对 speaker 与 about。about 应覆盖事实涉及的主体（包括明确提及的家人或被转述者），同时排除仅作为报告者出现的人、未经确认的群成员和无实际参与的“我”。
3. 别名必须有本人直接声明；现有显示名不应机械重复写成别名。平台字段、账号 ID 和案例编号只用于识别，不应推导虚构身份、same_as 或 roleplay。学习材料确实带有平台和账号标识，但本轮没有验证它们是否造成误读，只将这一点列为后续可检验的解释。
4. 在保存前再次区分长期价值与瞬时状态、寒暄、附和、一次性场景小事；不能为了保存某句而补上未出现的场景或理由。新增前与已有记忆比较，活动改期等更正应更新已有事实，避免并存重复条目。

这些方向来自公开 dev 错误，不能据此修改样本、放宽评分或写入逐案例答案。档位增加也没有稳定消除它们：两轮 high 的证据正确率均值反而较 low 低 1.99 个百分点。建议先按本次规则采用 low，并在后续独立任务中验证提示词调整；配置项、调用记录、指纹和报告中的档位记录沿用 DECISIONS.md 的适配要求。

学习命令模板如下，在本 worktree 中执行；`effort_artifacts` 必须指向一个新的仓库外目录，四个 out 不能复用。原检查点指纹未包含运行时的推理档位和超时覆盖，不能依赖它区分两档。循环按顺序等待每个作业结束，不能加后台并发。

```bash
export IRIS_TEST_MODELS=/Users/cassia/Local/Code/iris-core/test-models.toml
effort_artifacts=/private/tmp/iris-glm-effort-new-run
mkdir "$effort_artifacts"
cat evals/learning_v1.jsonl evals/learning_v2.jsonl evals/learning_v3.jsonl > "$effort_artifacts/public-all.jsonl"
for effort_run in low-1 high-1 low-2 high-2; do
  uv run python evals/glm_probe/probe.py \
    --root "$PWD" --corpus "$effort_artifacts/public-all.jsonl" \
    --out "$effort_artifacts/$effort_run" \
    --variant "${effort_run%-*}" --workers 4 || break
done
```

实际四轮 out 为 `/private/tmp/iris-glm-effort-20261006/{low-1,high-1,low-2,high-2}`，每轮自动导出的 `judging-materials-*` 分别配自己的 `judgments-<运行>`。离线计分形式为 `uv run iris eval learning-score --materials <该轮材料目录> --judgments <该轮判分目录> --judge-model 'GPT-6 (Codex executor)' --out <该轮独立报告目录>`；没有使用内置对话模型判分。

盲判按每案例一个全新子代理、fork_turns=none 实施。每名判分员仅获冻结 scoring.md 和该案例完整 input，文件使用中性随机目录名；不给档位、轮次、旧报告或其他结果，禁止访问其他文件、会话和网络。调度员不判分，只派发和机械核对格式。原始评分与可选错误分类注释在所有判分结束前仅保存于各父会话内存，之后再统一保存；注释不参与指标计算，不改写布尔判定。每轮只向 learning-score 传一次 --judgments。单判无法计算双判分歧，本次也没有真人抽查或第二服务商对照。

判分模型沿用执行会话设置，未显式覆盖。曾有一个子代理返回平台模型不支持错误，使用原设置重试后恢复；没有因此重跑学习或选取分数。该错误与 GLM 服务商的 429 分开记录。全部 344 份判分完成后，两个调度会话在后续导出时发现临时内存键不可见；依据会话中仍可见的完整原始最终 JSON 与原存储调用逐项机械恢复，并复核材料对应、数组长度、ID 与布尔类型。没有依据摘要补值、重新判分或按分数替换结果；恢复来源记入每条 audit。此事属于结果转存过程的问题，未触发新的学习或判分。

质量比较使用每个档位两轮指标的算术平均，不能把四轮记忆合并后改用加权均值替代决定中的规则。high 的耗时条件按两轮全部学习尝试合并计算。严格 JSON 是整个 message.content 可解码为 JSON 对象（拒绝尾随字符、围栏和非有限常量），与现有解析器允许的规整、尾随内容容忍不同。

## 有效性与限制

按 README 预先确定的规则，只有因限流或超时放弃批次才作废重跑。四轮最终批次全部成功，因此全部保留。两轮 low 的 429、重试等待和未知用量照实计入，不筛选较安静或较高分的案例。另一执行会话可能同时使用 GLM 或 embedding，未隔离共享账户负载；不能将观察到的全部差异归因于推理档位。

第一次 high 完成与第二次 low 开始之间有约 28 分钟空档，属于会话中断与恢复期间；完整起止时间在运行表中列明。四轮配置与源码保持固定，但服务端不同时段负载、生成随机性和单判噪声仍是限制。embedding 失败可能使学习材料检索降级，报告不会把它误记为学习超时，也不会隐藏该混杂因素。

学习输出上限和提示词 v5 均未调整；本轮只为默认档位提供 dev 证据。即使数值达到三项 M1 学习门槛，也不能替代独立双判、规划者隐藏验收、端到端评测和人工抽查。
