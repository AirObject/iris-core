# M1-4 召回性能与向量方案

最终源码：`a93e718`。Windows 11 10.0.26200、Python 3.13.13、SQLite 3.50.4、numpy 2.5.3，20 个逻辑 CPU、23.27 GiB 物理内存。Python 3.12.13 的 SQLite 同为 3.50.4，两种 FTS5 方案均通过功能测试。

每组新开一个进程，载入固定随机种子的 2048 维合成向量。5 次预热、60 次串行采样，包含全文检索、向量排序、元数据、去重和召回记录提交；HTTP 项另含 ASGI／JSON 开销。查询向量预先生成，不包含外部 embedding 网络。为了覆盖较多候选，性能测试将向量阈值设为 0；默认质量阈值仍是 0.65。测试时同机另有学习评测在等待模型，未进行并发服务吞吐测试。

| 记忆数 | dtype | prepare P95 ms | HTTP prepare P95 ms | 向量评分 P95 ms | 块存储 MiB | 加载 RSS 增量 MiB | 峰值工作集 MiB | 载入秒 |
| ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 5,000 | float32 | 57.4 | 53.3 | 6.6 | 40.1 | 45.0 | 167.8 | 0.17 |
| 5,000 | float16 | 67.0 | 62.4 | 16.5 | 20.1 | 26.2 | 147.8 | 0.16 |
| 50,000 | float32 | 196.3 | 191.2 | 60.4 | 392.8 | 410.5 | 553.7 | 0.87 |
| 50,000 | float16 | 283.9 | 277.2 | 143.5 | 196.8 | 215.1 | 355.7 | 0.91 |

HTTP 与直接调用交替采样，缓存和系统负载会使 HTTP P95 偶尔更低，不能解释成 HTTP 没有开销。默认 float32 在 5k 和 50k 均低于 500 ms；数据适用于上述本机、负载和查询。

50k × 2048 × 4 为 409,600,000 字节（390.625 MiB）。实际块存储 392.766 MiB 还含 1024 行块对齐、ID 与修订号；Python 映射、SQLite 和分词器另占内存，不能只用矩阵字节数代表进程总占用。

float16 的向量块存储约减半，但本机 numpy 在半精度载入、float32 累加时较慢。20 条相同合成查询的前八名交集比例，5k 为 99.375%，50k 为 100%；这不是有标注语义质量评测。因此默认选 float32，float16 保留为内存受限时可设置的方案。

真实端点的[降维探测](embedding-dimensions.json)：`dimensions=1024` 返回 1024 维，约 331 ms；512 返回 HTTP 400。尚未评测 1024 维的召回质量，已存向量和 dev 标定均为 2048 维，本 PR 不切换默认维度。

复现：`uv run python evals/benchmark_retrieval.py --out <报告目录>`。完整测量见 [JSON](retrieval-performance.json)。[首次测量](retrieval-performance-initial.json)也保留；最终测量包含启动通知清理和完整数组 token 预算修正，没有从多轮中挑选最好样本。
