# GO 第四步：C2 运行前冻结

C2 是 C 的“可能重复”补充。冻结后只在公开 `goal_dedup_v1.json` 上比较；不改语料、标签、C 的提示词或合并约束。本回合没有真实模型窗口，只做离线验证；产品默认仍是已合入 #47 的 C，是否采用 C2 等双轮有效探测。

## 配对条件（标注不进入规则）

在 C 原有模型候选之外，取被 M2 `same_claim_sequences` 的数字或否定序列检查排除的配对。两边必须同 kind、open、未合并；明确的非空涉及人集合须相等（任一边为空表示未知），非空期限须一致（任一边为空兼容；先按角色时区规范化，不能解析的旧期限只按原值比较）。排除自己和管理员已驳回的配对。

相近须满足以下任一项：

1. 复用 C 的 `normalize_claim` 与 `difflib.SequenceMatcher`，正文规整后均非空且相似度 ≥0.25；
2. 两个目标的非空 `entry_id` 相同，且各自的依据消息在该入口内有共同发言人。发言人按已确认的主体归并取规范 ID，排除 self／scene；只看真实 `goal_sources`，不将涉及的人代替来源发言人，不推测缺失来源。

按相似度降序、创建时间、ID 排序，每个新目标最多 8 个这类配对。只写既有 `goal_duplicates` 的 possible 标记，不送模型，不更改任何正文、期限、完成状态；不放宽自动或手动合并中的数字／否定检查。用户可查看或驳回；若要手动合并，仍须先明确编辑不兼容的内容。

## 与 C 的组合

C 的模型候选、最多 8 个的上限、来源投影、批量请求和提示词均保持不变。新增的配对独立标记，不挤占模型候选名额。只有新增配对时立即返回 possible_duplicate，不创建待复核任务，也不调用模型；学习事务也可直接写此确定性标记。

存在普通模型候选时照常判断；新增 possible 标记立即可见，降级时仍保留，整体判断状态为 pending。成功判断时将新增配对与模型判为 same／uncertain 的对象合并为可能重复列表；因此存在这种未解决歧义时，即使模型另有唯一 same，也只标可能重复。写入时复核目标修订、状态、来源及设置；管理员驳回不被补做重开。数字／否定冲突的配对绝不自动合并。

C2 是探测内部的方法名，共用 C 的模型用途、并发、健康管理和预算，不增加管理设置、迁移或调度循环。方法切换可被在途修订检查识别。关闭判断仍保持 A 的既有行为。

## 运行与采用规则

- C 基线直接使用 #47 两次有效 60 秒探测（原候选冻结 `9cacbd02d38f0200dd757316c7b8c8c101dde113`）；不重跑 C。两轮均误合并 0/14，应合并识别 14/28，不应合并中可能重复 6/39（separate 0/29、uncertain 6/10），每轮 38 次模型调用。
- C2 每例 60 秒测量预算、GLM high、串行完整两轮，固定时钟、隔离数据库、宿主／学习／管理员真实创建路径；原提示词 SHA-256 `2afac86c301dcc87998d3a27763e9eb347a9c5fedc41852370c70344c73e777c`。公开语料 SHA-256 `8cb2e046d3e80c6a53bee65d74938ae220453ba108fbb37508e6adcfec6a6c32`。
- 任何降级（包括 429、超时、暂停、无效输出）整轮作废，保留材料并重跑；假模型运行不能参与采用判断。
- 按较差一轮比较误合并率和应合并识别率。0/0 仍按未达到处理。只有 C2 的误合并不高于 C 且识别率严格更高时采用 C2；不应合并中标可能重复的比例同时报告，不新增阈值或放宽原计分。分列 separate／uncertain 及 uncertain 可选候选命中情况。
- C2 若采用，产品仍使用 C 的 5 秒预算，不增加网络调用或放宽合并；本步不调整提示词与模型参数。调用次数、P50／P95、token、逐例失败类型照常留存，完整材料在仓库外。
