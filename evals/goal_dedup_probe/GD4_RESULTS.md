## 决定

采用 D3（`goal_dedup_judge_v3.md`），默认额外相似度门槛保持 0。连续两轮均达到规划者预登记的公开 dev 条件：自动误合并 0、应合并识别 28/28、不应合并中标可能重复低于 25%。不改自动合并保护，不改待复核补判、注入过滤或兜底。隐藏集未寻找或读取，由规划者另行复核。

基线固定采用 #98 中 GLM high 的有效公开轮 `gd3-goal-threshold-20261012/glm-run-01`，不重挑基线。该轮与本轮均使用 60 秒测量预算和门槛 0。基线报告见 [GD3](../reports/goal-dedup-threshold-20261012.md)。

## 冻结与方法

- 基于 main `25e3688`。D2 在 `87b81cf2913a447398092e77952915dc09092140` 首次实测前提交；两次均因模型重排候选 ID 导致严格校验失败，整轮作废。分类质量不使用不完整轮。
- D3 在 `fe07601d68c8ba701769fe026b4ff55728b71e9f` 首次实测前单独冻结；分类标准与 D2 逐字相同，只加强按输入位置保留 ID 的协议指令。D3 之后无产品源码或提示词改动，两轮连续运行，中途不修改环境或代码。规则见 [GD4_METHODS.md](GD4_METHODS.md)。
- 仅使用冻结的公开 `goal_dedup_v1.json`：67 例（28 merge、29 separate、10 uncertain），49 host、18 internal；admin 创建用假模型测试覆盖。逐例隔离数据库和固定时钟，走实际创建／学习入队后复核路径。标签只用于事后确定性计分，不送入模型。
- 模型 `glm-5.3-flash`，high；每例串行、间隔 2 秒，未加载 chat2。同期其他会话运行学习评测，因此只报告实测请求耗时，不把它当独占机器性能比较；未做 CPU 压测。
- 两组既有候选一起送模型：普通候选最多 8 个、数字／否定序列冲突候选最多 8 个。后者以前直接打标，现在要求模型确认；不改变召回或人物、期限、状态、范围、驳回过滤。所有原始序列冲突继续阻止自动合并，即使模型判 different 或额外门槛滤掉提示也不能解除保护。
- 保持严格 `same / uncertain / different` JSON 协议，uncertain 现限定为有对象、时间及动作对应依据且仍有具体未决差异。数字／否定冲突上的 same 仍降为提示；管理员和其他歧义上的 same 也不自动合并。模型关闭时不再仅凭近似正文新增弱提示；显式 A 保留供历史复现。
