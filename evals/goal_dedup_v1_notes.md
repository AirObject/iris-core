# goal_dedup_v1 冻结说明

本集为 M3 目标去重方法选择前手写的公开 dev 集，共 64 例。人物、账号、作品、活动和对话均为虚构，不含真实用户资料，未寻找或读取隐藏验收集。每例独立，不把同名主体或入口跨案例关联。没有复制其他语料改名，没有用脚本、循环或模板批量生成案例；一次性命令只用于结构、分布和时间检查。

## 格式与材料边界

沿用任务给定的 format_version=1，没有增删字段含义或添加扩展字段。根 timezone 为 Asia/Shanghai，role_name 为 Iris。所有时间均为带 +08:00 的 ISO 8601 字符串；deadline=null 表示没有结构化截止时间，不表示没有正文中的事件时间。现有目标的相对措辞按 created_at 解读，来源中的相对措辞按该消息 at 解读，新目标按 now 解读。2026 年 11 月 6 日为周五、7 日为周六、8 日为周日。

- 每例 existing 有 1—3 个目标；GD001—GD024、GD049 共 25 例各有 3 个。不以 unrelated 填充候选：干扰项分别共享人物、对象、动作、时间、状态中的若干项。
- subjects 的 id 是身份边界，aliases 是已知的本人别名，不推测同名账号同一人。people 省略时须根据正文、别名及来源理解；省略不是空集合，也不能仅按入口联系人代填实际对象。
- internal 均有自然聊天来源摘录；普通目标有角色承诺，question 的摘录可以只是产生信息缺口的对方发言。host、admin 可无来源，不伪造角色曾经承诺过。sender 仅用本例主体 id 或 self。
- question 一律 deadline=null。incoming 没有 state／created_at，表示 now 时刻新提出、尚未结束的目标；不另行制造旧状态。
- expected 的 target 只在 merge 时出现，引用本例唯一的 existing.key。expected、reason 和本说明属于评分标注，不能作为去重模型输入。

## 标注规则

先比较 kind 与旧目标状态，再判断动作意图、动作方向、对象、涉及人的角色、具体事件／场景及截止时间。不是关键词越多越接近就越应合并，也不是入口相同就更可信。

1. **merge**：能确定为同一意图，涉及人和事件兼容，旧目标为 open，kind 相同，且两边非空 deadline 相同。表达长短、缩写、确定的别名和跨入口不妨碍合并。不同作品、文件、月份、练习场次或输出版本不是同一对象。
2. **separate**：存在明确冲突或明确的新意图，包括不同人、方向、动作、事件时间、场景、数量、否定或两个非空截止时间。completed／abandoned 不吸收新请求；question 与 normal 无论措辞及期限是否相同都不合并。仅允许去重，不能把相冲突的新请求当作编辑旧目标的授权。
3. **uncertain**：缺少决定身份、事件或版本的信息，多种解释均与材料相容。不能从“只有一条相近候选”、入口、创建先后、常识或人物名字猜测。必须保留两条，可以标可能重复；执行合并即是误合并。
4. **空截止时间**：一边为空、一边有值是兼容条件，但其他条件仍须成立。GD020 合并后须保留新宿主期限；GD021、GD028 须保留旧宿主期限；GD025 须保留已过期的旧期限。deadline=null 不撤销期限，也不意味着自动采用 now 或顺延。
5. **未结束与未执行有别**：open 只表示没有被宿主／管理员显式完成或放弃。GD025 的过期目标仍可合并，GD059 却不能仅凭 open 排除“实际发过、现在要补发”的解释。
6. **来源界定场景**：GD033—GD036 的短目标必须连同来源解读。反过来，GD037 的群聊筹备与直播操作属于同一场直播，不能仅因 entry_kind 不同而拆分。

## 每个 uncertain 的缺口

| 案例 | 缺少什么 | 为什么不能直接合并或判定明确不同 |
| --- | --- | --- |
| GD016 | 同名小周的主体 ID | 两个小周各有同一句任务；群聊注入既未给 people，也未提供可定位的话语。无法指定 g1 或 g2，但并非已知第三个人。 |
| GD026 | “下次试琴”的预约日期 | 可能指 15 日，也可能另有预约；一边空期限只消除了期限冲突，没有证明事件相同。 |
| GD038 | 背包所属场景 | 私聊可能延续游戏背包，也可能指现实背包；入口本身不足以裁决。 |
| GD044 | “那堂课”的课程名称 | 陶艺课与摄影课都是候选，没有可用先行词。 |
| GD057 | “那个文件”的文件名 | 提纲和授权书都合理，还可能是另一份文件；不按候选排序猜。 |
| GD058 | “他”的先行词 | 来源摘录仍只说他，两个联系人都没有被定位；不从姓名猜性别。 |
| GD059 | “再发”的执行背景 | 可以是催同一个未发送任务，也可以是要求重发；系统 open 状态没有提供实际发送证据。 |

| GD062 | 成片版本 | 花絮保留与删除都已建目标，来源里的“那版”未消歧；既不能猜，也不能合并两个版本。 |

## 容易误判的明确案例

- GD009／GD011：林同学在前者是小林的已知别名，在后者是另一个主体；不能跨案例沿用身份假设。
- GD014／GD015：people 集合相等不能替代动作的作者、收件人或教与被教的方向。
- GD019／GD022：不能以“同一任务的新期限”作为合并理由；注入接口不是修改接口，宿主明确约束必须保留。
- GD020／GD021：分别测补入新期限和保留旧期限。仅报告决策准确，不能证明合并后的期限没有丢失。
- GD033／GD037：前者相同短句分属游戏与实体店陈列，后者不同入口仍指同一场直播。
- GD045／GD046：不以“都在问问题”统一 kind；普通承诺与待询问事项分别保留。
- GD049：最早的同文目标已经 completed，正确对象是后来 open 的 g2。
- GD055：页码范围部分重叠不意味着任务相同，也不能私自把范围取并集。

## 使用与冻结

合并决定按标注自动计分，不需要语义判分模型。执行合并到 separate／uncertain 案例中的任何目标，或 merge 案例中的错误 target，均计误合并。误合并率分母是系统实际执行的合并次数；零次合并不能写成“0%且已通过”，应报告分母为 0，并同时报告应合并识别率。应合并识别率按 M3 计划统计合到正确目标或与正确目标标为可能重复的比例；未执行合并与实际合并须分列。额外建议或未执行提案不放进执行次数。

截止时间保留、来源迁移、较早目标保留及结束状态不复活是产品行为检查，不以决策标签替代。时间保留可直接由本例材料推出，不新增与原格式不一致的评分字段。公开 dev 结果不能代替规划者隐藏集，也不能据此宣称 M3 门槛通过。

冻结前已逐例对照目标正文、来源和理由，并用一次性 Python 命令检查 UTF-8 JSON、唯一案例与目标 key、target 引用、主体引用、内部来源非空、question 无期限、时间带时区及先后关系、合并目标状态与截止时间兼容、规模和分布。未运行真实模型，也未根据候选方法结果改标注。提交前依次运行 Python 3.13 和 3.12 的全套 pytest，结果留在 PR。

本 JSON 与本说明在同一提交中冻结，后续报告绑定提交号及 JSON 的 SHA-256。冻结后不再修改；如发现真实标注错误，另列逐条理由交规划者处理。完整运行材料与判分保存在仓库外。
