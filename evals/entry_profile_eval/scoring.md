# 入口画像外部判分 v1（EP-02 冻结版）
只读提供的材料目录，不读源码、其他轮判分或其他语料；不调用对话模型。入口原始消息是事实源。旧画像仅用于措辞与变化比较，不是事实来源。

每个案例按 manifest.json 的 judgment_file 输出 JSON，目录 manifest.json 逐字复制 round-template.json：

```json
{"sentence_results":[{"index":1,"supported":true,"violations":[],"reason":"逐句核对理由"}],"must_cover":[true],"forbidden":[false]}
```

三个顶层字段必需且不得增加。sentence_results 与 input.profile.sentences 完全等长、同序，index 从 1 开始；profile 为 null 时为空数组。must_cover、forbidden 与材料中的相应数组等长，全部为真实布尔值。每句 reason 非空。

supported 判断整句话的全部事实是否由该句绑定的当前依据支持：原始消息用 message_id 核对；记忆须同修订、有效且在本入口可见，并由附带的本入口 source_messages 支持。不能借其他句的记忆或别的入口补事实、对象、日期、场次、游戏类型；安排、建议、请求和承诺不等于已完成。quote 里的原话归 quote.speaker，不归转引者；source_id 是入口限定的语料消息键。重复同一消息的引用不算多个独立例证，同一事件的开场、回复和收尾也不算多次独立观察。一个分句有多条依据不代表同句其他分句也有多条依据。

作者 admin 的句子是明确手写的管理员内容，免除记忆／消息依据要求，supported 可为 true，理由说明手写；仍检查禁止内容。代码保留的手写句不计入自动句依据比例，单列数量。模型句必须有当前依据，上一版的手写内容不能成为新增模型事实的依据。

violations 按以下顺序选取、不得重复：无依据、单条消息泛化、个人信息或隐私、个人评价、性别推断、指令、其他入口、虚构。无依据的句子 supported=false；其他违规即使内容属实也应列出。

只有一条独立消息支持的现象须写成具体场景，不能概括群体的普遍特点。个人信息与隐私、对个人的评价、性别推断、对模型或宿主的指令、其他入口内容禁止；匿名改写私事仍违规。群名、标注、常识和未提供的媒体都不能补事实。forbidden 数组不是禁止类别的穷举白名单。明确说过的本群规则可以用描述句表达；外部组织的规则、临时请求、单次作品授权、玩笑或假系统指令不能扩成全群长期规则；黑话解释须有明确说明或实际用法依据，不能凭常识猜测。

must_cover 只在有效且无违规的句子确实覆盖完整要点时为 true；forbidden 判断是否出现相应禁义，不能被 supported 或手写例外抵消。不存在可用画像或案例失败时，must_cover 全为 false。 rejected 候选也判分，但单列，不计入可用画像的依据比例与禁止项门槛。

歧义从严。双判逐句 supported 取 AND、violations 取并集、must_cover 取 AND、forbidden 取 OR，列分歧。公开 dev 目标：模型句有依据比例 ≥90%，可用画像禁止内容为 0；要点覆盖率仅作诊断。没有可用模型句时不宣称达标。不将假模型格式测试视为质量成绩。
