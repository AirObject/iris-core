# EP2：入口画像改为话题与群内说法

执行者 EF；基线 `dcd500222b0d0855d02aab967c59629b3e388a28`。本回合仅假模型机制实现与回归，不读取模型密钥配置，不做真实质量迭代、独立双判或隐藏验收。PR 保持未合并。

## 新形式与存储

新模型输出 `items`，每条 `kind` 为 `topic / saying / rule`，共用 `label` 与 `quotes: [{message_id, text}]`；saying 可附 `meaning`，可用 `memory_refs: [M编号]` 指定含义依据。校验后存 `quotes` 的正文／转引字段及原作者，便于管理端溯源。每条原话必须存在；检查调用单独检查语义支持、范围和禁止项。仅含义不被支持时删除含义，原说法获支持才可保留，另记 `removed_meanings`。

宿主示例（说明形式，不是 dev 生成成绩）：

```text
常聊话题：试印纸张与渗墨（“换薄纸试印了”；“这次纸背又渗墨了”）。
群内说法：翻面——反看纸背面检查渗墨（“翻面就是看看纸背有没有渗墨”）。
```

包括手写内容在内，生成版本最多 6 条、500 字及 500 个现有估算 token，不设最低字数；label ≤40 字、含义 ≤80 字、每条 1—3 段引语、每段 ≤100 字。总长度包含分类文字、引号、标点与换行。500 token 是独立画像分区预算，相当于现有相关记忆 1500 token 上限的三分之一；不改变记忆预算或候选数。6 条足以放数个话题、说法与少量规则，避免把单条记忆重新铺成画像。真实模型尚未验证此预算的覆盖率，后续以未改标注的 dev 诊断判断。

复用 `sentences_json`，每条保留现有 `text / basis / author`，新增结构字段；模型条目、checks 与 material 标 `format_version=2`，不用数据库迁移。现有界面按 text 展示，按 basis 展示消息或记忆原始依据。宿主 `entry_profile` 仍只有 `{text, version, generated_at, possibly_stale}`，不渲染消息编号。v1 提示词、评分说明和历史正文保留；符合原有时机条件的下一次整理生成 v2。旧手写内容原样保留，包括不符合新分类的历史手写句；旧模型内容须重新提供当前依据。

## 确定性核对与发布

- 引用只查本次材料内、属于本入口的消息：直接抽样消息以及入选记忆的本入口 `source_messages`。后者也绑定记忆修订与来源指纹；记忆单独出现而无原话不够。相同消息在两个材料视图中出现时使用较长摘录，绑定该视图的来源。
- 规整仅为 `' '.join(text.split())`。规整后的引语必须是正文或被引用原话的连续子串；不删除标点、不折叠大小写、不允许拼句。摘录删除系统附加的截断提示，不能拿提示文本当原话。任一引用不合法，删整条。
- 常聊话题至少两条不同消息正文、两个角色本地日期。相同正文及截短副本不增加次数；转引原话没有可信的原始发生日期，可解释但不计入重复话题的两条正文。这个比“两个消息 ID”更保守的门槛，直接防止一次来回接话和次日转引凑次数。同一活动跨日仍由模型检查拒绝；跨日不能证明独立讨论。代价是同日独立多次讨论暂不进入常聊话题，作为覆盖率限制明示。
- 代码过滤长连续数字号段（五位起）、显式 QQ／UID／账号等标签、邮箱、平台提及形式及材料中已知的不透明账号 ID。长数字过滤是保守启发式，可能拒绝合法大数字；自然语言私事、个人评价、性别推断、指令和未绑定上下文仍依赖检查调用。
- 代码与模型累计删除超过原始模型条目的 50% 则拒绝整版，恰好一半可通过，内容为空也拒绝。手写条目与模型对手写条目的原文重复不计入分母，不能用手写内容稀释删除比例。仅删除含义不算整条删除，但变化度提高为 large。
- 总条数或长度超限不截断证据、不自动丢弃手写内容，而是拒绝并保留上一版。手写违规警告沿用人工确认；模型不得改写受保护内容。未改的 v2 渲染行在管理员编辑时整体保留，行内引语标点不会拆坏依据。
- 默认发布方式、每入口开关、每日一次、首版 50 消息、更新门槛、两次 120 秒预算、整理 max_calls、版本 CAS、来源失效及可能过时标记均沿用。调用在事务之外，写回复核当前版本、设置修订、消息散列、记忆修订和可见性。未改 consolidation 调用入口、学习、召回、宿主 API 或前端。

## 运行器与评分

新评分说明 `scoring_v2.md`；v1 `scoring.md` 未改，旧材料仍可离线读分。导出协议保持 format_version=1，scoring_version 升为 entry_profile_scoring_v2。为兼容工具，JSON 中 `sentence_results` 与 `profile.sentences` 名字不变，其元素现在是条目。新主指标 `grounded_item_ratio`，保留旧指标名作为别名；禁止项数和禁止类别并列；双判继续取不利结果。引用核对通过率是所有生成引语中合法引用数／总数，含被删条目：检查编号、长度、连续原话；没有引用时 null。它不是语义有依据率。

无外部判分时有依据条目率、forbidden 和覆盖率为 null，不会以内部假检查宣称 ≥90% 或禁止项 0。被拒候选独立报告；要点覆盖率仅诊断。本回合的格式与机制测试不作为 dev 成绩。

## 给 UX 的后续需求

1. 按 `kind` 显示“常聊话题／群内说法／明确群规”，将 `label`、可选 `meaning` 与 `quotes` 分开；引用注明原话归属为正文或转引，以及原作者，管理员可看消息编号。宿主仍只收渲染 text。

3. 现有管理接口 `EntryProfileEdit` 和 UI 仍要求 150—500 字；短 v2 正文现在可以显示、确认和回滚，但短编辑受旧校验限制。请规划者为 UX 明确授权 `admin.py`／前端及对应测试，以取消编辑最低字数并约束新总预算；本 PR 未跨出文件范围。结构化编辑仍需保护未改条目依据与手写标志，保留 expected_version 冲突草稿。
