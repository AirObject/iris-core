## 四类失败的处理、局限与测试

1. **把跟进当作新讨论。** 在回复／引用链及同作者同对象跟进合组的基础上，增加通用的结果报告、已采纳建议和明确回指特征。同一作者对先前请求、最长名词对象一致，且报告处理结果或跟进时合组；明确回指以前讨论并报告尝试／采纳结果的消息不作为新讨论见证，不虚构原消息 ID。不按具体话题维护词表。无回指的另起问题可独立；假设性的“想按建议比较”不当作已完成结果。局限：省略、隐喻依赖模型；一条消息混合结果反馈与新问题时，可能保守地排除整条消息，造成覆盖损失。测试覆盖同求助者回报、不同作者回指、真正新问题、后来第三次独立讨论和假设语气。
2. **领域相近但主题不同。** 先按完整来源池计算讨论图，再把所选依据的 `discussion_groups` 送检。检查逐组返回 `focus`、`same_topic`、`independent`、`reason`，核对实际对象、问题性质，以及是否重新发起讨论。代码要求组 ID 完整且唯一、布尔值真实、至少两组跨本地日期且同时通过两项判断；保留的 safe_sources 仍须支持这两组，不能保留明确判为不同主题的组。一次 JSON 修正不能把已经输出的 false 改为 true。局限：判断对象与性质是否相同仍依赖模型，结构校验不构成语义证明。测试覆盖“同领域评论／制作求助”混绑、缺组／重复／未知组／字符串布尔、缺第二组来源、旧排队检查和重启。
3. **说法含义借旁证。** 新增 `meaning_support`，按顺序覆盖整个 meaning；只忽略格式标点和空白，不消除实词、否定或数字。每个要点的引用必须同时是本条输入 sources 和保留 safe_sources 的同 message_id／field 连续片段，且包含已声明的解释来源。另一条未绑定消息、同一消息的 context 中未摘录句子，以及检查已去掉的解释不能补证。提示词逐项判断解释是否支持要点。局限：代码证明引用归属与覆盖结构，不证明释义语义蕴含；模型仍可能把不成立的解释判为成立。测试覆盖未绑定消息、仅上下文出现、缺要点、解释被移除、正向完整解释和重启不发布。
4. **摘录泄漏一次性内容。** 核实目前记忆路径的宿主投影只渲染类别标签与 body，并没有自动追加 sources；本轮保持不附摘录的方式，没有另建摘录选择器。v6 禁止在正文内夹带原话例句，检查应把 safe_sources 缩为稳定主题的最小充分片段，且仍检查引文隐私。三项契约测试证明数字天气、一次性阵容变化、他人私事出现在核对上下文时不会自动进入宿主 text；原始证据不丢，读取不加 version。局限：正文内由模型嵌入的一次性叙述仍须靠正文规则及准入检查拦截，不能声称所有原始来源都已语义净化。

旧持久化准入任务没有 `groups_and_meaning_v1` 协议时取消旧结果并重新排队，防止升级／重启沿用不含逐组核对的接受结果。写回前再次校验检查结构，再走原有修订、来源快照和短事务 CAS。没有批量重写已发布条目。
