# consolidation_v2 公开说明

本集是 Iris 整理自主处理 `resolution=auto_v1` 的公开开发集，用于迭代合并、矛盾处理、依赖复核及前置保护。规则采用《SPEC-C-consolidation-auto-v1》第 2—6、10 节。场景与消息为手写构造；本次只做数据修订和静态核对，未调用模型、未运行评测，不以本集规模或静态核对结果宣称实现通过。

223 个案例内无序记忆对全部标在 `merges` 或 `no_merge`，无交叉或遗漏。另有 10 对 `mutual_merges.expected=keep_both`：7 对事实冲突，3 对真互补但受保护；不把它们计入 15 对可自动合并。假细节场景共 3 对，其中 CV005.c/d 因 d 置顶而跳过，另两对走普通重复合并。事件共 8 个：delete 6、forget 2。

两部分分别覆盖本人明确更正、本人否认转述、历史与当前并存、笔误或口误、无法裁决的版本、“更正”原话反而更早、全为角色发言的依据、对象或条件不同的相近命题。依赖包括唯一依据失效、仍有独立见闻、两条路径同到一条原始消息、剩余只到角色自述。合并包括真互补、同义或量词等价、数字／否定／时间冲突，以及容易补出人数、口令、赛果、功能等未给事实的场景。人工编辑、置顶和可见范围不同三类保护，两部分也分别具备。

## 材料表示

外层为 `format_version=1`、`name=consolidation_v2`、`timezone=Asia/Shanghai`、`role_name=Iris` 和 `cases`。案例 ID 连续为 CV001—CV024；记忆 key、来源 key、主体 ID、入口 ID 均在本例内解释，不跨案例连证据。相同来源 key 的重复引用必须是同一条原始消息，七个字段完全相同，不能导入成多条独立消息。

每例都显式声明完整 `entries`。范围由来源 `entry_id` 对应的入口计算，不在记忆上另存范围字段。`shared` 为本例入口全集，`entry_only` 仅自身入口，`entries` 为自身加 `visible_in` 后与入口全集相交；多来源及派生父边按交集继承。private、group、live 只是入口种类，不自动决定可见范围。本集实际使用 shared 和 entry_only。

来源 `kind` 使用 message、self_output，以及 CV019.s4 的 action_result。s4 表示场景内的操作结果，`sender=self` 标识操作发起者；它不是 Iris 对结果的自述。装载材料须将本例 source key 映射为唯一原始消息身份并保留这个种类，不能降成 self_output，也不能伪装成旁人消息。本次依据 C 第 4 节允许行动结果的规则作静态标注，未验证现有加载器的运行兼容性。

`memories` 是事件前快照；先按顺序应用 `events`，再判断整理前的工作对。delete 撤销依据而不删共享原消息，forget 使依据失效而不是证明反面。已删除记忆的原 key 仍保留在判分映射和对标注里，不能复活。`created_at` 是最初创建时间，不用来代替来源 `at` 排序；CV001.a 有后续追加确认，CV006.b、CV017.b 有延迟入库。时间均为 +08:00；相对日期按消息 at 解读，只给日期而未给时刻时不补造 event_time。

## 标签口径

`auto_contradictions` 按 C2 标注：

- supersedes：同说话人、双方非转述，由本人晚于旧条全部来源的明确更正支持，且不全是 self_output；speaker=self 时还须有对应外部消息或行动结果。旧条保留正文，加指向新条的 superseded，belief 取原值与 49 的较小者，并进入遗忘；新条不动。
- reported_vs_self：本人消息与关于本人的转述相冲突，只将转述降一档并加 disputed，不改成遗忘。
- coexist：历史、时段、对象或条件不同，可以并存，只记录。
- undecided：证据不足或核验条件不成立，两条加 disputed，正文、相信程度及生命周期不变。此时 old/new 仅定位输入，不代表已裁定事实新旧。

`auto_dependencies` 按 C3 标注。只计仍有效且相关的依据记忆；沿派生链追溯原始消息，排除只到 self_output 的支持，再按原始消息身份去重。0 条标 forget：保留正文，加 insufficient_support，belief 取原值与 49 的较小者，进入遗忘；至少 1 条标 keep：本项不改正文、相信程度或生命周期，M2 对同一次失效的一次扣减之外不再重复扣减。进入遗忘统一为 `lifecycle=forgotten`、`retention=min(retention,F-1)`，F 沿用系统遗忘阈值。两条同源路径的场景证明覆盖了这种材料形态；由于 C3 只分 0 与至少 1，本集的最终标签不能单独证明去重代码已经正确实现。

`merges`、`no_merge` 及 `mutual_merges` 的决定针对事件应用后、整理前的输入对。keep_both 只表示不执行合并，不要求两条最终都 active；如 CV004、CV006、CV013 的旧条仍须按 supersedes 遗忘。生命周期和分数由矛盾、依赖及保护标注另行核对。

可合并真互补项的 `must_keep` 仅列两侧各自独有且有意义的正文片段；共有主体、事件、时间、数字、否定和限定仍必须按 C1 保留。`must_not_add` 是具体诱导禁添项，不是允许添加其余无来源事实。仅对实际执行合并的结果检查合并正文；keep_both 项核对两条各自的正文与归属，不要求一条新正文同时容纳相反说法，尤其不能用子串包含代替否定检查。

保护优先于自动判断。`protected` 列人工编辑或置顶对象，也列本例因范围不同而必须跳过的工作对涉及的对象：CV012.x/y、CV024.e/f。范围保护是该对的属性，不表示这些 key 在所有可能工作中都全局冻结，也不改变其 last_edit 或 pinned；相关工作和原因见各例 reason。保护统计同时给案例、工作对和 key，三种口径均至少为 4。自动整理不得绕过保护去合并、降分或改变生命周期。
