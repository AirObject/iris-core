# visibility_v1 冻结说明

本集为 M4 可见范围实现前手写的公开 dev 集：32 例、99 个查询、69 条记忆、11 个目标、81 条按案例和来源 key 去重的消息。查询中有 74 项 forbidden、94 项 expected，另有 18 项 expected_goals；这些是“查询—对象”标注数，不是独立事实数。六例各标一对因范围不同而不能合并的记忆，三个案例包含四次管理员范围变更。所有人物、作品、地点、计划和聊天均为虚构，没有真实用户隐私数据。

基于 origin/main `b746dd4c49e58d969be4fa2a7467b49e32fa0990`，已读 AGENTS.md、DECISIONS.md 2026-10-10「M4 计划」、evals/README.md「M4 计划」及设计 11.4、9.4、16.1、23.4。格式参考公开 recall_v2 和 consolidation_v1，内容没有从它们复制改名；每例由执行者逐条手写，未用脚本、模板或循环生成。程序只用于结构、引用、时间和计数核查。未寻找或读取隐藏集，未运行真实模型或查看方法对照结果。

## 标注规则

1. **按依据所在入口判断**。shared 是默认值，所有请求入口都可见；entry_only 只允许来源自己的入口；entries 只允许 visible_in 中列明的入口。private／group 是场景类型，不是权限；主体相同、别名相同、同一宿主或入口名前缀相似，都不增加权限。
2. **全部依据取严**。记忆的直接来源都参与判断，派生项还递归继承 derived_from 的范围；角色复述、公开来源较新、相信程度较高，都不能放宽某个旧依据的限制。以允许入口集合表示，就是同时满足所有依据的限制。本集多依据的范围组合均有包含关系，较小集合即最严格范围；未擅自制定不相交列表的产品处理流程。
3. **目标同样过滤**。本集目标均为有消息依据的 internal、open 目标，按全部来源取严；entry_id 只是目标登记的入口，不替代来源检查。VS018 特意将目标登记在群聊，却保留私聊依据。普通目标和没有截止时间的询问都受限制。本集不规定无来源宿主／管理员目标的默认范围。
4. **按查询时的设置**。静态案例的 entries 给出本次所有查询适用的设置；动态案例从 entries 的初始设置开始，按查询时间应用之前的 visibility_changes。改变的是入口配置，对已存在的记忆、来源链和目标立即生效，既不是只影响新对象，也不是把历史授权名单累加起来。
5. **不同范围不去重、不合并**。比较实际允许入口集合，不能只比较枚举名称：两个不同入口的 entry_only 不相等。no_merge 是记忆对；VS005、VS006、VS009、VS015 在私聊中两条都可见，其 expected 同时列两条，是对“不同范围不做召回去重”的检查。与共享事实同文的私聊对象仍不可在群里返回。
6. **任何分区都守边界**。forbidden 对相关记忆、人物要点、目标分区均生效；点名、参与者出现、重要度很高、问句已经包含某个细节，都不构成授权。公开独立对象可以表达相同事实，必须按返回对象及其真实来源判断，不能使用全文禁词表把公开对照一起屏蔽。
7. **共享对照不收紧**。VS027—VS029 全部共享，含省略 visibility 的默认值；私聊来源、self 输出和派生链本身都不是禁止跨入口的理由。这里只提供小组对照，不替代 M4 要求的全部公开学习请求和召回返回逐条回归。

## 格式补充

保留任务给定的 format_version=1、字段含义及 UTF-8 JSON。key 均为案例内标识，跨案例不共用对象。self 为 Iris；scene 是保留说话人标识，本集没有场景消息。以下新增字段只用于明确材料，不约定产品接口字段名：

| 字段 | 类型与含义 | 原因 |
| --- | --- | --- |
| entries[].visible_in | 非空、不重复的入口 ID 字符串数组，仅 visibility=entries 时有 | 指定允许入口的完整列表；本集的列表都显式含来源入口，不暗加“所有私聊”或其他入口。 |
| visibility_changes | 可选数组；项含 at、actor、entry_id、visibility，entries 模式另含 visible_in | 描述管理员改变入口配置。actor 固定 admin；每项完整替换该入口的可见范围。改为 shared／entry_only 后旧列表作废。 |
| queries[].at | 可选的 +08:00 时间字符串 | 动态案例每问必填，按此时刻取配置；静态省略等于 case.now。 |
| queries[].expected_goals | 可选目标 key 字符串数组 | 可见目标的正对照。与 expected 的记忆键分开，避免改变原字段意义；缺省表示没有额外目标正例断言。 |
| goals[].state、created_at | 本集 state 固定 open；created_at 为 +08:00 时间 | 排除完成／放弃和创建时间造成的过滤干扰，便于核查承诺来源早于目标创建。 |

所有原有记忆字段照常解释。来源 key 唯一标识本例原始消息，同 key 必须有完全一致的入口、作者、时间和正文。VS009 的两条记忆共用公开 s2，不能导入成两条独立消息；直接来源多于一条不等于可以任选一条定范围。全部来源早于所属对象创建，派生依据先于派生对象创建；所有记忆和目标在本例最早查询之前已存在。日期为 2026 年 12 月；10 日是周四、11 日是周五。正文没有凭名字推断性别。

memories 是给定的已形成快照，全部有效、未置顶、最近正文修订视为 learning；缺省的保留强度按产品初始值装载，不在本集另设生命周期变化。查询不提交使用反馈、不学习本次 recent_messages、不把它们自动写成新记忆或目标。主体别名按给定快照装载，VS026 同时有本人原话支持“云团”。

queries 的 text=null 表示回复准备使用该问 recent_messages 组成查询，不改成空字符串。recent_messages 每项属于当前 query.entry_id；空数组表示本次没有近期消息。运行适配须让近期消息窗口恰为该数组（空数组时条数为零），不能把用于装载来源的旧消息自动塞入窗口，否则 R11 会把本应检验的记忆当作冗余滤掉。每问独立设置窗口和 participants，不沿用上一问的宿主已知记忆列表；源消息仍保留作证据。

search 的 include_goals 在本集每问显式填写。false 时整个目标分区必须为空，即使某个目标本来可见；这种请求开关检查与隐私 forbidden 分开统计，不能把关闭目标分区计作成功处理了目标可见性。prepare 按产品行为附带可见的未结束目标。所有目标均为未过期或无截止时间，数量不超过默认分区预算。

## 运行与计分边界

每例独立装载入口、主体、来源、记忆和目标，维护原 key 与运行时对象 ID 的映射。运行凭据须有访问全部被查询入口的权限，401／403等请求失败不能当作过滤成功。不能为了适配现有去重逻辑，在载入时预先丢掉不同范围的对象；如果载入仍走去重，跨范围的吞并本身就是失败，而不是更小的测试输入。没有 visibility 的入口确实走默认 shared，不通过名称猜配置。

每个静态案例的三个查询复用同一已形成快照，设置各自近期窗口；动态案例按 at 顺序在同一实例执行查询和管理员变更，保留缓存，以便检验查询后改严时的缓存失效。未标记任何 memory 已在宿主上下文，未做使用反馈。case.now 是静态查询时刻或动态时间线结束时刻；不能先把动态案例全部变更应用到最终设置，再回头判最早一问。

no_merge 的整理检查从该案例独立快照运行，适用 case.now 的配置；不要用整理后的记忆替换原查询段输入。记录每次实际合并和占位链，展开到原 key 后若包含任一 no_merge 对，即违背本集的范围隔离断言，即使正文没变或最终范围变严也失败。这不是重定义 M3 的通用误合并指标。查询段同时检查不同范围的候选是否被召回去重错误抑制。

**零泄漏**：逐问扫描相关记忆、人物要点、目标分区及其附带内容，任何 forbidden 对象被返回，或从它生成未经授权的摘要／改写，均记泄漏。记录 case、query、对象 key、实际分区及来源映射；泄漏查询数与泄漏对象次数分别报告，不用正例召回抵消。相同正文的公开 m2／g2 正常返回不是泄漏，但不能在它的来源、占位或归属中夹入受限对象；没有可靠映射时应报材料不完整，不能凭相同文字猜测通过。跨范围整理合并也算泄漏，单列六对的结果。

expected 是本问应能取到的可见记忆，expected_goals 是可见目标的正例；它们不是所有可见对象的穷举，也不是新增可见性规则。实际漏返须逐项记录，区分权限过滤、召回相关性、预算及去重原因；不得把空返回当成过滤正确，或把普通召回缺失伪报为隐私泄漏。人物要点正例控制在每问三条以内，其他正例也在默认预算以内。本集不自行新增召回达标百分比；共享默认行为仍须按 M4 计划与 M3 定稿逐条比较。

来源消息只供装载和检查证据，不自动成为宿主输出。即使记忆本身共享，其他入口原始消息仍不得加入近期消息或回复材料；出处摘要按设计 9.4 保留入口、时间、说话人，不能借展开来源带出跨入口原文。本集不执行真实宿主令牌越权请求，R03 的鉴权契约由相应实现测试覆盖。

报告需列出全部 99 问的执行情况、74 项禁止标注、94 项记忆正例、18 项目标正例、六对整理结果及四次设置变更。失败、未执行、丢失材料不能记成零泄漏；公开集与规划者隐藏集分别报告，不能仅凭本集宣布 M4 隐私门槛通过。

## 容易被质疑的边界

- **同文也禁止私聊对象（VS005、VS009、VS019）**：这是对象及依据的访问限制，公开对象可独立表达相同事实。按字符串封禁会误伤正例，按“事实已经公开”直接放行私聊对象又会丢掉依据边界。
- **角色以前在群里说过推测（VS010、VS011）**：材料是已有快照，不要求在当前配置下重新产生那些旧输出。本轮只判断给定对象现在能否返回；自述重复不是独立证据，不能清掉 derived_from 的限制。那些旧来源不在本次近期窗口中。
- **“本入口”不是“同一个人”（VS007、VS023）**：同人跨客户端并不扩大列表，入口类型和名称也不代替完整 ID；这两例分别检验 entry_only 的具体入口和 entries 的完整名单。
- **更宽依据的出处也可能无权看派生（VS022）**：A 只提供 {A,B,C} 那份依据；另一份只允许 {B,C}，所以包含两者的结论不能回 A。所用范围有包含关系，不依赖未定义的冲突列表处理。
- **放宽也要作用于历史链（VS031）**：本任务明确按查询时设置，因此不能用“曾经私密”永久阻断；与 VS030 的立即改严互为对照。改严前已经返回过的结果不要求追溯撤回，但改严后的新请求必须遵守新设置。
