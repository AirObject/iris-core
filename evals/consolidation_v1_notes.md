# consolidation_v1 冻结说明

本集为 M3 模型整理方法选择前手写的公开 dev 集，共 40 例、89 条记忆。包括 12 对应合并、47 对不应合并、10 项矛盾和 8 项依赖复核。所有人物、作品、地址和聊天均为虚构，没有真实用户资料，未寻找或读取隐藏集。逐例手写，没有从其他语料复制改名，没有脚本、模板或循环生成案例；一次性程序只做解析、引用、时序、计数和格式检查。

与本集一起冻结的 [consolidation_scoring_v1.md](../src/iris/prompts/consolidation_scoring_v1.md) 负责合并正文、矛盾结论、依赖处理和人工保护的语义判分。应否合并按 JSON 标注自动计分。本集不包含产品代码、评测运行器或方法选择结果。

## 格式与三处扩展

保留任务给定的 format_version=1 以及所有原有字段含义。每例独立入库，固定 now，不跨案例复用主体或记忆。三处添加都是为了证据可核对：

| 添加字段 | 类型／使用位置 | 理由 |
| --- | --- | --- |
| sources[].key | 字符串；所有记忆来源及 edit 新来源 | 标识本案例内的原始消息。同 key 必须对应完全相同的 entry_id、sender、kind、at、text 等内容；反复引用只导入一次消息。不能把每次引用复制成独立证据。运行器可映射为自己的消息 ID。 |
| events[].sources | 来源对象数组；仅 edit 事件 | 给出支持新 content 的原话，追加到该记忆来源并按 key 去重。否则依赖复核只看到被改的断言，无法从来源判断新结论。 |
| events[].last_edit | learning／admin 字符串；仅 edit 事件 | 指明新正文修订是否受人工保护。CS038 为 learning，CS040 为 admin；不能沿用编辑之前的标记。 |

没有删除字段，没有改变 memories[].sources、last_edit、derived_from 或 events.op 的意义。评分输出另加 protection_results 用于单列已有的人工保护要求，不是新增产品规则。评分材料字段 actual_merges／before／after 等是离线导出约定，不规定产品接口名称。

case.memories 为事件前快照。按 events 顺序应用事件后再执行模型整理：delete 撤销目标记忆但不删除共享来源或复活原 key；forget 使其进入遗忘；edit 替换正文、更新 last_edit 并追加新来源。其余字段按既有操作语义处理，不能因为本格式未列修订号就省略产品中的修订检查。模型看到当前记忆及可用来源，不看到旧正文修订历史；判分材料另保留事件前后快照，以核对因果和重复扣减。

type 使用现有记忆类型；虚构背景和待验证推断使用事实类型，分别由 stance=设定／推断及正文保留其边界，不另造背景／推断类型。所有时间均带 +08:00。来源消息的相对时间按 at 解读；未给精确事件时刻时 event_time=null，不能补出午夜时间。明确未来安排的 event_time 可以晚于 now，不意味着已经发生。每条记忆的来源有 1—4 条；追加 edit 新来源后仍不超过 4 条。全体来源按案例和 key 去重后共 91 条（含两个 edit 新来源）。

## 标注规则

- **只合并同一事实**：人物、speaker、stance、事件、数字和否定均兼容且能确定同指。简略复述可以合并到包含细节的同一事实，但结果须保留全部关键限定。别名、缩写和数值的文字写法变化不是新事实。同人、同主题、同消息中的不同事实不能拼成一个人物简介。
- **来源与归属分开核对**：同一原始消息被重复提炼可以合并；来源相同不证明两个命题相同。本人亲历与他人转述、角色推断与原始事实保持独立。多个消息 key 不自动代表独立证据，尤其是本人重申、角色复述和共同源头的派生链。
- **不确定不合并**：本格式没有 uncertain 合并类别；无法确定同一实物的 CS024 放入 no_merge，遵守 M3 的保守默认。没有因为来源不足而猜测同一事件。
- **矛盾回到原话**：以明确更正、证据时间和本人对自身情况的澄清判断，不按记忆条数投票或单按 created_at 取最新。10 项矛盾含 2 项无法裁决的争议（CS028、CS032），另含时间变化与历史承诺的表面冲突；后两者须解释范围，不是抹掉旧事实。
- **相信程度的命题要明确**：“说过X”与“X当前成立”不同。传闻被否认不证明转述者没说过；过去偏好改变不证明过去不真实。失去支持不等于反面已经成立，也不要求精确降到某个数字。
- **人工正文保护**：CS033.a、CS034.a、CS040.d 在初始快照已为 admin；CS040.a 经 edit 后也受保护。整理不可改它们的正文和相信程度，只能在允许范围内另加标注或建议。CS009.a 仅 pinned=true，仍为 learning，不能把置顶误当人工编辑。
- **依赖看真正的支持路径**：降低是唯一源头失效后保留强度降低或确认已有的一次扣减；保持是仍有独立支持；复核是按被纠正依据的新内容判断其对旧推断的影响。依赖复核不改派生正文，不自动删除。共同源头不能双扣，同名或相似记忆不承接依赖影响。

## 运行和判分边界

每例先入库记忆与来源、建立 derived_from，再应用事件，保留前后基线，最后调用模型整理。加载器应维护 key 映射而非假定固定数据库 ID；来源 key 相同时复用原始消息。对已删除依据仍需保留失效依赖标识及判分所需映射，不把旧正文重新喂成有效记忆。正文、类型、相信程度与派生关系均按给定快照导入，不预先替模型修正 CS031 等故意带错的旧摘要。

M2 确定性维护可能在事件发生时已扣一次保留强度。评分比较 case、before、after 三个时点；降低不要求再扣一次，保持也不强求精确恢复旧分数。应展示实际扣减发生处及原因，不能用输出一句“已降低”替代真实变化。依赖的“复核”必须指出新证据怎样改变支持范围，不仅重写一个待复核标签。删除对象不等于删除共享来源；模型处理不自动删除派生对象。

自动合并计分须看完整原 key 集合，复合合并含任意 no_merge 对即错；不能只检查动作中最相似的那一对。合并后正文再由评分说明判，不以文字质量冲抵误合并。合并识别率和实际执行量分别报告，零合并按 M3 计划记为0/0、按未达到处理，不当作有意义的0%误合并率。来源保留、占位与人工保护另做确定性核对，不能由语言模型覆盖。

本说明不修改 M3 门槛：公开 dev 和规划者隐藏集分别计算，矛盾／依赖一致率为辅助指标；分母及分歧须明确报告，不将40例视作隐藏验收。两轮判分互不可见，正向布尔值逐项取AND；门槛判分者不参与该轮实现。失败、降级或预算放弃按 M3 计划处理，不删去失败项后声称通过。
