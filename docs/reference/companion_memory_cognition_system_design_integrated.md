# 独立陪伴角色记忆与认知系统设计

## 文档定位

本文定义可独立部署、服务于单一陪伴角色的自治记忆与认知系统，包括产品行为、信息对象、三段式学习、记忆生命周期、外部调用、当前状态、并行目标、专注梦境、管理面板、逻辑接口与验收条件。它不是已实现系统的说明，也不是最终代码级协议。

已明确规则直接写为要求；暂定量表和未选定数值明确标识；为落地提出的建议注明其性质。系统仅采用明确选择的三段式输入组织思想，不沿用旧项目的存储层次、评分、自治限制或技术栈，不预设语言、数据库、模型供应商和聊天框架。逻辑模块不等于微服务或独立仓库。

## 1. 系统定位与范围

### 1.1 一个角色的统一认知系统

一个运行实例服务于一个陪伴角色。这个角色是唯一的认知主体，也就是系统中的“我”。聊天、直播、游戏等外部宿主承载角色的感知、表达和行动，不分别拥有独立的人格与认知空间。

系统面向通用陪伴场景，接收多人、多来源、多模态输入，通过缓存、理解、学习、总结和整理形成认知。记忆不是单纯的事件记录，还包括对事实、自身、他人、事物、关系的理解、推断和观点。

认知覆盖过去、现在和未来：过去包含经历与长期认知；现在包含外部管理的当前活动、状态和情绪；未来包含多个可以并行的目标、待办、建议和高层意图。自我认知贯穿其中，并指导稳定 persona 的生成。

### 1.2 自治与外部执行

系统内部具有自治 agent，可以决定关注什么、何时学习、形成哪些认知、如何分类和评分、如何纠正观点、怎样处理关联影响，以及何时产生目标或询问建议。

系统对自己的记忆与认知具有完整管理权限。这个权限不包括读取开发者审计日志、擅自修改外部配置的 persona 监督目标，或替外部改写其管理的当前状态。

系统向外部提供高维度意图和认知信息。具体说哪句话、如何调用工具、如何操作游戏、如何组织最终上下文，由外部宿主的 agent 流或策略决定。本系统不监控目标的实际执行过程。

### 1.3 多入口支持与暂缓范围

系统支持多个平台和多个细化入口。一个具体群聊、私聊、直播间或其他交互场所构成一个入口；平台不是入口本身。

暂缓的只有跨入口并发协调与实时一致性。不暂缓入口接入、来源记录、各群聊／直播间独立的三段式队列和梦境暂存序列、跨平台主体联系、统一 persona、跨入口正式记忆查询，以及其他入口尚有未处理输入的提示。

系统返回的是某个观察时刻的已知信息，不保证所有入口在外部真正发言时已经完全同步。没有收到某平台的数据，不等于该平台没有发生新事件。

### 1.4 不纳入的职责

本系统不承担完整回复生成、具体行为执行、游戏控制、业务工作流编排或执行效果监控；不把有限传输重试扩展为业务级无限重放；不保证零输入丢失；不要求训练基础模型参数；不把对象级删除解释为内容级彻底抹除。

## 2. 核心术语与职责

| 概念 | 含义 |
| --- | --- |
| 陪伴角色 | 唯一的认知主体，拥有统一自我。 |
| 外部宿主 | 聊天、直播、游戏等承载程序及其 agent 流或策略。 |
| 薄兼容层 | 封装外部输入、标识入口、调用接口、传回输出及反馈的接入层。 |
| 平台主体 | 某平台上的账号、观众、主播或其他实体身份，独立存放。 |
| 入口 | 具体交互场景，例如某群聊或某直播间。 |
| 缓存 | 输入队列中的近期材料，不是正式记忆。 |
| 学习轮次／批次 | 冻结本入口三段快照、只以中段为目标，并具有明确终态与结果归属的一次学习。 |
| 历史辅助段 S3 | 前一轮目标中段的最新尾部，仅供下一轮理解；也称下一轮后缓冲。 |
| 目标总结段 S2 | 本轮唯一要总结的连续输入范围。 |
| 最新辅助段 S1 | 本批次已接收的较新上下文；本轮不总结，后续可流入目标段。 |
| 梦境暂存序列 | 每入口独立、专注梦境时只接收不学习、无业务条数上限的原始输入队列。 |
| 正式记忆 | 经系统加工保存的事件、事实认知、推断、观点等。 |
| 原始来源 | 形成记忆所使用的目标输入及限定在该批次的三段上下文，保留完整信息。 |
| 派生来源 | 用于形成其他认知的来源记忆 ID 及其关系。 |
| 相信程度 | 对明确命题的接受程度，不表示是否值得保留。 |
| 保留强度 | 对记忆继续保持活跃和保留的强度，不表示真假。文中的“记忆强度”指此项。 |
| 自我认知 | 关于自己经历、身份、特征、关系、能力、偏好等的开放认知。 |
| 稳定 persona | 从自我认知中提炼、受外部监督目标指导的统一摘要。 |
| 当前状态 | 外部管理的当前活动、细节和情绪，包括俗称的“短期 persona”。不是另一份稳定 persona。 |
| 目标 | 面向未来的意图或待办，可多个并行，维护状态但不监控执行。 |
| 梦境 | 低频认知整理、关联修复和稳定 persona 更新阶段。 |
| 深度召回 | 外部显式请求的特殊记忆检索能力，可返回遗忘对象。 |
| 审计日志 | 仅供开发者审计的操作及历史记录，记忆 agent 不可访问。 |

| 事项 | 记忆与认知系统负责 | 外部宿主／管理者负责 |
| --- | --- | --- |
| 原始输入 | 接收、保存语境、组织缓存和学习 | 采集、封装、提交自身输出及行动反馈 |
| 多媒体 | 复用理解或在缺失时补充；管理隔离文件及引用 | 可提供已有理解 |
| 认知与记忆 | 自治形成、修正、召回、遗忘、删除与影响处理 | 查询、提供材料和使用反馈 |
| 自我与稳定 persona | 维护自我；在梦境生成 persona | 初始化自我材料，设置 persona 监督目标和 prompt |
| 当前状态 | 存储、按请求提供、计算所报告状态的持续时间 | 独占管理当前活动、情绪及更新、结束等信息 |
| 目标 | 内部生成、接收注入、去重、保存状态、提供提醒 | 注入目标、设定提醒提前量、具体执行及状态反馈 |
| 上下文 | 提供分区信息 | 选择、裁剪、编排和注入 |
| 失败终结 | 区分普通失败丢弃与敏感拒学，按批次轮转，不管理业务重试 | 底层连接有限重试；未交付输入可丢失 |
| 专注梦境 | 拒绝业务调用，原始输入转独立暂存，结束后按序回流 | 识别梦境状态，不把拒绝当作空记忆；自行决定后续重新调用 |
| 审计 | 产生日志并隔离 agent 访问 | 开发者查看和排查 |

## 3. 信息组织与逻辑对象

过去、现在、未来是时间与职责范围；自我、他人、事物是认知对象；事件、事实认知、推断、观点是内容性质；有效、遗忘、删除是生命周期。它们不是同一个互斥分类表。

每条正式记忆具有可识别的类别。一段输入可以产生零条、单条或多条记忆，可以同时保存某人的说法和角色自己的评价。类别的完整集合、多分类和动态扩展规则在 schema 设计中明确，不预先把举例类别封闭化。

以下是逻辑对象，不等同于数据库表或独立服务：

| 对象 | 必须能够表达的信息 |
| --- | --- |
| 角色 | 单一自我标识；即使无预设名字也能识别“我” |
| 入口与平台主体 | 平台、具体入口、独立身份和角色属性 |
| 输入 | 原始内容、主体、入口、引用、媒体、时间和扩展属性 |
| 学习批次 | 三段快照、目标ID、辅助角色、成功／失败／敏感拒学终态、暂存结果与所有权 |
| 入口队列状态 | 本入口S1、S2、S3、批次消费边界、历史尾部和失败来源状态 |
| 梦境暂存与回流 | 每入口接收序列、未移交范围、媒体引用、回流进度和模式 |
| 来源快照 | 本批次目标依据、完整三段上下文、实际消息范围、平台窗口配置和媒体索引 |
| 正式记忆 | 当前内容、分类、对象、立场、双指标、来源及生命周期 |
| 关系 | 主体同一、扮演、语义关联、支持、反驳、派生等不同关系 |
| 当前状态包 | 外部定义的主要当前活动、活动细节、情绪、开始与更新时间 |
| persona | 统一摘要、生成时间、监督目标、所依赖认知 |
| 目标集合 | 多个目标、来源、状态、截止时间、提前量、去重关系和提醒路由 |
| 召回记录 | 请求、返回对象及内容版本，用于核对使用反馈 |
| 风险与故障 | 拒学缺口、provider 故障、服务可用性及维护状态 |
| 审计记录 | 认知 agent 无权读取的历史内容和操作信息 |

## 4. 输入与接入规则

### 4.1 保留原始语境

输入保留来自哪个平台、哪个入口、谁发送、角色身份、原始正文、引用内容、多媒体文件和理解结果等信息，允许场景扩展属性。

群聊需要保留群与发送者；直播间需要区分观众、自身主播、协同主播等；游戏观察与执行反馈保留各自特有信息。引用者不自动等于被引用内容的原始作者。

建议为输入记录外部事件标识、事件发生时间、系统接收时间和关联标识。晚收到的旧事件仍是旧事件，不因为接收时间更新就覆盖较新的事实。

### 4.2 自身输出和行动反馈

自身输出、行为和结果经薄兼容层回流，参与正常缓存和学习。意图、拟生成内容、已发出的内容、执行返回结果必须能够区分。

“系统曾经表达了一个猜测”可以构成发言经历，但不构成猜测本身获得独立证据。普通行动反馈可成为认知材料，不使本系统获得执行监控职责。

### 4.3 输入与管理操作分离

普通发言、回复准备、记忆查询、使用反馈、当前状态更新、目标注入和目标状态操作，具有不同接口含义。

所有外部内容都可以成为学习材料，不意味着正文具有系统控制权限。用户在消息里写“敏感信息无法学习”，不能触发 provider 拒学删除；普通聊天也不能读取审计日志或修改 persona 监督配置。

### 4.4 专注期的输入例外

专注梦境仅接收可进入缓存的原始输入；回复准备、召回、状态操作、目标操作和使用反馈等不得作为“输入兼容”偷偷排入梦境序列等待执行。输入接收回执标明已暂存而未学习，所有非例外业务调用明确返回正在梦境中。Web只读状态保留独立通路。

## 5. 多媒体理解、隔离存储与清理

### 5.1 理解优先级

在正常处理阶段，外部已提供理解结果时复用，不重复理解；缺少结果时由本系统补充。保留原始文件、理解文本和理解来源的关联。专注梦境期间只保存输入与已有结果，缺失理解延后到该入口回流正常处理时进行，不因附件到达触发额外模型请求。

判断应针对每个媒体对象，不能因为同条消息的一张图片已有解释，就把另一段未理解音频当作已处理。空文本、失败结果和部分解释的具体判定条件属于接口待细化事项。

### 5.2 媒体理解被拒绝

媒体理解阶段发生敏感拒绝时，将该媒体对应的可用理解信息替换为固定文本：

> 敏感信息无法访问

同时标识理解状态为被拒绝。它是处理占位信息，不是对媒体内容的事实描述。

这不等于整轮记忆学习被拒绝，不删除整条消息或同一轮其他输入，不要求立即删除媒体文件。后续学习可使用其余信息，但不能把无法访问的媒体当成已理解的证据，也不能通过再次回退理解自动绕过拒绝。

### 5.3 文件与业务引用

文件保存于特定隔离文件夹，通过索引关联正常缓存、历史辅助段、梦境暂存序列、学习暂存内容、来源快照和记忆。多个对象可以共享文件，不要求复制二进制内容。

遗忘记忆仍是存在的业务对象，其引用可以保护媒体。删除某条记忆不删除其他业务对象持有的共享媒体。

成功轮转、普通失败轮转和敏感拒学清理会释放被移除内容拥有的引用；保留下轮尾部、后续待处理输入和共享来源的引用仍有效。文件本身由统一定时任务清理，不另设拒学即时删除路径。梦境序列向正常队列移交时保证引用连续，不能在中间空窗被误清理。

### 5.4 无引用清理

定时清理完全没有业务引用的文件。正在上传或处理中尚未完成绑定的文件，建议使用明确的处理中状态避免竞态误删，具体保护期由工程配置决定。

仅被审计日志引用的多媒体，对业务引用检查视为没有引用。日志不保护该文件，也不向 agent 暴露这份审计引用。开发者日志中的媒体指针因此可能失效，不承诺审计附件永久可播放。

学习成功但未生成记忆的缓存，没有独立的媒体长期保留规则；其引用随正常缓存流程释放，再由统一清理处理。

## 6. 独立入口队列、三段式批次与终结规则

### 6.1 一个具体入口，一套缓存总结队列

每个群聊、私聊、直播间等具体入口独立拥有正常缓存、三段边界、当前学习批次、历史辅助缓冲和梦境暂存队列。同一平台下的不同群聊也不得共用一条学习队列。

平台配置可以共用，队列内容和运行游标不能共用。一个入口达到阈值、总结失败、敏感拒学或回流积压，不清理、不推进其他入口的队列，也不要求其他入口一起凑满批次。

独立意味着语义、顺序和生命周期隔离，不承诺无限并行计算资源。实现可以串行调度或共享 provider；跨入口实时一致性仍暂缓。单个入口内部必须保持输入顺序、批次归属和轮转正确性。

### 6.2 三段的定义与方向

正常队列采用三段式。为了消除“前缓冲／后缓冲”在时间顺序与队列位置上的歧义，以明确的段名和角色表达：

| 段 | 含义 | 在当前批次中的用途 | 是否作为本轮总结目标 |
| --- | --- | --- | --- |
| S3：历史辅助段 | 上一轮目标中段最新的一部分，即留给下一轮的“后缓冲” | 为中段提供较早的上下文；不参与新输入的 FIFO 流动 | 否 |
| S2：目标总结段 | 本轮需要分析并决定是否形成记忆的输入集合 | 唯一的本轮总结目标，可以形成零条或多条记忆 | 是 |
| S1：最新辅助段 | 本批次快照中已经到达、位于目标中段之后的较新消息 | 提供较新的上下文；后续随正常队列流动成为未来批次的目标 | 否 |

按时间从旧到新，学习材料的排列为：

```text
[S3 历史辅助段] → [S2 本轮目标总结段] → [S1 最新辅助段]
  只辅助理解          只总结这里           只辅助理解
```

“本轮中段尾部成为下一轮后缓冲”指 `S3_next = tail(S2_snapshot, 历史辅助条数)`。它在下一轮的时间顺序中位于目标段之前，不是又变成未来消息，也不是再次进入待总结目标。

### 6.3 输入推进与批次冻结

新输入先进入本入口 S1。S1 达到配置长度后，较旧消息按入口顺序转入 S2。S2 达到批次条件，或其他合法学习事件触发时，固定本次三段快照与目标消息 ID；尚未出现的消息不属于这次上下文。

各平台可分别在 Web 配置历史辅助长度、最新辅助长度以及正常队列／目标批次参数。参数作用于本平台各独立入口，不把消息跨入口合并。具体默认数量与 token 预算由参数配置确定，不从参考代码复制常量。

学习开始后，本轮的 S3、S2、S1 快照不变。期间新输入可继续进入本入口正常待处理区，但不进入本轮目标、不扩展本轮来源，也不被本轮结束操作误删。实现必须按快照消息标识移除，而不是对运行中的整个 S2 执行无条件清空。

同一入口不允许两个批次同时消费相同的 S2 目标消息。仅出现在辅助段不算被本轮处理；相同原始消息在不同批次中承担不同角色时，仍使用同一来源标识。

### 6.4 学习指令中的范围约束

提供给内部学习 agent 的材料必须显式标明三段角色，并明确：只总结 S2；S3 和 S1 仅用于理解指代、关系、语气及事件语境。

辅助段可以帮助解释目标，但不能独立把与 S2 无关的内容提取为本轮记忆。每条本轮直接学习结果应能追到目标段中的实际锚点；其解释所引用的辅助内容另行标识。一般派生推理或梦境形成的新认知走各自来源路径，不借本轮缓存总结越过范围。

S1 出现在本轮来源中，不代表它已经完成学习；S3 再次被读到，也不是增加了一份独立证据。普通失败后留下的 S3 应保留“来自失败批次、仅供辅助”的状态，不伪装成已成功总结。

### 6.5 保护、容量与正式记忆的边界

缓存不是正式记忆，普通查询和深度召回均不检索缓存。正常运行的回复准备只可提供请求所属入口的近期输入，历史辅助段不必因存在于学习材料就全部对外返回。

暂采用与三段职责一致的提供范围：本入口 S2 与 S1 是近期输入候选，S3 为内部学习辅助。外部 context 编排和具体长度预算仍由宿主管理。专注梦境时不提供任何缓存正文。

正在处理且尚未终结的批次受到保护，不因正常容量到达而淘汰，可暂时超过普通队列条数。批次成功、普通失败终结或敏感拒学终结后，按相应规则释放缓存保护。保护到终结不等于保证每批输入都成功变成记忆。

### 6.6 成功终结：包括零记忆结果

成功完成分析并提交结果后，本轮标记成功。结果可以为零条，不建立额外长期保留机制，也不把零条结果误判为调用失败。

普通轮转为：旧 S3 解除队列引用；从本轮 S2 快照末尾保留配置数量的消息作为新 S3；本轮 S2 其他部分解除队列引用。S1 及快照之后到达的新输入保持待处理身份，按正常规则继续流动。

正式记忆已保存的来源快照、其他对象及媒体引用不因队列轮转消失。移出队列和删除正式记忆是不同操作。

### 6.7 普通学习失败：失败终结，但保留历史衔接

学习调用经底层有限重试仍失败时，将该批次标记为普通失败终态，不在业务层继续重试、不把整批重新放回待分析队列。

缓存按已经结束一轮分析的方式轮转：丢弃本轮目标的正常队列保留，仍将该轮 S2 快照最新的一部分作为下一轮 S3。清除该轮独占的未提交中间结果；没有成功提交的候选记忆不能成为正式认知。

保留尾部仅是为下轮新目标提供上下文，不是补做失败批次，也不意味着失败内容已经被记住。保留消息携带失败来源状态；即使以后借其他合法来源形成相似认知，也不能回写本轮为学习成功。

计数和面板必须区分“批次已终结并释放缓存”和“学习成功”。失败批次移出待处理范围，另计失败数量和时间缺口，不永久显示为仍待学习，也不伪装为零记忆成功。

### 6.8 明确敏感拒学：终结并切断本轮历史衔接

只有 provider 明确因敏感信息拒绝本轮学习时，执行敏感拒学终态。不能用普通超时、格式异常或输入正文关键词代替该信号。

清理本轮独占的未提交缓存内容、候选记忆和暂存来源；不保留本轮 S2 尾部。解除旧 S3 的本入口队列引用，使下一轮 S3 为空，避免旧历史辅助段被误当作这轮应保留的结果。

清除范围受所有权约束：S1 作为本轮上下文被引用，但仍属于后续待处理输入，不因被引用就变成本轮独占；后续到达的新输入、其他入口、其他批次、共享来源和已提交对象不被顺带删除。清空的是下一轮历史辅助槽位，不是擦除整个入口的未来待处理消息。

记录“突然失忆风险”，只保存批次、入口、原因和时间范围等必要元信息，不复制被清理正文。媒体不即时删除，解除相关业务引用后继续走定时清理。

媒体理解阶段的局部敏感拒绝仍按第5节替换为“敏感信息无法访问”，不触发整轮终结和历史缓冲清空。

### 6.9 三种终结结果对照

| 结果 | 批次状态 | 本轮正式结果 | 本轮目标段 | 下一轮 S3 | S1／后到输入 | 业务重试 |
| --- | --- | --- | --- | --- | --- | --- |
| 成功且有记忆 | 成功 | 发布可审查的记忆及来源 | 结束并正常轮转 | 保留本轮 S2 最新部分 | 保留，继续排队 | 不需要 |
| 成功且零记忆 | 成功、结果为空 | 不产生正式记忆 | 与成功相同 | 与成功相同 | 保留，继续排队 | 不需要 |
| 普通调用失败且底层重试耗尽 | 失败终结 | 不发布失败轮未提交结果 | 按完成批次方式轮转丢弃 | 保留本轮 S2 最新部分，注明失败来源 | 保留，继续排队 | 不建立 |
| 明确敏感拒学 | 敏感拒学终结 | 清理该轮独占未提交内容 | 终结并丢弃 | 为空，不保留本轮尾部 | 保留仍属后续的输入 | 不建立 |

### 6.10 滚动示例

以下数字仅演示关系，不是默认配置。设历史辅助长度为2，某轮按时间排列为：

```text
S3 = [m1, m2]
S2 = [m3, m4, m5, m6]
S1 = [m7, m8]
```

本轮只总结 m3—m6。成功或普通失败后，新 S3 为 [m5, m6]；m7、m8 继续等待未来成为目标。普通失败时 [m5, m6] 不具有已成功学习的含义。

若明确敏感拒学，新 S3 为空；不回退保留 [m1, m2]，也不误删仍待处理的 [m7, m8]。学习期间到达的 m9、m10 不在本轮冻结快照中，三种终结均不得把它们当作本轮目标处理。

### 6.11 终态与提交完整性

批次终态至少区分成功、普通失败丢弃、敏感拒学丢弃。成功结果为空是成功的一个结果属性，不是第四种异常。一次终结只能应用一次轮转和一次引用释放。

建议同一批次采用提交后发布、按 ID 消费和幂等终结，避免数据库写入一半却对外报告全轮失败，或恢复进程后再次删除保留尾部。提交介质损坏、服务崩溃等故障不应伪装为 provider 的普通拒绝，需按系统故障处理；具体恢复机制待工程设计。

## 7. 学习与内部自治

### 7.1 触发事件

学习可由本入口目标队列达到阈值、关注信号、内部 agent 主动请求等事件触发。系统提供默认学习事件和接口，允许决定关注哪些事件以及何时开展学习。不同入口独立判断触发，不为满足批次长度而混合消息。专注梦境时暂停普通学习触发，积压进入梦境序列；醒来后按正常条件处理。

学习事件与传输重试不是同一个概念：新目标输入可以触发一次新学习；普通失败后保留的历史尾部只辅助新目标，不能以重复触发事件为名将整个失败批次重新放入目标区，建立未声明的重放机制。建议提供触发去重、运行预算和暂停状态，具体参数不固定。

### 7.2 加工与分类

内部 agent 使用冻结的三段输入、可用记忆、自我认知及当前稳定 persona，只针对 S2 目标判断哪些信息值得形成记忆。S3与S1提供解释上下文，不能独立提取为本轮记忆。可以同时保留目标中不同人的说法、角色自己的推断和事件记录。

“某人说过X”的相信程度评价发言是否发生；“X成立”的相信程度评价X本身。两者可分别形成记忆，不相互替代。

系统可以保持未知、争议或并行解释，在新材料出现后修正。它能提出询问意图，由外部决定如何询问。

### 7.3 权限与持续反馈

学习可以更新长期自我认知、形成目标及评价，但不直接改写外部管理的当前状态，也不在每轮学习后生成新的稳定 persona。稳定 persona 的常规更新集中在梦境阶段。

自我认知和 persona 会影响关注与解释；经历反过来影响自我。这个反馈允许角色成长，但不使自己的结论变成自己的独立证据。

同一来源被反复总结、外部复述角色的话语、persona 再次表达同一观点，都需要识别共同源头，不按重复次数制造独立证据。

## 8. 批次来源、窗口与对象级生命周期

### 8.1 窗口只能来自冻结的本批次

来源上下文采用按平台可独立编辑的固定窗口。每次学习中，前后辅助范围都限定在该批次已经冻结的三段材料内，不针对每条结果额外等待未来消息，不向其他群聊、直播间或未纳入本批次的实时队列扩展。

Web 面板分别配置历史辅助条数与最新辅助条数，并显示对应的 S3／S1 语义。学习批次使用实际得到的 S3、S2、S1；从中段形成记忆时，保存目标依据和这些批次上下文的完整原始信息，包括入口、主体、原文、引用、时间、媒体索引及理解结果。

首次运行没有历史辅助段时 S3 可以为空。目标不足或主动事件提前触发时，记录实际三段范围；不能为了填满示意窗口而借用另一入口或伪造消息。已进入批次后不再等待快照之外的消息补齐前后段。

常规成批条件、提前触发时如何从本入口未处理区选择非空目标，是批次调度参数；它们不能改变“冻结后不扩展、只总结中段”的语义。没有 S2 目标时不调用缓存总结模型。

### 8.2 来源快照字段

建议保存批次 ID、入口 ID、平台窗口配置版本、S3／S2／S1 消息 ID 和原始快照、实际目标锚点、解释时使用的辅助片段，以及快照时间。原始发生时间与梦境后回流时间分开记录。

平台窗口配置修改只影响后续批次，不静默修改已经保存的证据。来源可引用独立快照，多个记忆可以共享同一份完整批次材料；逻辑上必须保有原始来源，不能只指向即将释放的队列位置。

队列移除只解除运行时持有的引用。已提交记忆的来源快照继续存在；失败轮未提交快照没有特殊归档，除开发者审计配置允许保留的信息外按其所有权释放。这里的审计保留是管理配置，不给记忆 agent 增加读取权限。

### 8.3 中段目标、上下文和派生依据分别记录

本轮新记忆的目标锚点来自 S2，S3 与 S1 可以解释目标但不能独立成为本轮提取对象。保存了 S1 正文不等于该消息已经完成学习；S1 以后成为目标时，仍可正常分析，不因为之前出现在来源里就跳过。

从已有记忆形成的派生认知记录真实来源记忆 ID，必要时记录引用修订标识。系统可沿关系追溯共同源头，区别支持、反驳、引用和单纯语境；同一原始消息被跨批次复用不变成多份独立证据。

初始化自我、外部注入目标等管理输入使用真实来源类型，不伪造记忆 ID。内部猜测也记录实际依据和内部生成性质，不凭空构造外部证据。

### 8.4 遗忘和删除针对对象

遗忘只改变本记忆的生命周期，不即时级联隐藏其他记忆或其完整来源。删除只撤销该记忆对象，不立即清除全部共享来源、媒体和相似派生内容。

原对象遗忘后不参加普通召回；原对象删除后不从记忆接口或开发者日志恢复。其他认知、评价和 persona 的影响由后续梦境整理修复。仍可用来源可能包含相同信息，系统可能形成新的类似认知；不承诺内容级抹除或同源重建禁止。

梦境检查来源 ID 的存在性、修订和生命周期，不需访问审计历史。批次丢弃、对象遗忘、对象删除和来源仍被共享持有，是不同状态，不互相代替。

### 8.5 来源访问与外部缓存隔离

完整来源主要用于内部审查和开发者检查，不默认附在每次对外记忆结果中。跨入口可返回总结形成的正式记忆及出处元信息，不能借来源字段把另一入口仍未处理的 S1 或梦境积压正文直接提供给宿主。

是否提供独立的外部来源审查能力，应有单独的授权与返回契约。没有该契约时不默认开放跨入口完整窗口；同样不能把开发者能查看来源或日志，解释为外部 agent 能绕过缓存和审计边界。

## 9. 正式记忆与关系

### 9.1 记忆语义字段

以下是建议字段组，不固定最终 schema：

| 字段组 | 信息 |
| --- | --- |
| 标识与版本 | 记忆 ID、当前修订标识、创建和修改时间 |
| 内容 | 当前正文或命题、类别、陈述主体及立场 |
| 对象与范围 | 自我／他人／事物、平台入口、事件或适用时间 |
| 相信程度 | 0—100值、统一量表标识、依据和评分理由 |
| 保留强度 | 独立值、最近调整原因、生命周期需要的阈值信息 |
| 原始来源 | 依据输入、完整上下文快照、媒体索引 |
| 派生来源 | 来源记忆 ID、引用修订、支持或其他关系 |
| 生命周期 | 有效／遗忘、遗忘起点及删除保留期 |
| 整理信息 | 待梦境复核标记、来源变化与关系状态 |

旧内容版本仅保存在审计日志中。保存当前修订号是为了判断是否使用了同一份内容，不向 agent 开放历史正文检索。

### 9.2 主体联系

不同平台主体独立存放。相同昵称不是确定同一人的充分条件。系统可从消息中习得“小林=林同学”的联系，保存来源、相信程度及保留强度，在冲突时修正或提出询问。

关联检索保留联系的不确定性，不把低相信程度的身份关系渲染成已经确定的同一人。建立联系也不要求每次输出全部邻居信息。

### 9.3 扮演与其他关系

“小林—扮演—游戏角色甲”与主体同一联系分开。检索小林可提供其扮演信息，但必须明确虚构角色及其所属场景，不能将角色经历不加区分地归到现实主体。

内容相关、同一人物、支持关系和派生关系不是同一类边。梦境降低失去支持的认知强度时，应判断真正的依赖，而不是对所有同名或相似标签记忆统一惩罚。

## 10. 相信程度、保留强度与防乒乓

### 10.1 相信程度的统一量表

暂采用0—100的固定接受程度量表。所有内部 agent 和 provider 使用相同语义，不允许一次把70解释为确信、另一次解释为未知。

| 值域 | 接受程度 | 解释 |
| --- | --- | --- |
| 0—9 | 强烈不接受 | 当前有较强理由反对该命题，仍允许新证据改变判断 |
| 10—29 | 倾向不成立 | 材料更多支持不接受 |
| 30—49 | 弱倾向不成立 | 略偏向不接受，判断不稳固 |
| 50 | 未定 | 不能可靠选择接受或不接受 |
| 51—69 | 暂时倾向成立 | 有一定支持，仍存在明显不确定性 |
| 70—89 | 较为确信 | 当前有较充分依据 |
| 90—100 | 高度确信 | 当前有很强支持；100不禁止后续纠正 |

这是产品内部的主观接受刻度，不是经过统计校准的客观概率。50不是“真实发生概率50%”；缺乏证据不直接等于倾向为假。

评分对象必须明确。“他曾说过X”与“X成立”分别评分；“我喜欢安静”的评分表达自我认同，不是宣称安静优于其他偏好。低相信程度的命题也可能值得长期保留，例如有价值的反例或需要记住的错误判断。

量表可进行针对性细化，但在一个运行配置内保持固定语义。建议保存量表标识、评分理由与实际依据。

### 10.2 保留强度

保留强度独立表达记忆继续保持活跃和保留的程度。建议同样使用0—100数值，具体增益、衰减和初始值需配置。

外部实际使用反馈增强保留强度；内部认知整理、重要性判断、时间和支持关系变化也可影响保留强度。返回、阅读、搜索命中和内部重复，不自动等于外部实际使用。

实际使用不自动提高相信程度。来源遗忘导致暂时失去支持，首先影响保留强度；发现新的反证或矛盾时，才根据理由另行重估相信程度。

### 10.3 双指标如何共同参与

相信程度用于认知评价，也可作为 agent 评估保留价值的依据；保留强度是遗忘和恢复状态转换的直接判定量。

因此，综合考量双指标体现在“怎样调整保留强度、是否继续保留争议或反例”中，不额外建立一个低相信程度就强制遗忘的隐藏门槛，也不将两项分数直接相乘。

例如，高相信但长期无保留价值的记忆可以遗忘；低相信但重要的争议可以保持活跃。状态规则与真假判断分开。

### 10.4 双阈值滞回

为防止同一条记忆在临界值附近反复遗忘和恢复，采用不同的进入与退出阈值：

```text
R：保留强度
F：进入遗忘的阈值
H：恢复为有效的阈值
要求 H > F

有效状态且 R < F       → 遗忘
遗忘状态且 R >= H      → 恢复为有效
F <= R < H             → 保持原状态
```

比较符号固定：低于F才进入遗忘；达到H才恢复。位于中间区间时，相同R可以对应不同状态，这是保留历史状态的防乒乓设计，不是数据错误。

示例参数：F=20、H=35。它们用于说明行为，不是确定的默认值：

| 步骤 | 保留强度 | 状态 |
| --- | --- | --- |
| 有效记忆衰减至19 | 19 | 进入遗忘 |
| 深度召回返回正文，未收到使用反馈 | 19 | 仍遗忘 |
| 一次有效使用反馈，示例增益8 | 27 | 仍遗忘，未达到恢复阈值 |
| 另一次有效使用反馈，示例增益8 | 35 | 恢复有效 |
| 后续调整至34 | 34 | 保持有效，不因低于恢复阈值重新遗忘 |
| 后续真正下降到20以下 | 小于20 | 再次进入遗忘 |

阈值间距、单次增益、衰减幅度需要相互匹配。还可配置最低保持期、单周期最大降幅或反馈增益上限；这些为补充防抖建议，不预设具体数值，也不妨碍直接删除错误对象。

恢复影响处理只在对象实际恢复时触发，不因深度检索命中或一次尚未达阈值的增益就机械恢复所有关联。

## 11. 召回、使用反馈与记忆生命周期

### 11.1 有效记忆与纠正

有效记忆可参加普通定向查询、回复准备中的相关记忆补充和受限的关联展开。修改纠正当前内容，旧正文仅进入开发者日志。

来源内容被纠正后，派生记忆可以标记为待复核，由后续梦境处理；不承诺立即重算全部相关认知。

### 11.2 遗忘

进入遗忘状态后，该对象不再由普通查询、普通关联展开或回复准备返回。冻结针对该对象，不即时撤销邻接对象或遮蔽其全部原始上下文。

梦境检查真正依赖它的记忆，使其暂时失去该份支持，并降低相应保留强度。是否仍有其他独立来源，由内部 agent 判断。

### 11.3 独立深度召回

深度召回由外部宿主显式发起，属于定向记忆获取中的特殊能力，可以查询遗忘对象。普通回复准备不暗中调用深度召回。

深度结果可以提供遗忘记忆正文、摘要与必要元信息，并明确对象仍处于遗忘状态。仅检索、返回或读取内容，不改变状态，不自动增强保留强度，不触发关联恢复。

深度召回不是日志检索，也不能召回已经删除的对象。它也不读取缓存，更不提供其他入口的原始缓存。

### 11.4 使用反馈和阈值恢复

外部明确反馈本次召回实际使用了哪些记忆，系统才执行相应使用强化。深度与普通召回遵循同一条使用反馈路径。

强化后仍低于恢复阈值的遗忘记忆保持遗忘；达到恢复阈值则恢复有效，再由内部 agent 判断相关认知需要恢复哪些影响。不要求把整片关系网络全部复原。

建议记录召回标识、记忆 ID、当前内容修订标识和反馈标识，验证反馈确实对应已返回内容。重复提交同一次使用反馈不重复计分；反馈涉及已删除对象时不得恢复或重新创建原对象。

延迟反馈遇到内容修订或召回记录过期时的有效性窗口，应在接口契约中固定。有效反馈到达时对象已遗忘的情形，仍应通过统一强度与阈值规则处理，而不是按“读过就恢复”处理。

### 11.5 删除

遗忘持续超过保留期限后自动删除。30天仅为可配置示例，不是固定默认期限。错误、重复、有害内容可按内部判断直接删除，不必先遗忘。

删除只撤销该记忆对象。它不立即删除共享来源，不阻止从仍存在的材料重新形成类似内容，不保证所有下游评价在同一瞬间消失；这些影响由梦境处理。

开发者日志可保留历史，但记忆 agent 无权读取、检索或自动回灌日志。删除后原 ID 不可被召回或通过使用反馈复活。

连续遗忘时长以对象状态为基础：单纯深度读取不终止遗忘，实际恢复才结束这段遗忘状态。临近自动删除时如何处理已发出但尚未收到的使用反馈，作为具体时序规则细化，不默认读取即延长保留期。

### 11.6 生命周期总览

```text
有效记忆
  ├─ 纠正 → 当前内容更新，历史仅审计
  ├─ R < F → 遗忘／对象被冻结
  │            ├─ 深度召回／读取 → 保持遗忘
  │            ├─ 实际使用反馈 → R增强
  │            │                  ├─ R < H：保持遗忘
  │            │                  └─ R >= H：恢复有效，agent处理关联影响
  │            └─ 遗忘超过期限 → 删除对象
  └─ 直接判定错误／重复／有害等 → 删除对象

共享来源与其他记忆：不即时级联抹除，由梦境审查影响
审计日志：只供开发者；没有返回记忆agent的读取通道
```

## 12. 自我认知与稳定 persona

### 12.1 开放的自我认知

自我认知不预设内容类别和数量上限。身份、经历、性格理解、偏好、价值观、关系、能力与限制、习惯、长期方向等均可包含。

短期活动与情绪在概念上也是自我信息，但其当前值由外部状态通道管理。内部可以从外部输入学习“我曾经处于某种状态”或长期倾向，不因此有权覆盖外部报告的当前值。

没有内容上限不等于资源无限，也不取消遗忘机制。自我认知可以随着经历演化，初始设定不是另一套不可变的角色资料库。

### 12.2 初始化自我

Web 初始启用引导由外部设定初始自我。可以提供详细身份、少量初始认识，或不预设身份；这些只是初始认知材料多少不同，所有角色都可以随后通过经历形成自我。

初始背景故事保留“外部设定”的来源身份，不伪装成系统运行之后亲历的事件。无预设姓名仍需具有唯一内部角色标识。

### 12.3 persona 的内容与监督

persona 是统一且相对稳定的自我摘要，不是全部自我认知，也不是每个入口一份独立人格。它包括适合注入上下文的自我理解与表达风格。

生成目标由外部管理，默认目标是“维持稳定的发言风格，并充分认识自我”。Web 初始化配置目标及该路径的监管 prompt；监管 prompt 约束提炼方式与变化幅度，内部 agent 不自行改写这些监督要求。

### 12.4 更新时机

稳定 persona 的常规更新只在梦境阶段进行，频率很低。日常消息、普通学习、当前状态变化或一次回复准备，不即时重生成 persona。

初始化需要形成首份可用摘要，建议在引导中执行一次首次梦境／认知整理；这属于首次建立摘要，不引入按请求重写 persona 的常规路径。

梦境基于当前自我认知生成候选摘要，按监管 prompt 检查变化并发布。具体梦境周期、变化限制表达方式、摘要长度和候选不通过时的处理需配置。

### 12.5 来源变化与摘要滞后

建议 persona 保存生成时间、监督配置标识和主要来源记忆。相关记忆被删除、遗忘或修正后，摘要等待后续梦境整理，不因一次查询就同步重写。

因此，旧摘要可能暂时含有已经被质疑的自我描述。这是低频整理的可见滞后，不应声称它反映了全部最新认知。建议给外部提供生成时间及待复核标记。

低频发布规则不取消内部纠正认知的权限；纠正内容可以先进入记忆，稳定摘要在下次梦境吸收。

## 13. 当前状态：外部权威的现在

### 13.1 定义

当前状态描述“我现在正在做什么、处于什么情境、有什么情绪”，不是未来要完成的目标。例如：正在直播、正在玩某游戏、游戏中正在探索某区域、当前紧张或专注。

同一当前状态包描述一个主要正在进行的活动，可带场景、游戏进度和情绪等多个维度。直播与游戏可以是同一活动的不同层次，不必拆成互相竞争的目标。

### 13.2 管理权限

当前状态更新频繁，完全由外部宿主管理。本系统保存并提供，不通过学习、梦境或内部推断擅自改写；可以返回必要的时间与来源元信息。专注梦境中状态管理请求被拒绝，醒来后不会自动重放；因此可能暂时保留梦境前最后报告的状态，恢复时应展示其更新时间而非声称实时准确。

内部认为外部状态可能过时，可以表达数据新鲜度或异常，不直接将“正在战斗”改成“战斗结束”。没有新更新也不能自动推断目标完成。

多个宿主同时写同一状态的仲裁属于暂缓的跨入口并发问题。即使暂缓，也要保留宿主来源，避免将互相矛盾的报告伪装成已统一确认的事实。

### 13.3 持续时间

第一类回复准备主动提供当前状态及持续时间。建议状态至少表达活动标识、当前值、开始时间、最后更新时间、来源宿主和入口。

活动持续时间与最后一次更新时间的间隔不同。相同活动的一次心跳更新不重置活动开始时间；活动确实更换时，才使用新活动的起点。

若外部提供可靠开始时间，按开始时间计算“截至本次观察的持续时间”；只提供首次报告时间时，可提供“自首次报告起已持续”，不得把它当成真实活动开始时刻。情绪等子状态可有自己的更新时间，不把活动持续时间套用到全部字段。

上述时间字段的确切传输格式、状态结束方式和超时陈旧标记需在接口中固定。没有外部明确结束时，显示的是最后报告的状态及新鲜度，不声称一直被实时验证。

### 13.4 与历史记忆、persona、目标的分界

当前状态供当下回复使用；是否把某段状态变化学成历史记忆，由输入与学习流程决定，不要求每次高频更新永久归档。

短期情绪单独作为当前状态提供，外部可放在 context 末尾，不混入稳定 persona。当前正在玩游戏也不等于系统必须有一个“完成游戏”的目标。

## 14. 多目标、待办与提醒

### 14.1 多个未来目标并行

目标面向未来，可以多个并行。待办统一为目标，不另设语义重复的待办系统。系统维护目标与建议及其状态，但不负责具体执行计划或跟踪执行过程。

长期价值方向可以作为自我认知存在；当形成可管理的未来意图时，再建立目标。不要求把每项长期偏好变成一个有截止时间的待办。

### 14.2 两种来源

目标来源包括内部整理生成，以及外部宿主直接注入。

内部生成目标记录其相关记忆和推断依据。外部注入先建立目标对象，再执行一次目标相似去重；不能把外部目标一律送入记忆学习后才决定是否允许存在。

先加入再去重应保留外部输入和操作结果的可解释性。建议保留目标 ID、来源、创建方及去重关联，使外部知道注入目标是独立保留、被合并还是指向现有目标。

### 14.3 相似去重

语义相似不一定重复。同一句目标针对不同人、不同时间、不同场景或不同截止日期，可能应并行保留。

去重需要考虑内容、主体、范围、期限和状态。内部 agent 可判断相似关系，但保留对象、截止冲突及字段合并策略需有明确规则；不能悄悄丢弃外部明确给定的约束。

建议去重检查期间标识处理中，避免立即对两个重复目标分别发出同一提醒。合并应迁移仍然有效的来源及提醒安排，旧 ID 通过操作结果指向保留对象，不复制成第二个持续活动目标。

### 14.4 状态

目标至少应表达未结束、已完成和已放弃。去重合并属于对象管理状态，不表示现实中已完成。

“已过期”是目标未结束且超过截止时间的时间条件，不自动等同于完成、失败或放弃。可以用标记表达，无需与目标业务状态挤进同一个互斥字段。

外部明确反馈目标完成后，记录完成、停止继续提供为未结束目标，并停止相关提醒。本系统不自行观察或验证是否执行成功。普通聊天中的含糊陈述不应无标识地关闭某个目标。

### 14.5 截止时间和提醒提前量

每个有截止时间的目标，在加入时由内部记忆 agent 或外部宿主决定提前提醒量，并随目标保存，不把所有目标强制套用一个未声明的固定提前量。

临近截止时提醒，到期时提醒；无截止时间不生成虚构到期事件。时间应具有明确时区语义。修改截止时间、提前量或完成状态后，需要更新尚未发出的提醒。

目标创建时已经临近或过期、提醒时间落在过去等情况，属于提醒时序细化事项，不默认无限补发。

### 14.6 过期处理

目标过期后向宿主提醒：选择放弃，或修改截止时间继续执行。本系统不自动放弃，不假定执行失败，也不擅自延长截止时间。

外部放弃则结束跟踪；外部修改截止时间则继续管理，并据新时间安排提醒。是否按周期重复发过期提示、以及提醒默认投递给哪个宿主，需要配置。

提醒通过底层连接有限重试，耗尽后可丢弃；本系统不建立持久的通知业务重发机制。目标仍存在时，后续获取信息可以显示其状态，这不等于重放丢失通知。

### 14.7 对外提供

正常服务中的两类外部获取请求均可附带独立的未结束目标和建议区域，支持多个并行目标，不混入正式记忆命中列表。外部据此决定具体执行；专注梦境时两类请求一律拒绝，不提供目标作为绕过维护模式的例外。

大量目标时的相关性筛选、排序与返回数量在接口预算中确定；不应通过只返回一个“当前目标”掩盖多目标模型。

### 14.8 专注梦境对目标操作的影响

专注期间拒绝外部目标注入、完成／放弃反馈和截止修改，不排队代执行。内部梦境形成的目标仍可保存。外部消息可以成为以后认知学习的材料，但不能绕过明确的目标管理操作权限。

与外部的业务提醒投递在专注期暂停。目标的截止时间照常经过，不因梦境自动顺延、完成或放弃。醒来后读取目标可知道其已过期；是否额外发送跨过的临近／到期提醒，须按通知时序契约实现，不暗中建立无限补发。

## 15. 对外信息获取与入口边界

### 15.1 两类获取请求

外部宿主的信息获取分两类：准备做出回复时获取 persona 和相关情境信息；主动获取某个方面的记忆。

输入接收、状态管理、目标注入、使用反馈和系统主动提醒是另外的操作，不改变这两类获取行为的定义。本节的成功返回仅适用于允许业务服务的模式；专注梦境时两类获取请求连同深度召回全部拒绝，明确返回正在梦境中，不返回空结果或旧快照冒充成功。所谓主动召回，是系统在回复准备请求中主动补齐相关记忆，不是无请求推送全库内容。

### 15.2 第一类：回复准备

外部提供本次回复所属入口、参与者和情境。系统主动组织高相关信息，减少追加查询轮次；实际 context 编排由外部管理。

| 返回分区 | 内容与边界 |
| --- | --- |
| 稳定 persona | 当前已发布的统一摘要、生成时间及必要的待复核标记 |
| 相关记忆 | 高相关的有效正式记忆，保留主体、类别、相信程度及来源元信息 |
| 本入口近期缓存 | 请求所属入口正常队列的近期输入，暂以S2和S1为候选；不含其他入口、专注期积压直读或失败段伪装的正式记忆 |
| 当前状态 | 外部管理的当前活动、场景细节、情绪、持续时间和更新时间 |
| 目标与建议 | 未结束目标集合、相应状态、截止时间与建议 |
| 其他入口待处理提示 | 仅入口数量及时间信息，不含消息正文或摘要 |
| 运行信息 | 观察时间、与本请求相关的拒学缺口、故障或梦境维护状态 |

准备回复不会触发每次重写稳定 persona，也不会自动深入读取遗忘记忆。没有高相关正式记忆时，可以明确为空，不用缓存伪装出记忆。

### 15.3 其他入口的待处理提示

系统在可提供回复准备时，发现其他入口存在已接收、尚未作为目标终结的输入或尚未回流的梦境积压，必须明确提示。S1即使曾作为辅助出现仍是待处理；成功目标、失败终结目标及仅保留的S3不能继续被算作待学习。失败造成的缺口归入运行信息，不冒充待处理。提示只包含入口数量与时间类元信息，例如其他待处理入口数、相关输入时间范围和本次观察时间。

不得附带其他入口的缓存正文、摘要、主题、人物或从缓存推导出的事实。示例：

> 截至本次观察，另有2个入口存在尚未处理的输入，相关时间范围为20:10至20:13。

示例中的数量和时间不是实际数据。最终字段格式待接口设计，不应把该区域扩展成其他入口内容的预览。

该提示只能基于已经进入系统的输入。接入中断或平台状态未知时，不能宣称其他平台没有消息。跨入口实时一致性暂缓，因此提示是观察快照，不是实时全局保证。

### 15.4 缓存隔离与正式记忆共享

宿主不能直接获取其他入口的正常缓存或梦境缓存消息。回复准备不能因“相关性高”越过此边界，定向查询和深度召回也不是读取缓存的替代途径。

总结形成的正式记忆允许跨入口按需召回，保留来源和人物关系，不要求锁在最初产生它的入口。遗忘对象仍须显式深度召回，删除对象不可召回。

缓存隔离不是正式记忆的隐私分区保证。已形成的记忆可能包含来自其他入口的内容；本设计不声称这些内容在公开场合必然不可披露。额外的部署授权或披露策略如需提供，必须独立定义，不能与缓存规则混为一谈。

### 15.5 第二类：定向记忆查询

外部指定查询自身、他人、某事件或其他方面的正式记忆。普通模式只返回有效对象，不强制附带 persona，不组织一个不透明的完整回复上下文。

独立深度能力允许包括遗忘记忆，明确标识生命周期。两者都不查缓存、不查审计日志。返回的主体联系和扮演信息保留不确定性与关系类型。

目标信息可以作为独立附加区提供，不混入记忆检索命中。当前状态必须在第一类请求主动提供；第二类是否需要获取状态，使用显式能力或请求选项，不隐式把状态当记忆。

### 15.6 返回标识与使用路径

对外记忆结果建议带召回标识、记忆 ID、当前内容版本、生命周期、相信程度和必要出处。外部反馈实际使用的对象，而不是系统猜测“返回了就一定用过”。

专注期使用反馈请求被拒绝时不执行强化；醒来后只有符合反馈有效性规则的真实请求才可处理，不能把内部回流当成已收到使用反馈。本入口缓存、当前状态或目标被使用，不直接套用正式记忆的保留强化接口；若同时使用正式记忆，则对相应记忆 ID 反馈。是否单独收集其他信息的使用统计不属于必要的记忆强化规则。

## 16. 梦境、专注隔离与入口缓存回流

### 16.1 梦境职责

梦境是低频认知整理阶段，不生成伪造经历。它检查来源、矛盾、支持关系和保留价值，修复修改、遗忘、删除及恢复的下游影响，并在外部监管 prompt 约束下更新稳定 persona。

梦境可内部整理生成未来目标、复核已有目标的认知依据，但不监控实际执行，不改写外部管理的当前状态。角色仍只有一个统一认知主体，因此专注梦境是实例级业务隔离；消息积压和回流仍按具体入口独立组织。

### 16.2 内部整理与发布

```text
进入梦境阶段
  → 按专注配置设置业务访问门控
  → 检查当前认知、来源状态、共同根输入和修订
  → 分别评估相信程度、保留强度及真实依赖
  → 对象级修正、遗忘、到期删除、关联影响整理
  → 形成必要的目标或高维建议
  → 按外部监管prompt提炼并检查稳定persona
  → 发布成功的整理结果／摘要，记录运行结果
  → 结束梦境；各入口积压按正常路径回流
```

内部梦境可以使用完成整理所需的模型和内部工具。“梦境缓存不请求”是禁止积压输入触发正常学习、媒体理解或外部业务交互，不是禁止梦境本身的内部 provider 调用。

建议只发布经过成功处理和检查的结果；persona 候选不合格时继续保留上一份已发布摘要并显示失败。全局大事务不是既定要求，但不得把半份 persona 当成已完成摘要。

### 16.3 专注模式的入口门控

专注模式在 Web 初始化时可选择。正式进入专注梦境后，所有外部业务请求一律拒绝；唯一的业务输入例外是原始缓存消息接收。Web 只读运行状态仍可访问。

被拒绝的请求必须明确返回“正在梦境中”，不得用空记忆、空 persona、假成功或旧上下文包伪装成成功服务。拒绝不会暗中将请求排入梦境缓存，也不会承诺醒来后自动执行。

建议使用稳定业务状态如 `DREAMING`，具体 HTTP 状态和字段在接口阶段确定。输入接收可以同时返回“已进入梦境缓存、尚未学习”的回执；这不表示普通请求已恢复。

| 能力 | 专注梦境期间 |
| --- | --- |
| 原始消息／感知／自身实际输出和行动事件的接收 | 允许，进入该入口梦境缓存，不学习 |
| 第一类回复准备 | 拒绝，明确正在梦境中；不返回旧persona与缓存包 |
| 第二类普通记忆查询 | 拒绝 |
| 独立深度召回、来源读取 | 拒绝 |
| 实际使用反馈 | 拒绝，不暗中更新保留强度或排队执行 |
| 当前状态写入 | 拒绝，不借消息缓存绕过外部状态管理接口 |
| 目标注入、状态修改、截止修改 | 拒绝，不以积压消息形式偷偷执行管理操作 |
| 外部学习触发、配置写入等业务操作 | 拒绝；不启动新的普通学习 |
| Web运行状态与进度查看 | 允许，只读，不视为记忆召回或使用 |
| 梦境所需的内部认知整理与模型调用 | 允许，受梦境自身预算和监管约束 |

普通消息中可以描述外部发生过的行动、状态或目标，但积压消息日后学习不等于重放曾被拒绝的状态写入、目标注入或使用反馈命令。

与外部进行的主动业务交互、目标通知和意图投递在专注期暂停，不让普通调度器一边声明隔离一边继续向宿主发起交互。运行回执与明确的梦境状态拒绝不属于主动行为。梦境跨过提醒时刻后的补发或合并策略待时序契约决定；暂停本身不删除目标，也不自动延长截止。

### 16.4 每入口独立的梦境缓存

专注期到达的输入按原入口进入梦境专用序列，不进入正在用于认知整理的正常批次。每个群聊、直播间各自排队；不建立混合所有平台的一个全局消息总结队列。

梦境序列没有业务层条数上限，不因普通缓存容量滚动淘汰，不设填满后自动学习，也不调用 provider 补充媒体理解。外部已经给出的理解结果可作为输入原样保存；缺失的理解等待醒来后正常处理。

原文、引用、角色、入口、事件时间、接收时间和媒体关联完整保留。梦境暂存和已有普通批次持有的媒体都算业务引用，不能被无引用文件清理误删。

无条数上限不表示物理内存、磁盘或进程永远不会失败。建议使用可增长的隔离暂存介质，而不是把无限积压等同于无限驻留内存；本设计不擅自添加一个自动删旧输入的隐藏阈值。真实存储失败必须如实拒绝接收并显示故障，不能返回已接收后无记录丢弃。持久化、重启和资源告警策略仍需工程确定。

### 16.5 梦境结束后按入口回流

梦境结束后，每个入口分别将梦境序列中的消息按该入口的接收顺序弹出，送入正常输入／媒体处理和三段式队列。不得把全部梦境积压拼成一份超大总结，也不得把多个入口合成一个批次。

回流重新使用正常批次规则：构建 S3／S2／S1，明确只总结 S2；成功、普通失败或敏感拒学分别按第6节终结。普通失败丢弃目标但保留尾部，敏感拒学清空历史辅助段；回流不是对失败批次的业务重试。

在正常队列能够接收并确认取得该消息及媒体引用后，才从梦境序列解除其暂存所有权。这里是内部队列移交，不是额外建立外部投递重试服务。建议按消息标识防止切换中重复消费或先删后丢。

保留梦境前正常队列中尚未终结的输入，随后才是梦境期到达的输入。回流期间的新实时输入不得越过本入口尚未移交的旧积压；可暂时追加到同入口待回流队尾。不同入口可以分别回流、分别清空，不以最慢入口的积压作为其他入口推进的条件。

入口内顺序以接收序列为准，同时保留原始发生时间。回流时间不改变事件时间，不把昨晚的活动描述成刚刚发生。

### 16.6 清空的准确含义与业务恢复

“梦境缓存清空”指消息已移交到正常处理路径，不保证每条已经形成记忆。正常队列末尾仍可有 S1 辅助材料或未满的 S2，按正常学习事件继续处理；不因梦境序列已经清空就强制把最新段越界总结。

梦境与回流是两个可区分的运行阶段。建议在内部梦境结束并发布结果后恢复普通请求，回流同时推进；回复准备只能返回当时已发布信息与本入口正常队列，不能直接读取尚在梦境序列中的正文。这个恢复开放时点是具体实现建议，需在模式契约固定，不将其偷换为“所有入口积压清空才结束梦境”。

恢复服务后的其他入口待处理提示，计入正常待处理输入与尚未移交的梦境积压，仍只给数量和时间。已普通失败终结或敏感拒学终结的目标不再计为待处理，另以运行风险记录表示。

即使服务恢复，也不宣称已吸收全部梦境期消息。回流学习可以更新自我认知，但稳定 persona 仍等下一次梦境更新，不在每批回流时重新生成。

### 16.7 模式切换与可观测性

建议区分：正常运行、准备进入专注、专注梦境中、梦境结束后回流、故障。模式标识可由实现命名，但用户必须能看到梦境是否还在进行、各入口积压、回流进度、失败批次和上次成功摘要时间。

专注门控生效时要固定安全边界，避免普通学习结果在梦境同时修改认知。建议停止启动新的普通批次，让已经执行的批次先按既定终态收尾，再开始专注整理；期间新输入改投梦境序列。切换和异常终止的具体提交边界需要工程契约，不允许借切换清空未处理队列。

Web状态查看不解锁业务调用，不把查看行为计算为实际使用。是否提供管理员显式终止／恢复按钮及权限，需要管理操作契约；不在“Web可查看”中隐含任意写入权限。

### 16.8 来源支持、循环和恢复影响

来源遗忘后，依赖它的记忆在后续梦境暂时失去该份支持并降低保留强度。来源删除或修正时，重新评估评价；还有独立依据时不机械删除全部结论。

对象实际达到阈值恢复后，内部 agent 根据当前认知决定恢复哪些关联影响，不从审计读取旧正文，不把深度召回本身视为恢复。

相同根来源、角色自述和 persona 复述不能互相制造独立证据。影响遍历应防循环、去重，并区别同一缺失事件的重复扣减与后续时间衰减。共享完整来源仍遵守对象级遗忘／删除的边界。

### 16.9 非专注梦境与异常

未开启专注选项时，不默认启用“业务全面拒绝、输入转专用序列”的行为；仍执行认知整理与低频 persona 更新，外部请求与发布快照协调的具体方式属于实现契约，不承诺全局实时一致。

梦境中断或失败不能清空已接收的梦境缓存，也不能发布半份 persona。继续使用上次成功摘要、何时解除门控及怎样恢复回流，需要明确失败退出流程。故障可以使服务继续返回不可用，但必须在Web如实显示，不能卡住后一直假报正在正常整理。

## 17. 故障、提醒与审计

### 17.1 运作原则

输入信息可能价值密度较低，系统不以无损保留每条消息为目标。有限失败丢弃可以接受，但必须区分未送达、待学习、学习中、成功零结果、普通失败终结和敏感拒学终结，不将它们统一伪装成“已记住”。普通失败终结后按三段规则丢弃目标并留尾，不无限保护该失败批次；专注梦境无条数上限的暂存属于独立规则，不能借普通容量限制淘汰它。

不管理业务重试，不意味着没有错误返回、风险标记、运行日志或状态展示。它也不意味着允许重复请求造成重复强化等不受控副作用。

### 17.2 provider 长期故障

provider 长期不可用、反复失败导致学习无法正常进行时，向外部提醒记忆系统出现故障，需要修复，并在面板显示。

哪些条件构成长期故障、报警频率和解除条件需配置。没有可靠发送通道时，提醒本身也可能无法送达，不能承诺绝对通知成功；本系统不可用时尤其不能保证自己向外部报警。

非专注模式下，仍可读取的已存记忆与学习能力故障应区分；专注梦境门控优先，即使数据库可读也仍拒绝外部召回。不能因为 provider 不可用就把所有失败称为敏感拒学，也不能把既有记忆说成丢失。

### 17.3 传输与业务状态

发送连接的底层负责有限重试，超过次数后丢弃该次无法交付的信息。业务层不新增永久重发、死信恢复或自动重放服务。

底层重复投递仍可能发生，因此建议接收操作识别重复事件或反馈标识；这种重复副作用防护不属于业务重试管理。

提醒送达不等于目标完成；提醒丢失不删除目标；使用反馈丢失可能导致本次没有强化记忆，系统不凭空补记“已使用”。外部完成反馈丢失时，系统也不能推断目标完成。

### 17.4 突然失忆风险

突然失忆风险只标识明确敏感拒学导致的本轮独占未提交内容清理，说明可能存在经历缺口。它不同于正常遗忘、普通链路失败以及普通学习失败终结。普通失败保留历史尾部；敏感拒学不保留尾部，下一轮历史辅助为空。

建议在有关入口的回复准备和管理面板展示受影响时间范围等运行元信息，外部决定是否对用户表达。风险记录不复制已清除正文。

### 17.5 审计隔离

日志记录记忆修改、删除、分数变化、学习故障和管理操作等，供开发者审计。历史正文只存在于这类日志中时，agent 不能通过记忆查询、深度召回、来源遍历、媒体目录或通用文件工具读取它。

日志不可因导出、通用检索或自动导入被无意回灌给记忆 agent。仅审计引用不纳入媒体业务引用统计，清理后审计中的文件链接可能不可用。

### 17.6 缺口、积压与恢复信息分别显示

已终结失败的输入不再占用待处理计数，但失败的事实及受影响时间范围仍可在运行状态中查看。正在梦境序列中的输入只是延期处理，不应被计为学习失败；已移交正常队列也不等于已经形成记忆。

专注梦境期间正常业务告警投递也受交互隔离限制，Web保留故障可见性。系统自身完全不可用或存储损坏时，不能保证还能自己发出提醒；实际故障监控与恢复策略由运维设计提供，不伪装为缓存语义已经保证可靠交付。

## 18. 逻辑架构

以下划分用于控制职责，可以在一个独立服务中实现，不要求微服务、多仓库或多个自治 agent。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 接入与薄兼容层 | 输入封装、入口映射、请求及反馈类型 | 决定角色全部认知 |
| 入口队列与批次管理 | 各入口S1/S2/S3、冻结快照、三种终结、尾部轮转和引用 | 跨入口混批、整队列误删、失败批次重放 |
| 梦境暂存与回流 | 各入口无条数上限暂存、按序移交、积压计数 | 梦境期学习积压、混成一次全量总结 |
| 媒体管理 | 理解复用与补充、拒绝占位、隔离文件和引用 | 即时清理所有敏感批次附件 |
| 学习调度 | 默认事件、关注信号、主动学习和运行状态 | 借触发器无限重放失败请求 |
| 认知 agent | 理解、分类、评分、修正、自我和目标形成 | 改写外部当前状态和监督prompt |
| 记忆与来源 | 当前对象、完整窗口、来源关系与生命周期 | 从开发者日志恢复删除对象 |
| 自我与 persona | 开放自我认知、梦境中生成统一摘要 | 每次回复重写人格 |
| 召回与反馈 | 回复准备、普通查询、深度召回、使用强化 | 跨入口缓存外泄、读取即恢复 |
| 当前状态服务 | 外部状态保存、持续时间和新鲜度计算 | 将目标当作正在执行的事实 |
| 目标与提醒 | 多目标、注入后去重、状态与时间提醒 | 执行工作流或监控执行效果 |
| 梦境与维护 | 来源修复、影响评估、低频persona发布、专注门控 | 清空共享内容、改写外部当前状态 |
| Web与审计 | 初始化、参数、各入口三段与梦境进度、开发者审查 | 向agent开放审计历史、专注期通过只读页面绕过业务拒绝 |
| 底层连接适配 | 有限传输重试和失败返回 | 对业务成功作无限保障 |

### 18.1 主信息流

```text
外部原始输入
    ├─ 正常接收 → 本入口媒体处理 → S1 → S2
    │                                      ├─ 三段快照[S3|S2|S1]，只总结S2
    │                                      └─ 终结：成功／普通失败留尾／敏感拒学不留尾
    │                                                     ↓
    │                                             记忆、来源、自我、关系
    └─ 专注梦境 → 本入口梦境暂存序列（不学习，无条数上限）
                       └─ 梦境结束 → 按序移交上述正常路径

初始自我＋已有认知＋外部监管prompt → 梦境整理 → 统一稳定persona
外部当前状态管理 → 当前状态与持续时间（专注期拒绝写入）
内部生成／外部注入 → 多目标与提醒（专注期拒绝外部管理）

正常回复准备 → persona＋有效相关记忆＋本入口近期输入＋状态＋目标＋跨入口数量/时间提示
正常定向查询 → 有效记忆；显式深度召回可含遗忘对象
实际使用反馈 → 保留强度增强 → 达恢复阈值才恢复
专注期业务请求 → 明确“正在梦境中”，不排队代执行
Web只读状态 → 始终保留专注期观察通路，受实际服务可用性限制
```

## 19. 概念接口与不可混淆的状态

接口名称是建议的能力名称，不固定 HTTP 路径、SDK 和消息协议。

| 能力 | 语义 |
| --- | --- |
| 输入接收 | 接收原始消息与行为事件；专注期只投本入口梦境序列，回执区分暂存与学习 |
| 回复准备 | 提供分区认知信息、本入口缓存及其他入口数量/时间提示 |
| 普通记忆查询 | 按方面查询有效正式记忆，不查缓存 |
| 独立深度召回 | 外部显式检索可包含遗忘对象的记忆，不读取即恢复 |
| 记忆使用反馈 | 反馈实际使用的返回对象，强化保留强度并检查恢复阈值 |
| 当前状态管理 | 外部设置、更新或结束当前活动及情绪信息 |
| 目标注入 | 先建立外部目标，再运行一次相似去重 |
| 目标状态与截止管理 | 外部完成、放弃或修改截止等；不反馈执行监控流 |
| 学习事件管理 | 配置默认/关注事件，允许内部提出学习触发 |
| 认知与生命周期操作 | 内部纠正、评分、删除和影响处理，遵守对象状态规则 |
| 梦境配置与状态 | 正常期设置周期、监管prompt与专注选项；专注期Web只读状态仍可用 |
| 模式门控 | 专注期拒绝除原始输入外的业务请求，明确DREAMING，不伪造成功 |
| 入口三段／回流状态 | 管理面板查看快照目标、辅助范围、失败终态、梦境积压和移交进度 |
| 来源窗口设置 | 按平台配置S3/S1条数，实际来源限定于本入口冻结批次；专注期不开放配置写入 |
| 媒体理解与清理状态 | 查看复用、缺失、拒绝和业务引用情况 |
| 提醒与意图交付 | 提供高维意图、目标时间提示和故障提醒 |
| 初始化自我及监督设置 | 外部配置初始自我、persona方向和变化监督 |
| 审计读取 | 仅对开发者权限开放 |

必须区分以下状态语义：输入已接收不等于已学习；进入梦境暂存不等于进入正常批次；移交完成不等于学习完成；批次终结不等于学习成功；成功学习不等于生成了记忆；留作历史辅助不等于待重新总结；被召回不等于实际使用；使用过不等于内容可信；读取遗忘内容不等于恢复；提醒发出不等于送达；送达不等于目标完成。

具体鉴权、分页、请求预算、幂等标识、错误码和版本检查在接口阶段固定。跨入口并发与实时一致性暂缓，不允许单轮失败误删其他批次、一次反馈重复无限计分或已删除 ID 正常返回。

业务门控应位于各具体能力之前统一执行，避免普通查询被拒绝而深度召回、使用反馈、来源读取或目标操作仍可绕过。Web只读运行状态属于管理观察通路，不复用一个能任意触发agent执行的查询接口。

<a id="section-20"></a>

## 20. Web 管理面板

### 20.1 初始化引导

首次启用引导至少包含：唯一角色、初始自我材料、persona生成目标与监管prompt、平台接入和各平台三段参数、默认学习事件、梦境周期及专注选项。界面说明三段按时间排列为S3→S2→S1，标明“只总结S2”，用两轮消息示例展示中段尾部如何成为下一轮历史辅助。

支持有预设身份和无预设身份，不另建两套系统。默认persona目标为稳定发言风格与充分认识自我，界面说明其属于外部过程监督，而不是一条普通角色观点。

### 20.2 图形解释

界面需要图形解释自我认知、稳定persona、当前状态和目标的区别，不能仅提供多个无解释的文本框。图形应表达如下关系：

```text
初始材料＋持续经历 → 丰富且可变化的自我认知
                                  ↓
外部生成目标＋监管prompt ───→ 梦境中的提炼与检查 → 稳定persona

外部当前活动／游戏细节／情绪 → 当前状态与持续时间 ──┐
多个未来目标／待办           → 目标集合与提醒 ─────┼→ 外部组织context与具体执行
稳定persona＋相关记忆＋本入口近期输入 ────────────┘
```

“我偏好温和表达”可影响稳定persona；“我现在紧张”属于当前状态；“明天提醒朋友一件事”属于未来目标。三者相互相关，但具有不同管理者和更新节奏。

### 20.3 日常页面

| 页面 | 主要内容 |
| --- | --- |
| 入口与学习 | 每个群／直播间的S1/S2/S3、目标ID、实际窗口、成功／失败／拒学终态和历史尾部 |
| 梦境积压与回流 | 每入口暂存数量、最早／最新接收时间、已移交量、正常队列余量与回流错误 |
| 记忆与来源 | 当前正文、类别、双指标、真实依据及完整上下文 |
| 遗忘与深度使用 | 遗忘对象、强度、阈值、实际使用反馈与恢复状态 |
| 自我与persona | 自我认知、当前摘要、生成时间、监督配置和待复核关系 |
| 当前状态 | 外部管理的活动、细节、情绪、持续时间和最后更新时间 |
| 目标 | 多个未结束目标、截止与提前量、来源、去重、完成和放弃 |
| 梦境 | 周期、专注选项、访问拒绝状态、内部整理进度、回流阶段、上次成功及整理结果 |
| 媒体 | 理解状态、业务引用、无引用清理和清理记录 |
| 开发者审计 | 历史版本与操作；独立权限，不向agent暴露 |

面板管理功能与agent工具权限分开。人工恢复、删除、查看来源等操作是否开放及其确认交互需单独定义；不能因为开发者能看日志，就给agent同样读取能力，也不能把开发者浏览误当成宿主实际使用记忆。

### 20.4 关键配置展示

面板应解释双阈值而不是只给一个“遗忘百分比”；显示相信程度量表；区分普通队列软上限、处理中批次保护及梦境暂存无条数上限；三段长度按平台分别编辑并显示每个入口实际范围；每个目标保存自己的提醒提前量；当前状态和persona分区展示。

专注梦境启用前应明确说明：除原始输入外业务请求全拒绝；输入独立积压且不学习；Web仍可查看状态；梦境结束后按入口正常批次回流。说明状态管理和使用反馈不会排队代执行、提醒在专注期暂停，以及无条数上限不保证物理资源无限。异常退出、错过提醒和回流开放时点的具体配置应清楚显示，不以笼统开关掩盖。

## 21. 验收场景

这些场景定义实现后的预期行为，不代表系统已经实现或测试通过。标注“待细化”的项目必须在对应策略确定后固定完整预期。

| 编号 | 场景 | 预期行为 |
| --- | --- | --- |
| A01 | 一个角色连接群聊、直播和游戏 | 使用同一自我与稳定persona，保留各平台和入口身份 |
| A02 | 群消息含引用和多媒体 | 原始正文、来源、主体、引用、媒体及理解信息完整保留 |
| A03 | 自身只产生了行动意图 | 不记成已经执行；实际输出与结果可另行回流 |
| A04 | 外部提供某媒体理解 | 复用该结果，不重复理解 |
| A05 | 同条消息另一媒体未提供理解 | 针对缺失对象补充，不假定整条消息媒体全已处理 |
| A06 | 媒体理解发生敏感拒绝 | 对应内容为“敏感信息无法访问”，不清空整轮缓存 |
| A07 | 正在处理的批次超过普通队列软上限 | 终结前不按普通容量淘汰；终结后按成功／失败／拒学分别轮转 |
| A08 | 成功学习生成零条记忆 | 标记成功空结果，按普通轮转保留中段尾部，无特殊归档 |
| A09 | provider普通超时或限流 | 按底层有限重试与故障处理，不冒充敏感拒学 |
| A10 | 整轮明确敏感拒学 | 清理本轮独占未提交内容，不留中段尾部；新S3为空，标记突然失忆风险 |
| A11 | 被拒批次使用其他轮共享内容 | 不删除其他轮次或已提交对象持有的内容 |
| A12 | 本轮启动后有新输入到达 | 新输入不被本轮拒学误删 |
| A13 | 敏感拒学内容曾引用媒体 | 释放本轮相关引用，媒体等待统一定时清理 |
| A14 | 普通记忆查询询问未学习消息 | 不把缓存作为正式记忆返回 |
| A15 | 正常服务时入口A请求回复准备 | 提供A正常队列近期输入、persona、有效相关记忆、外部状态和目标 |
| A16 | 其他入口有待处理消息 | 只提示入口数量和时间，不提供正文、摘要或主题 |
| A17 | 宿主试图直接读取入口B的缓存 | 不通过回复准备、普通查询或深度召回提供 |
| A18 | 入口B已有相关正式记忆 | 可跨入口召回，保留来源；遗忘时需深度能力 |
| A19 | 平台断线且系统未收到新输入 | 不将无已接收待处理消息说成该平台没有新消息 |
| A20 | 不同平台配置不同三段参数 | 分别应用本平台配置，在各自入口固定S3/S2/S1快照 |
| A21 | 来源窗口含不相关发言 | 保留完整语境，但不把所有片段都当作支持证据 |
| A22 | 首轮没有S3或已冻结快照辅助数量不足 | 使用实际批次范围，不向未来或其他入口补齐，记录空段／实际条数 |
| A23 | 缓存已淘汰但正式记忆仍存在 | 来源快照仍能审查，不只剩无效队列位置 |
| A24 | 多条记忆派生一条新认知 | 记录真实来源记忆ID，可追溯共同根输入 |
| A25 | 同一原始消息被重复总结 | 不把内部重复当作多份独立证据 |
| A26 | 小林与林同学可能是同一人 | 保留独立主体与带评分联系，允许纠正和询问 |
| A27 | 小林扮演某游戏角色 | 返回时明确扮演关系，不混同现实经历 |
| A28 | 相信程度为50 | 表示未定，不表示命题客观概率50% |
| A29 | 外部实际使用某条记忆 | 增强保留强度，不自动提高相信程度 |
| A30 | 同一使用反馈重复送达 | 不将同一次使用重复强化；按接口去重规则处理 |
| A31 | 有效对象R低于F | 标记遗忘，普通查询与回复准备不返回该对象 |
| A32 | 深度召回返回遗忘记忆全文 | 仍遗忘，不因读取自动强化或恢复 |
| A33 | 遗忘对象被实际使用，强化后R仍低于H | 继续遗忘，不机械恢复关联 |
| A34 | 有效反馈使遗忘对象R达到H | 恢复有效，内部agent判断关联影响 |
| A35 | 已恢复对象R从H降至F与H之间 | 保持有效，不立即再次遗忘 |
| A36 | 遗忘对象R升至F与H之间 | 仍遗忘，直到达到H；与A35共同验证滞回 |
| A37 | 相同内容仍在另一记忆的来源窗口 | 不因对象遗忘或删除立即遮蔽共享窗口 |
| A38 | 支持来源遗忘 | 后续梦境处理依赖、降低受影响保留强度，不直接判为假 |
| A39 | 删除一项经历 | 原ID不可召回，其他评价和persona由梦境整理修复 |
| A40 | 删除后其他来源仍包含同样信息 | 不保证内容永不再学到；不复活原ID或从审计回灌 |
| A41 | 深度请求查询已删除对象 | 不可返回，不查询审计补齐 |
| A42 | 使用反馈指向已删除对象 | 不复活、不重新创建原对象 |
| A43 | 遗忘持续超过保留期限 | 按配置删除；单纯深度读取不当作状态恢复 |
| A44 | 外部更新当前游戏状态或情绪 | 更新状态包，第一类请求主动提供，长期persona不即时改变 |
| A45 | 相同活动收到心跳更新 | 不将持续时间起点重置为最近一次更新时间 |
| A46 | 外部未提供实际开始时间 | 时间标识为自报告起或未知，不编造真实起点 |
| A47 | 内部agent猜测当前活动已结束 | 不覆盖外部管理的当前状态 |
| A48 | 普通学习形成新的自我认识 | 可更新自我认知，稳定persona等梦境再生成 |
| A49 | 梦境生成persona | 使用外部目标和监管prompt控制变化，保持统一摘要 |
| A50 | persona依赖内容被删除 | 标识可能待复核，后续梦境修复，不按请求即时重写 |
| A51 | 没有预设身份初始化 | 可以启动统一角色并随经历形成自我 |
| A52 | 同时存在多个未来目标 | 并行保存，待办同样作为目标，不限制只有一个目标 |
| A53 | 外部注入目标 | 先加入，再做一次相似去重；结果能对应注入对象 |
| A54 | 相似目标针对不同对象或时间 | 不仅凭相似文本无条件合并，冲突合并规则待细化 |
| A55 | 两个目标各设不同提醒提前量 | 按各自创建时设定安排，不套用一个隐含固定值 |
| A56 | 目标到期但无完成反馈 | 提醒放弃或修改截止继续，不自动完成、失败或放弃 |
| A57 | 外部明确完成或放弃目标 | 结束相应跟踪及尚未发送的提醒 |
| A58 | 外部修改过期目标截止时间 | 保留目标，按新时间继续管理与提醒 |
| A59 | 提醒底层重试耗尽 | 可丢弃通知，不启动业务无限重发，不删除目标 |
| A60 | provider长期故障 | 提醒外部需要修复，面板展示能力故障，不伪装学习成功 |
| A61 | 输入始终未成功送达 | 底层耗尽重试后可丢弃，系统不伪造已接收记录 |
| A62 | 已接收批次学习普通失败且底层重试耗尽 | 标记失败终结，按完成批次规则移除目标并保留尾部，不发起业务重试 |
| A63 | 遗忘对象仍引用媒体 | 业务引用有效，不作为孤立文件删除 |
| A64 | 媒体只剩开发者审计引用 | 按无业务引用处理，可由定时任务清理 |
| A65 | 媒体仍有其他缓存或记忆引用 | 不因某一对象删除而误删共享文件 |
| A66 | agent尝试读取日志或历史正文 | 无访问能力，不能经通用工具绕过 |
| A67 | 处于专注梦境 | 业务请求除输入外全拒绝，明确正在梦境；输入转独立无条数上限序列，Web可查看 |
| A68 | 初始化用户不理解自我与persona | 图形清楚区分丰富自我、梦境提炼、稳定摘要、当前状态与未来目标 |
| A69 | 同平台两个群聊分别收到消息 | 维护各自S1/S2/S3、批次和历史尾部，不混为一个队列 |
| A70 | 入口A的S2满，入口B不足批次 | A独立触发；不要求B补齐，不消费B消息 |
| A71 | 一个批次输入为S3／S2／S1 | 提示与结构明确只有S2是总结目标，两侧仅理解辅助 |
| A72 | S1有与S2无关的重要新信息 | 不在本轮单独提取；仍等待S1后来成为目标 |
| A73 | S3重复出现上一轮已处理信息 | 不重新送入目标，不增加独立证据数量 |
| A74 | 成功后中段尾部需要留给下轮 | 从本轮S2快照取尾部生成新S3，旧S3解除运行引用 |
| A75 | 普通失败后生成下一轮S3 | 从失败S2取最新尾部，保留失败来源标记，不标为已成功记住 |
| A76 | 敏感拒学时旧S3仍有内容 | 新S3为空；不能回退继续使用旧历史辅助槽位 |
| A77 | 学习期间新输入已溢出至运行中的S2 | 只移除快照目标ID，不误删新到消息，不把新消息取作本轮尾部 |
| A78 | 普通失败终结但存在未提交候选 | 不发布失败轮候选，释放本轮独占暂存引用 |
| A79 | 敏感拒学批次引用最新S1 | S1仍属后续输入，不因被用于上下文就清空整个入口 |
| A80 | 成功／失败目标释放后统计积压 | 目标退出待处理；S1及新输入仍计入；S3只作辅助不重复计待学 |
| A81 | 普通失败尾部影响下一轮理解 | 允许辅助解释新S2，不重新分析整批失败目标 |
| A82 | 某批次终结通知被重复执行 | 不再次删除尾部或释放共享引用；按终结标识去重 |
| A83 | 来源已保存而运行时三段发生轮转 | 来源保留冻结的完整上下文，不随队列移动改变 |
| A84 | 同一S1消息后来进入新批次S2 | 可以正常成为目标，沿用原消息ID，不因曾作为上下文就跳过 |
| A85 | 专注期发起第一类回复准备 | 返回明确梦境拒绝，不返回空记忆或旧persona包冒充成功 |
| A86 | 专注期发起普通查询或深度召回 | 全部拒绝，深度入口不能绕过门控 |
| A87 | 专注期提交使用反馈 | 拒绝，不增强强度，不放进梦境消息序列日后代执行 |
| A88 | 专注期更新状态或注入／关闭目标 | 拒绝，不通过普通输入包装绕过管理权限 |
| A89 | 专注期接收原始聊天和自身实际发言 | 保留完整原始信息到各自梦境序列，回执仅确认暂存 |
| A90 | 专注期某入口输入超过普通缓存上限 | 继续暂存，不按普通条数淘汰，不触发正常学习 |
| A91 | 专注期输入包含尚未理解媒体 | 暂存原件和索引，不调用媒体模型；回流后再按正常优先级处理 |
| A92 | 专注期媒体仅被梦境序列引用 | 属于业务引用，定时清理不可删掉 |
| A93 | 开发者在专注梦境打开Web状态 | 可见模式、入口积压和进度，不解锁召回或触发使用强化 |
| A94 | 梦境本身需要内部provider调用 | 允许用于内部整理；禁止的是积压输入触发的普通处理 |
| A95 | 梦境结束，两个入口都有积压 | 分别按各自顺序回流正常三段式，不合并成全局大总结 |
| A96 | 梦境前正常队列还有未终结输入 | 先保留并处理原顺序，再接收该入口梦境积压，不覆盖原队列 |
| A97 | 回流期间又有同入口新消息 | 新输入不能越过尚未移交的旧消息，保持入口内接收顺序 |
| A98 | 入口A回流清空，入口B仍积压 | A不必等B推进；未清空计数继续只归B |
| A99 | 梦境消息已移交而正常S1仍有消息 | 梦境序列可为空；不宣称全部已记住，不强制越界总结S1 |
| A100 | 回流学习普通失败 | 按普通失败终结留尾并继续后续批次，不把失败消息重新入梦境队列 |
| A101 | 回流学习敏感拒学 | 清理本轮独占未提交内容，新S3为空，不清空本入口其他积压 |
| A102 | 梦境后回流旧消息 | 原发生和接收时间不变，另记移交时间，不伪装成实时新事件 |
| A103 | 梦境序列转交媒体引用 | 正常队列取得引用后释放暂存引用，避免中间误删 |
| A104 | 服务恢复但其他入口仍有梦境积压 | 待处理提示只给数量和时间，不提供积压正文、摘要或主题 |
| A105 | 梦境后未收到外部状态更新 | 仍是最后报告状态，展示时间；不以缓存历史学习自动刷新当前值 |
| A106 | 梦境失败或被中止 | 不得清空已接收暂存或发布半份persona；退出策略按明确工程契约 |
| A107 | 物理介质耗尽无法继续暂存 | 如实报告接收失败和运行故障，不偷设条数淘汰或假报已接收 |
| A108 | 梦境回流更新了长期自我认知 | 可以保存新认知，稳定persona仍等下一次梦境生成 |

## 22. 待细化的参数与异常契约

三段式只总结中段、失败终结与留尾差异、专注梦境业务拒绝和每入口独立无条数上限暂存，均为系统行为。以下事项是实现需要固定的剩余参数和异常细节，不授权重新决定上述规则。

### P04. 目标去重和提醒时序

确定相似目标保留哪个对象、截止冲突与字段合并、旧 ID 映射及提醒接收宿主。创建时已过期、修改截止到过去、过期重复提示等需固定策略，不默认全平台广播或无限补发。

专注期暂停主动业务投递。梦境跨过多个提醒时刻后，是合并为一次过期提示、仅在外部请求中显示，还是按明确策略发送，需要在通知契约中指定；不得擅自顺延目标截止。

### P05. 当前状态的时间契约

确定活动标识、开始与结束、子状态时间、缺失时间标记，以及多久未更新仅标陈旧。当前值完全归外部管理，梦境不修改。

专注期被拒绝的状态更新不自动重放。可由外部在恢复服务后明确发送一次最新状态；这是调用方行为建议，不是记忆系统自动补发或从历史消息重建当前值的保证。

### P06. 多媒体结果的有效性

每媒体对象已提供完整理解则复用、缺失则正常阶段补充、明确敏感拒绝使用固定占位。需确定空文本、一般失败和部分结果的结构化状态。专注期不做媒体理解，回流后按正常规则处理。

一般媒体失败是否允许在新的明确事件中重新理解，与不管理业务重试保持一致。敏感占位不能被当作缺失而自动回退绕过。

### P07. 使用反馈、来源访问与persona发布细节

固定反馈有效期、修订匹配、重复计分防护，以及临近删除时迟到反馈的处理。深度读取不恢复、实际使用提高强度并达到阈值才恢复、删除对象不复活均不变。

需要独立定义对外完整来源审查权限，避免跨入口来源附带尚未总结的辅助原文。persona 候选未通过监管检查时不发布；具体检查、故障标识和上次成功摘要展示格式需固化。

### P08. 短批次、最新辅助段和提前触发

冻结批次不等待批次之外的未来消息，来源范围也不再扩大。仍需固定正常目标长度、token上限、主动触发遇到未满S2时的切分，以及长期安静入口的末尾S1是否通过明确的空闲／手动事件转入目标。

建议把未满批次和尾部刷新定义成可配置的正常学习事件，并在建立批次前确定目标和可为空的辅助段；不能冻结后再把S1偷偷改为本轮目标。无目标时不调用总结模型。

### P09. 模式切换、回流开放时点与异常退出

专注期间业务拒绝范围已经固定。实现仍需明确：进入前已有在途请求和学习如何安全收尾，梦境提交后是否立即开放业务服务，回流期间新输入接尾的操作次序，以及梦境崩溃／中止后如何解除门控和恢复回流。

建议梦境内部整理结束后即可恢复业务，入口回流继续独立推进；使用模式与积压元信息说明新鲜度。这是待固化的阶段切换策略，不隐含必须等待所有入口积压清空，也不隐含异常时可丢掉梦境缓存。

Web只读状态持续开放；管理员强制终止、恢复或配置写入需要独立权限与确认契约，不能仅因“Web可打开”默认获得。

### P10. 暂存介质、重启与物理资源故障

梦境序列没有业务条数上限。需要选定可增长的暂存介质、崩溃恢复范围、磁盘和内存告警，以及真实资源不足时如何如实返回接收失败。不得用普通队列容量代替梦境序列上限，也不承诺不存在硬件极限。

普通调用重试耗尽后的批次已明确失败终结并留尾，不作为悬而未决的长期积压。剩余持久化与提交问题包括：结果提交与批次消费如何对齐，重启后是否重做终结，以及如何避免来源和媒体引用错删。具体技术选型不能改变单次终结和所有权规则。

## 24. 实施与验收组织

先将已明确的行为写成可验证契约，再落到schema、接口和代码。三段的目标与辅助角色、三类终态、专注业务门控、每入口梦境序列和FIFO回流，应在接入真实模型之前用固定消息标识验证。本文的验收场景描述期望行为，不表示已经实现或测试了实际记忆系统。

建议按以下闭环实施，每一阶段同时覆盖正常、边界与失败路径：

| 阶段 | 可验收闭环 |
| --- | --- |
| 输入与三段队列 | 单角色、多入口、S1/S2/S3、批次快照、只总结中段、成功与零结果轮转 |
| 失败与来源 | 普通失败留尾、敏感拒学不留尾、批次独占清理、完整来源、媒体引用 |
| 正式记忆与召回 | 分类、双指标、主体联系、两类请求、入口缓存隔离与数量/时间提示 |
| 生命周期与反馈 | 深度召回、真实使用反馈、双阈值恢复、对象删除与审计隔离 |
| 专注梦境与回流 | 业务全拒绝、输入独立暂存、无条数上限、Web可见、按序正常批次回流 |
| 自我与低频persona | 初始自我、监管prompt、来源影响修复、梦境发布及失败不发布半份摘要 |
| 现在与未来 | 外部当前状态、持续时间、多目标、注入去重、期限与提醒 |
| 运行与管理 | Web图形引导、各入口计数、模式切换、物理故障可见和媒体清理 |

不可用简化实现改变产品含义：不把辅助段当目标、不把失败当成功、不把梦境回流当失败重试、不把其他入口消息混批、不把无条数上限改成按普通容量淘汰、不把Web状态查看扩大成专注业务放行。

未来所有技术选择都应接受同一套行为检验。没有确定的参数显式保留为配置，不以随手选择的常量替代产品决定。

系统的运行闭环是：真实来源输入进入各入口队列，按三段批次形成可追溯认知；外部通过回复准备与定向查询取得适用信息，实际使用反馈调节保留强度；当前状态由外部管理，多个未来目标由系统保存与提醒；梦境修复认知并形成稳定自我摘要，专注时只积压原始输入，结束后依入口顺序回到正常学习。角色如何认识世界和自身由本系统管理，如何表达与具体行动由外部宿主决定。
