## 1. 一次交付与已批准决定

目标是让新用户可用一个Docker服务完成安装、管理员建立、实例初始化、宿主接入、日常观察与受控管理，并能备份、恢复及安装兼容版本。复用同一日常／梦境宿主及既有领域模块，不再创建第二套记忆或认知系统。Web、配置、权限、目录、持久启动身份和恢复作为一个完整能力验收。

| 已批准决定 | 行为与限制 |
| --- | --- |
| 身份与网络 | 一个本地管理员，外部宿主使用独立、可撤销且限定入口和操作的令牌；默认只发布宿主回环地址，容器间使用显式私有网络，不依赖外部账号服务 |
| 管理写操作 | 人工恢复遗忘对象、删除正式对象及已有状态／目标管理可用；核验当前revision、明确确认、原子事务及审计。禁止历史正文回灌、强制解除UNKNOWN或强行解锁 |
| 实例、备份与升级 | 新建正式实例，历次试验库保持只读且不自动迁移；提供一致备份／恢复、配置激活／回退和兼容版本升级，不能通过恢复旧备份丢弃切换后的新数据 |
| 生产存储 | 单个应用进程、SQLite、本地持久卷；容器内`/data`放数据库、媒体、索引、日志和备份，凭据只读挂载到`/run/secrets`；目录信息仅管理员可见，实际核验权限、别名和占用。不使用网络文件系统，不宣称硬件掉电已验证 |

本次不恢复[已暂缓的质量与音视频验证](../work/DEFERRED_ISSUES.md)，不增加外部行动执行、可选rerank、试验库通用迁移、远程对象存储、集群／多worker或完整大档资格。这些能力明确显示支持状态，不能因交付首期产品而隐含宣称已经完成。

## 2. 装配与启动身份

复用[日常宿主](daily-cognition-and-image-learning.md)、[梦境与维护](dream-and-long-term-maintenance.md)、[持久接入](durable-ingress-and-batch-runtime.md)、[正式记忆与来源](formal-memory-source-media.md)、[信息反馈](local-information-feedback.md)和[语义检索](async-embedding-semantic-retrieval.md)。Web调用有类型公开端口，不直接写领域表，不访问私有字典代替健康／观察接口。

使用显式的新托管装配格式，运行前固定全部Schema、命令、结果、实际writer及非空必要审计。具体表／索引／命令／配置键数由完整声明实物生成，不把未编码估算当作产品闭集；不运行中补表、追加SQL或按异常猜测旧格式。旧装配、原键及旧数据库继续按其原格式使用，不放宽旧精确类型检查。

管理与身份记录保存主体、会话／令牌验证摘要、权限及撤销revision；configuration保存不可变配置版本和激活事实；runtime保存可信建库身份、启动／停机及切换进度；备份由独立受控工程所有者保存清单和完成状态。各owner负责实际数据，统一存储协调短事务。模型无任何管理写能力。

首次创建数据库之前，持久保留预期database_id、instance_id、资源绑定、装配摘要及初始配置来源；受限文件采用原子发布和必要同步，不从目标库反推期望身份。创建、配置保存、各业务根、首次persona及准备完成分别有可恢复状态和原键。异常中断后只按原身份续办，不能重复新建角色或把半初始化暴露为READY。

引导服务与业务READY分开：新托管格式允许用统一配置模块声明并完整验证的有界部署启动参数，建立同一权威库的固定声明和管理仓储，先提供受保护的登录／向导。完整业务配置尚未通过时只保存管理所有的向导草稿，不产生业务有效快照，不开放接收、召回或模型调度；不能塞入模拟profile、秘密占位或空字段冒充完整配置。初始业务配置来源可先绑定唯一向导身份，通过整份验证后再固定内容摘要及不可变版本，按原键初始化各业务根。数据库／资源身份等启动固定项必须一致，不能从表单反向改成另一个库。该启动子态只属于新托管格式，不放宽旧装配的完整初始化要求。

正式新实例的首次persona继续使用已批准的生成、人工审核和原子发布端口；引导允许停在待审核状态。此前限定于合成试验的原文导入例外不扩展为任意生产自由文本导入。测试中的模拟审核行为须标为测试参与者，不伪造用户批准或供应商记录。

### 2.1 公开端口与原子事实

下表约束能力、所有者和边界，不限定类名或路由拼写。执行者可在本阶段选择语义化名称、必要工程库及有界数值，完成统一注册表和封闭类型；无需为每张表、每个普通技术参数另行审批。新增托管格式的错误码／reason集合可明确扩展，既有格式的闭集、回执和摘要不可回写。声明固定后，对外拒绝额外字段及未知状态。

## 3. 本地管理员与宿主权限

首次管理员建立由本机部署者持有的一次性引导凭据授权；不是访问空服务的第一个匿名请求自动成为管理员。引导凭据和管理员口令不进入镜像、命令行参数、URL、日志或仓库。口令仅保存经合适口令派生算法处理的验证材料，失败登录限速；会话随机、有限期、可退出与撤销。

浏览器使用受保护的同源会话；写请求必须防跨站伪造，严格Origin／Host边界，不开放任意CORS。默认HTTP仅在批准的回环／私有边界使用，不外推公网认证或TLS部署资格。敏感配置、完整来源及目录只向相应管理员能力提供；审计另核验独立开发者审计能力，不因持有普通管理会话而开放；普通页面错误、数量和游标也不能泄漏这些内容。

宿主令牌由管理员创建，明示host、入口集合、操作集合和有效期；原始令牌仅创建时向管理员展示，持久保存验证摘要，支持吊销。每次请求从当前有效权限派发，撤销与在途业务的末端权限核验有明确边界；不相信请求正文自报的principal、role或scope。不能从查询令牌获得管理、审计或模型工具权限。

撤销与业务提交竞争采用权威末端检查：撤销已确认后，尚未越过提交权限检查的新写拒绝；此前已提交事实不撤销，内部原确认及清理责任继续。查询也须重新确认当前权限后投影；被吊销令牌不能继续读取原结果，可由仍获授权的管理／宿主身份原键确认。

认证建立会话不等于开通模型调度。进程启动先恢复本地状态；管理员显式启用后才能发起新的模型工作，旧已发送／UNKNOWN不因此重发。令牌轮换与凭据变更不修改历史请求身份、旧usage或原确认路径。`/run/secrets`保持只读：供应商秘密由部署方替换受保护挂载，Web管理受控引用、版本和验证／激活，不获得任意文件读写能力，也不向浏览器回显已存密钥。

### 3.1 外部宿主、入口与通知路由（已批准）

管理Web通过ingress新增的受控注册端口登记宿主／入口关联；复用初始化向导的既有绑定。先覆盖既有平台及合法入口，不自动增加平台Schema、当前状态多宿主写权或跨入口读取范围。签发令牌时即核验host／entry已登记、所选路由属于该宿主，无绑定时在签发阶段拒绝。稳定ID建成后不原地改变所属宿主；需转交时新建路由并显式修改尚未发送目标的期限／路由，保留原发送事实。

逻辑路由至少包含稳定标识、所属宿主、入口范围、允许事件、enabled、revision及审计事实。连接在线状态不写成路由存在性。没有在线消费者或路由被禁用时仍可创建合法有deadline目标，明确提示当前不可送达；未知／越权路由始终拒绝。默认路由仅在宿主与入口恰有一个合法候选时由受控端口解析，并把最终route保存在目标中，不在每次发送时重新猜默认值。

路由实体、权限及撤销由management唯一维护；宿主与入口绑定由ingress受控端口维护。写入均有原键、适用的expected_revision和必要审计；Web列表只投影已授权绑定。宿主注册不授予第二个当前状态写宿主，也不授予跨入口缓存、独立审计或模型工作权限。令牌新增媒体／路由／事件权限默认空，不从旧操作权限推导。公开端口允许语义化类型与错误码在本次装配中冻结，不回写旧令牌、历史输入摘要或旧确认结果。

### 3.2 外部地址与Host／Origin校验（已批准）

外部origin与内部bind／port拆开声明，都由部署参数提供：外部origin允许省略协议默认端口，内部监听端口单独声明。地址解析后分别校验：

- **Origin：** 按规范化后的`(scheme, host, effective_port)`完整比较，scheme与域名小写，缺省端口由该Origin自己的协议补全（HTTP为80、HTTPS为443）；不能为了显示时省略端口而丢掉协议或有效端口。浏览器WS握手的Origin使用页面的HTTP／HTTPS来源，不改写成ws／wss。拒绝`null`、多Origin、重复Origin头及非合法来源格式；无Origin非浏览器客户端的Bearer要求仍按[WS鉴权协议](external-communication.md#ws)执行。[RFC 6454 §5](https://www.rfc-editor.org/rfc/rfc6454.html#section-5)要求三字段全部相同。
- **Host：** 独立解析单一authority，与配置的外部主机及有效端口比较；Host本身没有scheme，缺省端口依据已配置外部origin的协议补全，不能依据内部监听端口或客户端代理头猜测。重复Host头、非法格式或不匹配均拒绝；Host匹配不能代替Origin检查。

例如配置`https://core.example`时，Origin为`https://core.example:443`等价，`http://core.example`和`http://core.example:443`均不等价；Host为`core.example`与`core.example:443`等价，`core.example:8080`不匹配。可信代理仅提供受控转发通路，不豁免上述检查；不信任客户端提交的Forwarded／X-Forwarded-*。

修改外部地址或代理来源属于部署变更，由部署方同步更新部署参数、反向代理、DNS和证书后受控重启；Web只读展示，不提供在线切换。旧部署值（显式端口且等于监听端口）继续有效；须核对部署参数变化不被启动流程误判为持久资源身份变化。

## 4. 完整Web与接入

前端为同容器提供的静态构建资源，不运行前端开发服务器。页面以中文业务含义解释状态，基础操作不要求用户理解表名、命令数或内部规划编号。兼容API的封套版本显式区分，不靠前端自行合并不同owner的权威记录。

Provider配置及连接测试入口通过独立Provider和计量端口，受身份、用途确认、有限请求数和专注门控约束；不因名为测试而绕过登记、停发或清理。

首次引导包含唯一角色、初始自我材料、persona生成目标与监管规则、Provider及受保护凭据引用、平台／入口、三段长度、学习事件、梦境周期和专注选项。服务实际环境时区先展示，允许确认或修改，持久保存；不假定容器继承宿主时区，不改变旧传输协议对明确偏移的要求。

引导可保存和恢复未完成进度；配置预览、验证、初始化执行和首次persona审核分别呈现，不把保存表单当作生效。拒绝或中断保留原证据和原键。演示三段窗口只总结中段，解释自我认知、persona、当前状态和目标的不同所有者与更新节奏。

日常页面覆盖[现行管理行为](../product/operations-and-management.md)：入口与批次、梦境积压／回流、当前记忆／完整来源、遗忘与实际使用、当前persona／待复核、状态、目标、媒体、Provider计量与未知结果、诊断日志及独立开发者审计。分页与游标有界；区分成功零输出、普通失败、敏感拒学、积压和已移交。历史正文不能经agent查询或普通页面回灌。

外部宿主通过受令牌限制的公开HTTP完成原始接收、回复准备／查询、实际使用反馈及现行状态／目标管理；命令使用原幂等键，错误封套固定且不泄漏秘密。专注期拒绝普通业务写及召回，只允许已批准的原始接收、只读观察、原确认及受控梦境管理例外。主动通知仅按[已批准HTTP／WS协议](external-communication.md#ws)开放；不新增永久重放服务。

恢复遗忘和删除对象先读取当前对象／revision及影响摘要，再要求明确确认；事务内重新检查权限、revision、共享来源和资源释放计划。删除不可把对象独占来源、其他共享holder或未决模型资源清理错归一方。冲突返回新的预览需求，不以旧确认执行新对象状态。恢复仅适用于仍存在的合法遗忘对象，不从审计复活已删除正文；管理员浏览不记作宿主实际使用。

| 凭据与权限 | 选宿主、入口多选、操作多选、允许路由／事件、有效期；签发、列表、撤销、轮换引导 | 原始令牌只在新建成功时显示一次；显示实际有效／过期／撤销及关联连接，不把“未撤销”当“有效” |
| 通知路由 | 创建、查看、启用／禁用、revision、宿主／入口、允许事件、当前消费者、关联未结束目标数量 | 连接离线时明确“目标可保存，提醒可能无法送达”；禁用不删除目标或清除UNKNOWN |
| 连接与投递 | 有界分页的连接列表、各路由订阅、接入时间、最后心跳、队列占用、未确认量、按路由接管记录、安全断开；最近最小投递事实 | 区分待起算、宽限内待发、门控暂停及剩余时间、未发送、等待接收确认、已确认、结果未知及实际清理中；显示观察时间与后端截止，不在浏览器重置计时；接管标明受影响路由，超限提示实例争用；整连接断开预览全部订阅；无批量重发按钮 |
| 通信设置 | 启停WS、心跳／超时／容量、提醒时序／并发／宽限；外部地址与代理来源只读展示，并生成不含秘密的代理配置片段；见[通信配置分层](configuration.md#external-communication-configuration) | 显示默认／候选／实际值、来源、受影响连接、生效方式、失败原因；需重启不伪装立即可用；外部地址与实际请求Host／Origin不匹配时明确提示 |
| 接入说明与联调 | 下载协议、复制不含秘密的示例；测试HTTP认证、WS握手／订阅／探针／ACK；查看每步结果 | 失败定位到地址、TLS、身份、路由、专注、队列或ACK；服务端本地自检不能冒充外部网络可达 |

#### 4.1.2 三条完整用户路径

**首次接入：** 完成现有实例初始化→进入外部连接→选择／登记宿主与合法入口→创建禁用状态的逻辑路由→签发限定入口及操作的令牌→按示例启动宿主→完成WS认证与订阅→明确启用通知路由→发送合成探针并确认→在目标页创建有deadline的目标并选择该路由。各步可重复读取持久事实；刷新页面不会再次签发令牌或自动重发探针。

**修改设置：** 读取当前版本→编辑表单→服务端整份验证→预览影响（新连接、当前消费者、未发送计划、需重启项）→明确提交激活→显示实际消费者接入结果。冲突要求重新读取；结果待确认时保留原键及原输入，不能用新键重复提交。路由启停是管理对象操作，不伪装成通用配置patch。

**断线诊断：** 概览显示宿主离线→连接页显示最后心跳和安全原因→查看目标仍存在及各投递事实（宽限计时／暂停与已终结未发送分开显示）→修复宿主并重连（同一宿主可显式接管指定路由，其他订阅保持）→订阅确认→查询当前目标／状态。页面不得把UNKNOWN显示为“失败可重试”，也不得因重连成功抹去过去未送达。

#### 4.1.3 目标页面与权限表单联动

目标创建／修改期限页使用合法路由下拉选项，显示对应宿主、入口、启用和在线状态；非空deadline缺少合法路由时阻止提交并给出配置入口。只有一个合法默认候选时可以预选，保存结果显示实际绑定；多个候选必须明确选择。允许保存暂时离线或禁用的合法路由，并显示当前不可送达，不把网络在线作为目标存在的前置。

管理员与外部宿主都通过同一领域校验，不能只在前端补默认值。旧目标的route不可因默认配置变化悄悄改到另一个接收方。路由被引用时不能硬删除；禁用保留归属和审计，变更接收方通过新路由及逐目标revision更新。

权限支持多选与清楚分组：接收／媒体、召回／反馈、状态、目标、通知／运行观察、原键确认。默认不全选；查询权限不附带管理、审计、运行观察、媒体上传或深召回。原键确认仍限定原宿主／入口及操作，不提供跨主体查询结果的捷径。

#### 4.1.4 联调、秘密与可访问性

提供两种明确区分的检查：浏览器本地测试票据验证同源WS通路；真实宿主探针验证指定在线消费者的接收及ACK。测试票据只能接收探针，不能代收目标提醒、占用正式单消费者路由或读取业务数据。探针由用户明确点击才发送，带独立原键、有限次数与无模型说明；专注期拒绝新探针。

普通配置、二维码／示例、日志和下载文件不嵌入Bearer值。令牌原文仅新建时展示，离页清除，不写localStorage、URL或历史列表；未知签发结果先确认，再通过受控撤销／重新签发恢复，不能从持久摘要还原秘密。

真实浏览器验收包含键盘完整流程、焦点恢复、390／600像素布局、无横向溢出的表格／详情、颜色以外的状态提示、字段错误定位，以及刷新／重复点击／多页并发编辑。不以截图或静态页面替代实际服务端交互。

## 5. 配置版本、预览与激活

采用[配置模块](../modules/configuration.md)的唯一注册表、显式验证和不可变快照。每个可编辑键声明权限、类型、范围、敏感级别、生效边界及跨参数约束；未知键、未知字段及非法组合整份拒绝。不把账号明文口令／API key存入普通配置版本，只保存受保护引用及必要版本元信息。

配置工作流贯通：读取脱敏Schema／有效版本→提交有expected_revision的补丁→整份候选验证与差异预览→确认生效计划→持久激活→观察完成／恢复。预览显示影响哪些模块、是否等待原任务、需重启还是不支持迁移；保存新版本不等于激活。专注期普通配置写入继续拒绝，不排队代执行。

| 参数变化 | 固定处理 |
| --- | --- |
| 普通运行参数／角色prompt与profile等可安全重新绑定项 | 元数据明确下一事件、下一请求、下批次或下run生效；旧冻结工作完整保留原快照、profile、prompt、Schema和凭据引用 |
| 需替换资源或协调多个消费者 | 关闭相应新准入，等待安全边界，预备完整资源；以持久激活记录和有效指针确认，全部消费者同步完成前不宣布新配置生效 |
| 数据库／资源路径、监听、外部origin／可信代理来源与装配布局 | 标为需受控重启；按[部署身份](#external-origin)区分网络参数与持久资源身份，禁止偷偷移动数据库或把原库当新库 |
| embedding空间、未声明升级路径的旧格式或其他需迁移项 | 清楚拒绝为本版不支持的迁移；已批准的当前托管格式升级仅按[显式升级路径](#communication-deployment)执行，不自动重建或牺牲旧回执兼容 |

激活有独立持久意图，明确区分候选、已准备、已决定的目标版本及各消费者是否完成接入；提交成功后消费者恢复失败时保留原决定、关闭受影响准入并续办，不谎报回退完成。未提交的资源准备失败可释放候选资源，原有效版本继续。状态查询同时给出权威版本、实际消费者状态和清理状态。

配置、runtime激活事实和必要审计同短事务提交，I/O和等待均在事务外。当前内存快照必须对应持久有效指针；崩溃后按原激活键恢复，不能混用新旧消费者。失效预备资源归原操作清理，实际清理与激活是否确认分别表达。

领域对象的出生配置身份与当前运行配置版本必须区分：启用新版本不得让旧对象、来源或原Provider请求因绑定旧snapshot而不可读；不能全库覆写历史snapshot来绕过校验。新增版本解释由新装配明确承担，原格式拒绝保持。回退是对旧配置内容创建新的受审激活，不倒退业务数据、原幂等键、账本或已用额度；不能关闭旧UNKNOWN隔离来完成回退。

### 5.1 通信配置消费者（已批准）

通信参数纳入本节激活协议，参数来源和完整组合见[通信配置](configuration.md#external-communication-configuration)。普通参数用于新连接／新尝试；路由禁用、权限撤销需在新发送前立即核验，不能等旧连接自然过期。旧已开始尝试保留原配置引用及清理责任。降低容量、切换origin／代理、升级协议需分别声明排空或受控重启；回退配置不清空原UNKNOWN、计划、令牌撤销或已发送事实。

配置策略激活与路由／权限对象写分开处理。维护关门、消费者接入和恢复需向goals交接[宽限计时依据](../modules/runtime.md#communication-gate-clock)，不能把一次配置激活当作重新开始宽限。新连接／新尝试使用已确认版本，旧计划及其宽限继续保留冻结引用；下调容量先预览排空，不释放尚未结束的I/O。

| 容器路径 | 所有者与用途 |
| --- | --- |
| `/data/bootstrap` | 持久建库身份、资源绑定及管理引导状态；访问受限 |

| `/data/indexes` | 派生词法／向量文件，只有已发布且核验的代次可查询 |
| `/data/logs/runtime`、`/data/logs/index` | 统一诊断日志和可重建观察索引，不替代同事务审计 |
| `/data/backups`、`/data/backup_staging` | 已完成备份与未完成临时副本，不能先给未完成副本“可恢复”标记 |
| `/run/secrets` | 部署方只读挂载的认证秘密；不从Web任意路径读取，不包含在默认备份或导出中 |

这些路径及所属资源的安全级别按管理员可见处理。补齐统一配置的非public路径能力；不能仅把实际敏感路径贴成public以通过旧校验。实际记录同库关系、禁用的可选导出、全部受保护目录和别名关系，核验所有者、权限、符号链接、文件身份、可写性、可用空间及单进程占有。拒绝把数据库、媒体、备份或凭据目录当作静态HTTP目录。

沿用已批准SQLite运行库准入、WAL／FULL／外键及唯一写者；工程实际核验见[生产前置](persistence-and-transactions.md#runtime-production-prerequisites)。容器非root运行，用户主机路径不硬编码；Compose给出明确回环端口及持久卷。默认备份同卷只能防部分操作／升级错误，不声称防宿主盘丢失；提供受认证的完整备份下载供部署方另存。

一致备份先持久记录请求及唯一备份身份，建立有界静止点，停住相关新写和GC，确认本地事务与文件发布责任安定后，保存一致数据库、仍需保留的媒体／上传、索引清单、启动身份、配置版本及原恢复证据。必要原回执、UNKNOWN和责任不能丢弃；不能仅复制一个活动`.sqlite3`文件后称作一致备份。无法在边界内安定则明确延期／失败并保留原业务状态，不强制取消在途资源。

备份启动前、文件复制中、完成标记发布前后及恢复切换前后分别验证进程中断；每一处都能判定原库仍权威、备份不完整或新资源已完成，不能靠猜测目录是否存在。保留原数据库身份和请求身份，另设切换所有权以防两份恢复副本同时具备发送权。

完成前核验各文件长度／摘要、声明版本、清单路径及引用完整性，原子发布完成标记。恢复先在新的隔离资源上验证，拒绝路径逃逸、符号链接、版本错误、缺文件和摘要不符；原库不被覆盖。相同业务身份恢复不得同时运行两个可发送实例。确认原实例停止、原进程资源结束及可信切换身份后才能接入；恢复默认本地零发送，需显式开启后续新工作，未知请求继续隔离。

## 7. 升级、运行观察与工程资源

版本包包括不可变镜像／版本标识、依赖锁、装配与兼容声明、启动检查和健康观察。升级前预检目标版本与当前格式，保留一致备份和原镜像；首份托管交付支持声明兼容格式的升级；本次增加的当前托管格式显式升级按[下节](#communication-deployment)执行，禁止静默迁移试验库。失败后保留原权威数据和实际切换状态。

首份托管产品没有历史正式发布版；升级回归可使用本阶段建立的两个实际不同、格式兼容的受控构建，记录代码差异、镜像摘要及兼容范围，不能以同一镜像换标签代替。该证据不外推所有历史试验库或未来任意版本。

代码回退要求旧版本仍能解释当前数据和全部已提交工作；否则拒绝自动回退并说明所需维护。备份恢复不是无损代码回退，不抹除升级后输入。SIGTERM有界关闭但保留实际未决责任；重启确认数据库、原请求与清理后再报告READY。资源不足、故障、暂停和未初始化分别显示，健康探针不触发模型或业务恢复重放。

镜像先支持实际验证的Linux arm64；不自动增加amd64、第二平台或长期压测。保留现有小档约束与至少2GiB宿主可用预留，备份前计算额外空间，空间不足拒绝操作，不删除旧库／证据或申请800GiB。新增Dockerfile、Compose及生产启动入口须可直接执行，静态前端实际构建入镜像；由正常启动命令托管信号、健康及持久资源，而非只给一段示例配置。具体镜像、运行时及新增库由执行者核实官方兼容资料、维护锁文件并记录实际版本；不机械升级已可用依赖。

沿用配置总编码524288、普通命令1MiB、唯一配置初始化2MiB、静态声明8MiB和现有材料边界。新增Schema、认证／激活／备份记录须先做全份实物容量；若合法组合不能容纳，提供实际字节、原限制位置和最小扩容方案，停止受影响部分，不截断或拆成未批准的半事务。所有身份集合、会话、令牌、历史列表、请求体、并发和临时I/O有显式有界配置，长期业务数据按原产品生命周期保留。

### 7.1 外部通信部署与当前托管格式升级（已批准）

提供两套可复现的部署档：

1. **本机／显式私网档：** 保留默认回环发布、非root、只读根、持久卷和受保护秘密。HTTP／WS可共用端口；只有明确受控边界可使用明文。容器服务间开放必须显式声明网络，不因WS新增通配公网映射。
2. **受控TLS代理档：** 增加代理Compose资源与配置，提供HTTPS／WSS、明确外部origin、代理来源白名单和证书只读挂载。Core内部端口仅向代理开放；不信任任意客户端提交的Forwarded／X-Forwarded-*。代理原样转发客户端Host（外部端口非默认时保留端口）；应用按[地址校验](#external-origin)规范化比较Host／Origin，Secure cookie依外部origin的协议决定。管理员Web保持同源，应用保留独立认证和权限。

代理处理Upgrade、空闲超时、请求／响应大小及长连接关闭；应用负责心跳、ACK与身份。代理空闲超时须大于心跳周期加余量，且不短于提醒总时限。代理缓冲、框架发送队列可能延迟实际网络写，迁移时要保守界定“可能已交付”，不能沿用旧StreamWriter假设宣称可撤回。部署说明必须包括外部443／内部8080、证书替换、重启、健康探测、实际代理来源核验和失败回退。代理行为以锁定版本实测，不只给示例片段。[NGINX官方说明](https://nginx.org/en/docs/http/websocket.html)要求显式处理Upgrade／Connection及空闲超时。

单应用进程持有原数据库／文件资源租约，禁用自动reload及多worker。监听器生命周期（采用ASGI备选时即其lifespan）接入原统一宿主恢复和SIGTERM流程，不启动第二份调度器。健康检查分开表达监听活着、持久恢复完成、业务READY、WS可接入与通知被专注暂停；不得因探针触发模型或通知重发。

关闭先停止HTTP／WS新准入和新派发，再按有界期限等待原工作、关闭连接并报告未决资源；强制进程结束后仍可从原账本判定UNKNOWN及原提交。还原备份后不得恢复在线连接、测试票据或旧发送权；宿主重新认证，现有模型发送许可及UNKNOWN限制保持。

**当前托管格式升级已批准：** 先核对新路由／配置／通知记录能否在明确声明的兼容扩展中存储；需要新格式时，已授权继续实现当前托管格式到新格式的显式维护升级，先一致备份、预检、隔离准备、确认原实例停止，再切换权威资源。保留database／instance／幂等键／配置历史／目标／媒体／全部未决事实。中断可判断旧库仍权威或新库已提交，禁止原地猜测补表。旧镜像不能解释新数据时拒绝无损代码回退；恢复旧备份可能丢失切换后数据，不能自动当回退执行。

交付新安装及当前托管实例升级两条实际路径，不把“重建一个空实例”当作升级。历史试验格式继续拒绝；若兼容范围超出本节已批准决定，暂停该部分而不清库绕过。

## 8. 集中验收矩阵

本节保留首份托管产品的验收口径，作为本次相关回归依据；外部通信增量按[通信验收矩阵](external-communication.md#acceptance)连续完成，最终统一交付，不等待中途阶段验收。本次通信验证使用模拟模型，新增真实供应商请求为0，不引用下方原管理交付的真实调用条件扩大本次范围。

| 能力 | 必须验证的正常及失败边界 |
| --- | --- |
| 新安装与重开 | 新卷／新实例、非root目录、单进程互斥、SIGTERM／强制进程结束、持久卷重建容器、启动零发送及实际环境 |
| 引导与persona | 一次性引导凭据、重复提交／中断续办、时区确认修改、唯一SELF、生成后审核／拒绝、原键发布与待审核界面 |
| 身份与隔离 | 登录限速、会话过期／退出／撤销、跨站请求、错误Origin／Host、令牌入口／操作限制及撤销竞争，普通宿主不能取得管理／审计 |

| 管理写 | 人工恢复／删除、共享来源／媒体、revision竞争、确认失效、重复请求、必要审计；不回灌历史、不强化管理员浏览 |
| 配置激活 | 新旧冻结工作并存、整份候选拒绝、专注拒写、资源准备失败、提交确认丢失、消费者同步中断、原键恢复及配置回退保留业务数据 |

| 升级回退 | 实际两个兼容版本的受控升级／失败／回退，切换后新接收数据保留；不兼容版本拒绝而非自动迁移 |
| 容量与故障 | 完整注册表／Schema／初始化实物，空间／只读／锁竞争／I/O失败，慢HTTP、迟到任务和真实清理；错误封套及所有权不降级 |
