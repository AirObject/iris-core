## 9. 内部上下文与成本控制

<a id="source-line-686"></a>

### 9.1 分离两个上下文构建器

`AgentContextBuilder`给内部学习/梦境模型组装材料；`ReplyInformationAssembler`给外部宿主返回分区信息。外部仍负责最终聊天context的编排。不能为了方便把内部监管prompt、开发者审计或完整来源全部交给外部。

学习prompt建议结构如下，顺序是逻辑展示，具体缓存边界由协议适配：

```text
固定任务与权限约束
固定输出schema、双指标量表和S2范围规则
版本化persona与必要自我信息
受限的相关正式记忆（ID/版本/性质/来源）
[S3: 历史辅助，仅理解]
[S2: 唯一目标，必须有锚点]
[S1: 最新辅助，仅理解]
本次操作预算及输出约束
```

保存prompt模板版本、persona版本、模型profile版本、目标/辅助消息ID、召回材料ID与token估算；不只保存一段无法解释来源的最终字符串。

<a id="source-line-705"></a>

### 9.2 请求频率控制

按批次而非每条消息调用LLM。以S2每批100条为纯示例，每天20,000—30,000条对应约200—300次基础学习调用；实际还包括提前触发、媒体理解、梦境和必要工具循环。100不是默认参数。

若S3和S1各10条，上述示例每轮携带120条材料，单是辅助输入的消息数量开销约为目标段的20%。实际token开销取决于长度分布，不能用“消息数比例”冒充准确计费。

正常批次采用消息数与token预算共同约束；在冻结前选择能处理的S2。冻结后不能为省钱静默裁掉目标消息，再将整批标为成功。单条超长内容需要显式分片/提取策略或处理限制，不以无记录截断代替完整来源保存。

<a id="source-line-713"></a>

### 9.3 避免重复花费

仅为正式记忆的可检索语义表示生成embedding，默认不为每条原始聊天、每个来源窗口或每次分数变化生成向量。零记忆批次不产生记忆embedding请求。使用供应商支持的批量输入，按最大条数与token限制拆分。

向量缓存键包含内容hash、embedding空间指纹、维度和预处理版本；修改分数不重算，正文变化才使对应向量失效。不同供应商同名模型不自动视作同一空间。

媒体先复用外部理解，再复用可跨情境的已有内部理解；hash相同不代表所有情境解释都可复用。已经明确拒绝的材料不以换模型重试作为默认优化。

persona只在梦境更新。梦境先处理有来源变化、生命周期变化或到期的对象；周期全库校验分块执行，不能每次把全部记忆发给LLM。对新目标先本地查候选再判断相似，不为每对目标单独付费。

固定任务、schema和稳定persona可形成重复前缀，在支持的provider上利用prompt caching；实际命中需要满足供应商的匹配、长度和有效期规则，不作为必然折扣或一秒保证。[S12](references.md#s12)[S13](references.md#s13)

### 9.4 预算与吞吐观察

[M13](../modules/provider.md#contract)以同一账本汇总每类工作的调用次数、token/媒体量、已知或估算费用、成功/失败/拒学、缓存命中和调用时长；[M02](../modules/runtime.md#contract)提供工作排队年龄，[M05](../modules/cognition.md#contract)/[M11](../modules/dream.md#contract)提供业务批次结果，通过关联ID组合而不重复计费。学习、媒体、embedding、rerank与梦境分别计量。

先提供可配置的单轮输入/输出预算、最多工具步数、provider并发上限、每周期调用量及费用提醒。预算暂停和provider故障分开；暂停不得伪装成成功或敏感拒绝，不暗中丢弃未处理输入。

批处理吞吐可粗略用`并发数 × 平均目标消息数 / 平均批次耗时`估计，再用真实负载验证。梦境回流期间也观察最早积压年龄；只看平均队列长度会掩盖某个入口长期得不到处理。

后台学习不得长期占满在线查询embedding所需的连接/配额。可预留小的在线请求预算；API有整体配额限制时仍会降级，而不是突破供应商限制。
