## 17. 故障、提醒与审计

<a id="source-line-863"></a>

### 17.1 运作原则

输入信息可能价值密度较低，系统不以无损保留每条消息为目标。有限失败丢弃可以接受，但必须区分未送达、待学习、学习中、成功零结果、普通失败终结和敏感拒学终结，不将它们统一伪装成“已记住”。普通失败终结后按三段规则丢弃目标并留尾，不无限保护该失败批次；专注梦境无条数上限的暂存属于独立规则，不能借普通容量限制淘汰它。

不管理业务重试，不意味着没有错误返回、风险标记、运行日志或状态展示。它也不意味着允许重复请求造成重复强化等不受控副作用。

<a id="source-line-869"></a>

### 17.2 provider 长期故障

provider 长期不可用、反复失败导致学习无法正常进行时，向外部提醒记忆系统出现故障，需要修复，并在面板显示。

哪些条件构成长期故障、报警频率和解除条件需配置。没有可靠发送通道时，提醒本身也可能无法送达，不能承诺绝对通知成功；本系统不可用时尤其不能保证自己向外部报警。

非专注模式下，仍可读取的已存记忆与学习能力故障应区分；专注梦境门控优先，即使数据库可读也仍拒绝外部召回。不能因为 provider 不可用就把所有失败称为敏感拒学，也不能把既有记忆说成丢失。

<a id="source-line-877"></a>

### 17.3 传输与业务状态

发送连接的底层负责有限重试，超过次数后丢弃该次无法交付的信息。业务层不新增永久重发、死信恢复或自动重放服务。

底层重复投递仍可能发生，因此建议接收操作识别重复事件或反馈标识；这种重复副作用防护不属于业务重试管理。

提醒送达不等于目标完成；提醒丢失不删除目标；使用反馈丢失可能导致本次没有强化记忆，系统不凭空补记“已使用”。外部完成反馈丢失时，系统也不能推断目标完成。

<a id="source-line-885"></a>

### 17.4 突然失忆风险

突然失忆风险只标识明确敏感拒学导致的本轮独占未提交内容清理，说明可能存在经历缺口。它不同于正常遗忘、普通链路失败以及普通学习失败终结。普通失败保留历史尾部；敏感拒学不保留尾部，下一轮历史辅助为空。

建议在有关入口的回复准备和管理面板展示受影响时间范围等运行元信息，外部决定是否对用户表达。风险记录不复制已清除正文。

<a id="source-line-891"></a>

### 17.5 审计隔离

日志记录记忆修改、删除、分数变化、学习故障和管理操作等，供开发者审计。历史正文只存在于这类日志中时，agent 不能通过记忆查询、深度召回、来源遍历、媒体目录或通用文件工具读取它。

日志不可因导出、通用检索或自动导入被无意回灌给记忆 agent。仅审计引用不纳入媒体业务引用统计，清理后审计中的文件链接可能不可用。

<a id="source-line-897"></a>

### 17.6 缺口、积压与恢复信息分别显示

已终结失败的输入不再占用待处理计数，但失败的事实及受影响时间范围仍可在运行状态中查看。正在梦境序列中的输入只是延期处理，不应被计为学习失败；已移交正常队列也不等于已经形成记忆。

专注梦境期间正常业务告警投递也受交互隔离限制，Web保留故障可见性。系统自身完全不可用或存储损坏时，不能保证还能自己发出提醒；实际故障监控与恢复策略由运维设计提供，不伪装为缓存语义已经保证可靠交付。

## 20. Web 管理面板

<a id="source-line-986"></a>

### 20.1 初始化引导

首次启用引导至少包含：唯一角色、初始自我材料、persona生成目标与监管prompt、平台接入和各平台三段参数、默认学习事件、梦境周期及专注选项。界面说明三段按时间排列为S3→S2→S1，标明“只总结S2”，用两轮消息示例展示中段尾部如何成为下一轮历史辅助。

支持有预设身份和无预设身份，不另建两套系统。默认persona目标为稳定发言风格与充分认识自我，界面说明其属于外部过程监督，而不是一条普通角色观点。

<a id="initial-default-timezone"></a>

**默认时区产品决定已获用户批准。** 首次默认采用服务实际运行环境的时区，由Web初次引导展示，允许用户确认或修改；确认后的时区由统一配置持久保存。容器不能假定继承宿主时区，初始展示须反映服务实际所在环境。工程交付状态见[STATUS](../work/STATUS.md)。

明确携带时区的输入按其明确时区解释；默认时区用于相应输入和展示边界。内部UTC持久时间及[现有要求明确偏移的传输接口](../architecture/local-information-feedback.md)保持，不因默认时区而接受这些接口原本拒绝的无偏移时间。该决定不追溯改写旧事件、旧模型输出或既有质量标注；“上午”等模糊精度不能被默认时区转换成任意精确时刻。

Web初始化及配置衔接统一见[首期产品计划](../architecture/managed-runtime-and-deployment.md#web)；不因初始化展示而改写旧事件时间协议。

<a id="source-line-992"></a>

### 20.2 图形解释

界面需要图形解释自我认知、稳定persona、当前状态和目标的区别，不能仅提供多个无解释的文本框。图形应表达如下关系：

```text
初始材料＋持续经历 → 丰富且可变化的自我认知
                                  ↓
外部生成目标＋监管prompt ───→ 梦境中的提炼与检查 → 稳定persona

外部当前活动／游戏细节／情绪 → 当前状态与持续时间 ──┐
多个未来目标／待办           → 目标集合与提醒 ─────┼→ 外部组织context与具体执行
稳定persona＋相关记忆＋本入口近期输入 ────────────┘
```

“我偏好温和表达”可影响稳定persona；“我现在紧张”属于当前状态；“明天提醒朋友一件事”属于未来目标。三者相互相关，但具有不同管理者和更新节奏。

<a id="source-line-1008"></a>

### 20.3 日常页面

| 页面 | 主要内容 |
| --- | --- |
| 入口与学习 | 每个群／直播间的S1/S2/S3、目标ID、实际窗口、成功／失败／拒学终态和历史尾部 |
| 梦境积压与回流 | 每入口暂存数量、最早／最新接收时间、已移交量、正常队列余量与回流错误 |
| 记忆与来源 | 当前正文、类别、双指标、真实依据及完整上下文 |
| 遗忘与深度使用 | 遗忘对象、强度、阈值、实际使用反馈与恢复状态 |
| 自我与persona | 自我认知、当前摘要、生成时间、监督配置和待复核关系 |
| 当前状态 | 外部管理的活动、细节、情绪、持续时间和最后更新时间 |
| 目标 | 多个未结束目标、截止与提前量、来源、去重、完成和放弃 |
| 梦境 | 周期、专注选项、访问拒绝状态、内部整理进度、回流阶段、上次成功及整理结果 |
| 媒体 | 理解状态、业务引用、无引用清理和清理记录 |
| 开发者审计 | 历史版本与操作；独立权限，不向agent暴露 |

面板管理功能与agent工具权限分开。人工恢复、删除、来源检视及确认边界见[已批准管理交付](../architecture/managed-runtime-and-deployment.md#web)；不能因为开发者能看日志，就给agent同样读取能力，也不能把开发者浏览误当成宿主实际使用记忆。

<a id="source-line-1025"></a>

### 20.4 关键配置展示

面板应解释双阈值而不是只给一个“遗忘百分比”；显示相信程度量表；区分普通队列软上限、处理中批次保护及梦境暂存无条数上限；三段长度按平台分别编辑并显示每个入口实际范围；每个目标保存自己的提醒提前量；当前状态和persona分区展示。

专注梦境启用前应明确说明：除原始输入外业务请求全拒绝；输入独立积压且不学习；Web仍可查看状态；梦境结束后按入口正常批次回流。说明状态管理和使用反馈不会排队代执行、提醒在专注期暂停，以及无条数上限不保证物理资源无限。异常退出、错过提醒和回流开放时点的具体配置应清楚显示，不以笼统开关掩盖。
