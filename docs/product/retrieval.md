## 15. 对外信息获取与入口边界

<a id="source-line-696"></a>

### 15.1 两类获取请求

外部宿主的信息获取分两类：准备做出回复时获取 persona 和相关情境信息；主动获取某个方面的记忆。

输入接收、状态管理、目标注入、使用反馈和系统主动提醒是另外的操作，不改变这两类获取行为的定义。本节的成功返回仅适用于允许业务服务的模式；专注梦境时两类获取请求连同深度召回全部拒绝，明确返回正在梦境中，不返回空结果或旧快照冒充成功。所谓主动召回，是系统在回复准备请求中主动补齐相关记忆，不是无请求推送全库内容。

<a id="source-line-702"></a>

### 15.2 第一类：回复准备

外部提供本次回复所属入口、参与者和情境。系统主动组织高相关信息，减少追加查询轮次；实际 context 编排由外部管理。

| 返回分区 | 内容与边界 |
| --- | --- |
| 稳定 persona | 当前已发布的统一摘要、生成时间及必要的待复核标记 |
| 相关记忆 | 高相关的有效正式记忆，保留主体、类别、相信程度及来源元信息 |
| 本入口近期缓存 | 请求所属入口正常队列的近期输入，暂以S2和S1为候选；不含其他入口、专注期积压直读或失败段伪装的正式记忆 |
| 当前状态 | 外部管理的当前活动、场景细节、情绪、持续时间和更新时间 |
| 目标与建议 | 未结束目标集合、相应状态、截止时间与建议 |
| 其他入口待处理提示 | 仅入口数量及时间信息，不含消息正文或摘要 |
| 运行信息 | 观察时间、与本请求相关的拒学缺口、故障或梦境维护状态 |

准备回复不会触发每次重写稳定 persona，也不会自动深入读取遗忘记忆。没有高相关正式记忆时，可以明确为空，不用缓存伪装出记忆。

<a id="source-line-718"></a>

### 15.3 其他入口的待处理提示

系统在可提供回复准备时，发现其他入口存在已接收、尚未作为目标终结的输入或尚未回流的梦境积压，必须明确提示。S1即使曾作为辅助出现仍是待处理；成功目标、失败终结目标及仅保留的S3不能继续被算作待学习。失败造成的缺口归入运行信息，不冒充待处理。提示只包含入口数量与时间类元信息，例如其他待处理入口数、相关输入时间范围和本次观察时间。

不得附带其他入口的缓存正文、摘要、主题、人物或从缓存推导出的事实。示例：

> 截至本次观察，另有2个入口存在尚未处理的输入，相关时间范围为20:10至20:13。

示例中的数量和时间不是实际数据。最终字段格式待接口设计，不应把该区域扩展成其他入口内容的预览。

该提示只能基于已经进入系统的输入。接入中断或平台状态未知时，不能宣称其他平台没有消息。跨入口实时一致性暂缓，因此提示是观察快照，不是实时全局保证。

<a id="source-line-730"></a>

### 15.4 缓存隔离与正式记忆共享

宿主不能直接获取其他入口的正常缓存或梦境缓存消息。回复准备不能因“相关性高”越过此边界，定向查询和深度召回也不是读取缓存的替代途径。

总结形成的正式记忆允许跨入口按需召回，保留来源和人物关系，不要求锁在最初产生它的入口。遗忘对象仍须显式深度召回，删除对象不可召回。

缓存隔离不是正式记忆的隐私分区保证。已形成的记忆可能包含来自其他入口的内容；本设计不声称这些内容在公开场合必然不可披露。额外的部署授权或披露策略如需提供，必须独立定义，不能与缓存规则混为一谈。

<a id="source-line-738"></a>

### 15.5 第二类：定向记忆查询

外部指定查询自身、他人、某事件或其他方面的正式记忆。普通模式只返回有效对象，不强制附带 persona，不组织一个不透明的完整回复上下文。

独立深度能力允许包括遗忘记忆，明确标识生命周期。两者都不查缓存、不查审计日志。返回的主体联系和扮演信息保留不确定性与关系类型。

目标信息可以作为独立附加区提供，不混入记忆检索命中。当前状态必须在第一类请求主动提供；第二类是否需要获取状态，使用显式能力或请求选项，不隐式把状态当记忆。

<a id="source-line-746"></a>

### 15.6 返回标识与使用路径

对外记忆结果建议带召回标识、记忆 ID、当前内容版本、生命周期、相信程度和必要出处。外部反馈实际使用的对象，而不是系统猜测“返回了就一定用过”。

专注期使用反馈请求被拒绝时不执行强化；醒来后只有符合反馈有效性规则的真实请求才可处理，不能把内部回流当成已收到使用反馈。本入口缓存、当前状态或目标被使用，不直接套用正式记忆的保留强化接口；若同时使用正式记忆，则对相应记忆 ID 反馈。是否单独收集其他信息的使用统计不属于必要的记忆强化规则。
