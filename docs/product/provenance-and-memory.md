## 8. 批次来源、窗口与对象级生命周期

<a id="source-line-349"></a>

### 8.1 窗口只能来自冻结的本批次

来源上下文采用按平台可独立编辑的固定窗口。每次学习中，前后辅助范围都限定在该批次已经冻结的三段材料内，不针对每条结果额外等待未来消息，不向其他群聊、直播间或未纳入本批次的实时队列扩展。

Web 面板分别配置历史辅助条数与最新辅助条数，并显示对应的 S3／S1 语义。学习批次使用实际得到的 S3、S2、S1；从中段形成记忆时，保存目标依据和这些批次上下文的完整原始信息，包括入口、主体、原文、引用、时间、媒体索引及理解结果。

首次运行没有历史辅助段时 S3 可以为空。目标不足或主动事件提前触发时，记录实际三段范围；不能为了填满示意窗口而借用另一入口或伪造消息。已进入批次后不再等待快照之外的消息补齐前后段。

常规成批条件、提前触发时如何从本入口未处理区选择非空目标，是批次调度参数；它们不能改变“冻结后不扩展、只总结中段”的语义。没有 S2 目标时不调用缓存总结模型。

<a id="source-line-359"></a>

### 8.2 来源快照字段

建议保存批次 ID、入口 ID、平台窗口配置版本、S3／S2／S1 消息 ID 和原始快照、实际目标锚点、解释时使用的辅助片段，以及快照时间。原始发生时间与梦境后回流时间分开记录。

平台窗口配置修改只影响后续批次，不静默修改已经保存的证据。来源可引用独立快照，多个记忆可以共享同一份完整批次材料；逻辑上必须保有原始来源，不能只指向即将释放的队列位置。

队列移除只解除运行时持有的引用。已提交记忆的来源快照继续存在；失败轮未提交快照没有特殊归档，除开发者审计配置允许保留的信息外按其所有权释放。这里的审计保留是管理配置，不给记忆 agent 增加读取权限。

<a id="source-line-367"></a>

### 8.3 中段目标、上下文和派生依据分别记录

本轮新记忆的目标锚点来自 S2，S3 与 S1 可以解释目标但不能独立成为本轮提取对象。保存了 S1 正文不等于该消息已经完成学习；S1 以后成为目标时，仍可正常分析，不因为之前出现在来源里就跳过。

从已有记忆形成的派生认知记录真实来源记忆 ID，必要时记录引用修订标识。系统可沿关系追溯共同源头，区别支持、反驳、引用和单纯语境；同一原始消息被跨批次复用不变成多份独立证据。

初始化自我、外部注入目标等管理输入使用真实来源类型，不伪造记忆 ID。内部猜测也记录实际依据和内部生成性质，不凭空构造外部证据。

<a id="source-line-375"></a>

### 8.4 遗忘和删除针对对象

遗忘只改变本记忆的生命周期，不即时级联隐藏其他记忆或其完整来源。删除只撤销该记忆对象，不立即清除全部共享来源、媒体和相似派生内容。

原对象遗忘后不参加普通召回；原对象删除后不从记忆接口或开发者日志恢复。其他认知、评价和 persona 的影响由后续梦境整理修复。仍可用来源可能包含相同信息，系统可能形成新的类似认知；不承诺内容级抹除或同源重建禁止。

梦境检查来源 ID 的存在性、修订和生命周期，不需访问审计历史。批次丢弃、对象遗忘、对象删除和来源仍被共享持有，是不同状态，不互相代替。

<a id="source-line-383"></a>

### 8.5 来源访问与外部缓存隔离

完整来源主要用于内部审查和开发者检查，不默认附在每次对外记忆结果中。跨入口可返回总结形成的正式记忆及出处元信息，不能借来源字段把另一入口仍未处理的 S1 或梦境积压正文直接提供给宿主。

是否提供独立的外部来源审查能力，应有单独的授权与返回契约。没有该契约时不默认开放跨入口完整窗口；同样不能把开发者能查看来源或日志，解释为外部 agent 能绕过缓存和审计边界。

## 9. 正式记忆与关系

<a id="source-line-393"></a>

### 9.1 记忆语义字段

以下是建议字段组，不固定最终 schema：

| 字段组 | 信息 |
| --- | --- |
| 标识与版本 | 记忆 ID、当前修订标识、创建和修改时间 |
| 内容 | 当前正文或命题、类别、陈述主体及立场 |
| 对象与范围 | 自我／他人／事物、平台入口、事件或适用时间 |
| 相信程度 | 0—100值、统一量表标识、依据和评分理由 |
| 保留强度 | 独立值、最近调整原因、生命周期需要的阈值信息 |
| 原始来源 | 依据输入、完整上下文快照、媒体索引 |
| 派生来源 | 来源记忆 ID、引用修订、支持或其他关系 |
| 生命周期 | 有效／遗忘、遗忘起点及删除保留期 |
| 整理信息 | 待梦境复核标记、来源变化与关系状态 |

旧内容版本仅保存在审计日志中。保存当前修订号是为了判断是否使用了同一份内容，不向 agent 开放历史正文检索。

<a id="source-line-411"></a>

### 9.2 主体联系

不同平台主体独立存放。相同昵称不是确定同一人的充分条件。系统可从消息中习得“小林=林同学”的联系，保存来源、相信程度及保留强度，在冲突时修正或提出询问。

关联检索保留联系的不确定性，不把低相信程度的身份关系渲染成已经确定的同一人。建立联系也不要求每次输出全部邻居信息。

<a id="source-line-417"></a>

### 9.3 扮演与其他关系

“小林—扮演—游戏角色甲”与主体同一联系分开。检索小林可提供其扮演信息，但必须明确虚构角色及其所属场景，不能将角色经历不加区分地归到现实主体。

内容相关、同一人物、支持关系和派生关系不是同一类边。梦境降低失去支持的认知强度时，应判断真正的依赖，而不是对所有同名或相似标签记忆统一惩罚。
