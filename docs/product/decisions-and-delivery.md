## 22. 待细化的参数与异常契约

三段式只总结中段、失败终结与留尾差异、专注梦境业务拒绝和每入口独立无条数上限暂存，均为系统行为。以下事项是实现需要固定的剩余参数和异常细节，不授权重新决定上述规则。

<a id="source-line-1154"></a>

### P04. 目标去重和提醒时序

确定相似目标保留哪个对象、截止冲突与字段合并、旧 ID 映射及提醒接收宿主。创建时已过期、修改截止到过去、过期重复提示等需固定策略，不默认全平台广播或无限补发。

专注期暂停主动业务投递。梦境跨过多个提醒时刻后，是合并为一次过期提示、仅在外部请求中显示，还是按明确策略发送，需要在通知契约中指定；不得擅自顺延目标截止。

<a id="source-line-1160"></a>

### P05. 当前状态的时间契约

确定活动标识、开始与结束、子状态时间、缺失时间标记，以及多久未更新仅标陈旧。当前值完全归外部管理，梦境不修改。

专注期被拒绝的状态更新不自动重放。可由外部在恢复服务后明确发送一次最新状态；这是调用方行为建议，不是记忆系统自动补发或从历史消息重建当前值的保证。

<a id="source-line-1166"></a>

### P06. 多媒体结果的有效性

每媒体对象已提供完整理解则复用、缺失则正常阶段补充、明确敏感拒绝使用固定占位。需确定空文本、一般失败和部分结果的结构化状态。专注期不做媒体理解，回流后按正常规则处理。

一般媒体失败是否允许在新的明确事件中重新理解，与不管理业务重试保持一致。敏感占位不能被当作缺失而自动回退绕过。

<a id="source-line-1172"></a>

### P07. 使用反馈、来源访问与persona发布细节

固定反馈有效期、修订匹配、重复计分防护，以及临近删除时迟到反馈的处理。深度读取不恢复、实际使用提高强度并达到阈值才恢复、删除对象不复活均不变。

需要独立定义对外完整来源审查权限，避免跨入口来源附带尚未总结的辅助原文。persona 候选未通过监管检查时不发布；具体检查、故障标识和上次成功摘要展示格式需固化。

<a id="source-line-1178"></a>

### P08. 短批次、最新辅助段和提前触发

冻结批次不等待批次之外的未来消息，来源范围也不再扩大。仍需固定正常目标长度、token上限、主动触发遇到未满S2时的切分，以及长期安静入口的末尾S1是否通过明确的空闲／手动事件转入目标。

建议把未满批次和尾部刷新定义成可配置的正常学习事件，并在建立批次前确定目标和可为空的辅助段；不能冻结后再把S1偷偷改为本轮目标。无目标时不调用总结模型。

<a id="source-line-1184"></a>

### P09. 模式切换、回流开放时点与异常退出

专注期间业务拒绝范围已经固定。实现仍需明确：进入前已有在途请求和学习如何安全收尾，梦境提交后是否立即开放业务服务，回流期间新输入接尾的操作次序，以及梦境崩溃／中止后如何解除门控和恢复回流。

建议梦境内部整理结束后即可恢复业务，入口回流继续独立推进；使用模式与积压元信息说明新鲜度。这是待固化的阶段切换策略，不隐含必须等待所有入口积压清空，也不隐含异常时可丢掉梦境缓存。

Web只读状态持续开放；管理员强制终止、恢复或配置写入需要独立权限与确认契约，不能仅因“Web可打开”默认获得。

<a id="source-line-1192"></a>

### P10. 暂存介质、重启与物理资源故障

梦境序列没有业务条数上限。需要选定可增长的暂存介质、崩溃恢复范围、磁盘和内存告警，以及真实资源不足时如何如实返回接收失败。不得用普通队列容量代替梦境序列上限，也不承诺不存在硬件极限。

普通调用重试耗尽后的批次已明确失败终结并留尾，不作为悬而未决的长期积压。剩余持久化与提交问题包括：结果提交与批次消费如何对齐，重启后是否重做终结，以及如何避免来源和媒体引用错删。具体技术选型不能改变单次终结和所有权规则。

## 23. 参数与工程配置

| 项目 | 设计约束／配置状态 |
| --- | --- |
| 角色数量 | 一个实例一个角色 |
| 入口 | 每个群聊、私聊、直播间独立队列；跨入口并发与实时一致性暂缓 |
| 三段方向 | 时间从旧到新为S3历史辅助→S2目标→S1最新辅助 |
| 本轮目标 | 只总结冻结的S2；S3/S1仅理解，不自动变为已处理 |
| 平台窗口 | 每平台独立编辑S3和S1条数；范围限定本批次，不等待未来补齐 |
| 目标批次长度 | 可配置；短批次、token预算与空闲尾部触发待参数契约 |
| 普通容量 | 处理中批次可超过软上限；终结后按对应轮转规则释放 |
| 成功／零结果 | 正常轮转，S2最新尾部成为下轮S3；零结果无特殊归档 |
| 普通调用失败 | 底层重试耗尽后失败终结，丢弃目标并留尾，不业务重试 |
| 敏感拒学 | 只清理该轮独占未提交内容；新S3为空；媒体仍定时清理 |
| 学习事件 | 默认集合、关注信号、内部主动事件；专注梦境暂停普通触发 |
| 相信程度 | 暂采统一0—100接受量表；50未定，非客观概率 |
| 保留强度 | 独立量，建议0—100；初值、增益与衰减待配置 |
| 遗忘／恢复阈值 | H必须大于F；20／35仅行为示例 |
| 防抖 | 双阈值；可加保持期和周期降幅限制，数值待配置 |
| 遗忘保留期 | 可配置；30天仅示例 |
| persona | 统一摘要，常规更新仅梦境；首次生成纳入初始化 |
| persona监督 | 外部目标和监管prompt；默认稳定发言风格与充分认识自我 |
| 梦境周期 | 低频；具体周期、工作预算与异常退出契约待定 |
| 专注期业务访问 | 除原始缓存输入外全部拒绝，明确返回正在梦境中；Web只读状态例外 |
| 梦境缓存 | 各入口独立，无业务条数上限，只暂存不学习、不媒体理解 |
| 梦境回流 | 梦境结束后按各入口顺序转正常路径，采用相同三段及终结规则 |
| 回流完成含义 | 暂存移交完成，不等于全部形成记忆；正常尾部继续受正常触发管理 |
| 业务恢复时点 | 建议梦境内部结束后恢复、回流独立推进；具体切换契约需固化 |
| 当前状态 | 外部独占管理；持续时间与更新时间分别表达；专注期拒绝写入 |
| 未来目标 | 多个并行，待办统一为目标；内部生成或外部注入后去重 |
| 提醒提前量 | 每目标加入时由内部agent或外部决定 |
| 过期处理 | 提醒放弃或修改截止继续，不自动结束；梦境跨期通知策略待定 |
| 跨入口缓存 | 正常与梦境缓存均不向其他入口提供；只提示数量和时间 |
| 跨入口正式记忆 | 可按需召回，保留来源、类型、相信程度和生命周期 |
| 传输重试 | 底层有限次数；业务层不管理重试；未送达信息可丢失 |
| 长期provider故障 | 对外和Web表明需修复；主动投递受专注模式与通道可用性限制 |
| 媒体清理 | 定时清理无业务引用文件；梦境暂存与S3算引用，仅审计引用不保护 |
| 部署与技术栈 | 独立服务与自带Web；语言、模型、数据库、暂存介质和协议未指定 |
| 运维与审计 | agent与日志隔离；权限、重启、告警、备份与保留策略待工程设计 |

## 24. 实施与验收组织

先将已明确的行为写成可验证契约，再落到schema、接口和代码。三段的目标与辅助角色、三类终态、专注业务门控、每入口梦境序列和FIFO回流，应在接入真实模型之前用固定消息标识验证。本文的验收场景描述期望行为，不表示已经实现或测试了实际记忆系统。

建议按以下闭环实施，每一阶段同时覆盖正常、边界与失败路径：

| 阶段 | 可验收闭环 |
| --- | --- |
| 输入与三段队列 | 单角色、多入口、S1/S2/S3、批次快照、只总结中段、成功与零结果轮转 |
| 失败与来源 | 普通失败留尾、敏感拒学不留尾、批次独占清理、完整来源、媒体引用 |
| 正式记忆与召回 | 分类、双指标、主体联系、两类请求、入口缓存隔离与数量/时间提示 |
| 生命周期与反馈 | 深度召回、真实使用反馈、双阈值恢复、对象删除与审计隔离 |
| 专注梦境与回流 | 业务全拒绝、输入独立暂存、无条数上限、Web可见、按序正常批次回流 |
| 自我与低频persona | 初始自我、监管prompt、来源影响修复、梦境发布及失败不发布半份摘要 |
| 现在与未来 | 外部当前状态、持续时间、多目标、注入去重、期限与提醒 |
| 运行与管理 | Web图形引导、各入口计数、模式切换、物理故障可见和媒体清理 |

不可用简化实现改变产品含义：不把辅助段当目标、不把失败当成功、不把梦境回流当失败重试、不把其他入口消息混批、不把无条数上限改成按普通容量淘汰、不把Web状态查看扩大成专注业务放行。

未来所有技术选择都应接受同一套行为检验。没有确定的参数显式保留为配置，不以随手选择的常量替代产品决定。

系统的运行闭环是：真实来源输入进入各入口队列，按三段批次形成可追溯认知；外部通过回复准备与定向查询取得适用信息，实际使用反馈调节保留强度；当前状态由外部管理，多个未来目标由系统保存与提醒；梦境修复认知并形成稳定自我摘要，专注时只积压原始输入，结束后依入口顺序回到正常学习。角色如何认识世界和自身由本系统管理，如何表达与具体行动由外部宿主决定。
