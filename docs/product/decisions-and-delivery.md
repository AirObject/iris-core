## 22. 待细化的参数与异常契约

三段式只总结中段、失败终结与留尾差异、专注梦境业务拒绝和每入口独立无条数上限暂存，均为系统行为。以下事项是实现需要固定的剩余参数和异常细节，不授权重新决定上述规则。

<a id="source-line-1154"></a>

### P04. 目标去重和提醒时序

确定相似目标保留哪个对象、截止冲突与字段合并、旧 ID 映射及提醒接收宿主。创建时已过期、修改截止到过去、过期重复提示等需固定策略，不默认全平台广播或无限补发。

专注期暂停主动业务投递。梦境跨过多个提醒时刻后，是合并为一次过期提示、仅在外部请求中显示，还是按明确策略发送，需要在通知契约中指定；不得擅自顺延目标截止。

<a id="source-line-1160"></a>

### P05. 当前状态的时间契约

确定活动标识、开始与结束、子状态时间、缺失时间标记，以及多久未更新仅标陈旧。当前值完全归外部管理，梦境不修改。

专注期被拒绝的状态更新不自动重放。可由外部在恢复服务后明确发送一次最新状态；这是调用方行为建议，不是记忆系统自动补发或从历史消息重建当前值的保证。

<a id="source-line-1166"></a>

### P06. 多媒体结果的有效性

每媒体对象已提供完整理解则复用、缺失则正常阶段补充、明确敏感拒绝使用固定占位。需确定空文本、一般失败和部分结果的结构化状态。专注期不做媒体理解，回流后按正常规则处理。

一般媒体失败是否允许在新的明确事件中重新理解，与不管理业务重试保持一致。敏感占位不能被当作缺失而自动回退绕过。

<a id="source-line-1172"></a>

### P07. 使用反馈、来源访问与persona发布细节

固定反馈有效期、修订匹配、重复计分防护，以及临近删除时迟到反馈的处理。深度读取不恢复、实际使用提高强度并达到阈值才恢复、删除对象不复活均不变。

需要独立定义对外完整来源审查权限，避免跨入口来源附带尚未总结的辅助原文。persona 候选未通过监管检查时不发布；具体检查、故障标识和上次成功摘要展示格式需固化。

<a id="source-line-1178"></a>

### P08. 短批次、最新辅助段和提前触发

冻结批次不等待批次之外的未来消息，来源范围也不再扩大。仍需固定正常目标长度、token上限、主动触发遇到未满S2时的切分，以及长期安静入口的末尾S1是否通过明确的空闲／手动事件转入目标。

建议把未满批次和尾部刷新定义成可配置的正常学习事件，并在建立批次前确定目标和可为空的辅助段；不能冻结后再把S1偷偷改为本轮目标。无目标时不调用总结模型。

<a id="source-line-1184"></a>

### P09. 模式切换、回流开放时点与异常退出

专注期间业务拒绝范围已经固定。实现仍需明确：进入前已有在途请求和学习如何安全收尾，梦境提交后是否立即开放业务服务，回流期间新输入接尾的操作次序，以及梦境崩溃／中止后如何解除门控和恢复回流。

建议梦境内部整理结束后即可恢复业务，入口回流继续独立推进；使用模式与积压元信息说明新鲜度。这是待固化的阶段切换策略，不隐含必须等待所有入口积压清空，也不隐含异常时可丢掉梦境缓存。

Web只读状态持续开放；管理员强制终止、恢复或配置写入需要独立权限与确认契约，不能仅因“Web可打开”默认获得。

<a id="source-line-1192"></a>

### P10. 暂存介质、重启与物理资源故障

梦境序列没有业务条数上限。需要选定可增长的暂存介质、崩溃恢复范围、磁盘和内存告警，以及真实资源不足时如何如实返回接收失败。不得用普通队列容量代替梦境序列上限，也不承诺不存在硬件极限。

普通调用重试耗尽后的批次已明确失败终结并留尾，不作为悬而未决的长期积压。剩余持久化与提交问题包括：结果提交与批次消费如何对齐，重启后是否重做终结，以及如何避免来源和媒体引用错删。具体技术选型不能改变单次终结和所有权规则。

## 24. 实施与验收组织

先将已明确的行为写成可验证契约，再落到schema、接口和代码。三段的目标与辅助角色、三类终态、专注业务门控、每入口梦境序列和FIFO回流，应在接入真实模型之前用固定消息标识验证。本文的验收场景描述期望行为，不表示已经实现或测试了实际记忆系统。

建议按以下闭环实施，每一阶段同时覆盖正常、边界与失败路径：

| 阶段 | 可验收闭环 |
| --- | --- |
| 输入与三段队列 | 单角色、多入口、S1/S2/S3、批次快照、只总结中段、成功与零结果轮转 |
| 失败与来源 | 普通失败留尾、敏感拒学不留尾、批次独占清理、完整来源、媒体引用 |
| 正式记忆与召回 | 分类、双指标、主体联系、两类请求、入口缓存隔离与数量/时间提示 |
| 生命周期与反馈 | 深度召回、真实使用反馈、双阈值恢复、对象删除与审计隔离 |
| 专注梦境与回流 | 业务全拒绝、输入独立暂存、无条数上限、Web可见、按序正常批次回流 |
| 自我与低频persona | 初始自我、监管prompt、来源影响修复、梦境发布及失败不发布半份摘要 |
| 现在与未来 | 外部当前状态、持续时间、多目标、注入去重、期限与提醒 |
| 运行与管理 | Web图形引导、各入口计数、模式切换、物理故障可见和媒体清理 |

不可用简化实现改变产品含义：不把辅助段当目标、不把失败当成功、不把梦境回流当失败重试、不把其他入口消息混批、不把无条数上限改成按普通容量淘汰、不把Web状态查看扩大成专注业务放行。

未来所有技术选择都应接受同一套行为检验。没有确定的参数显式保留为配置，不以随手选择的常量替代产品决定。

系统的运行闭环是：真实来源输入进入各入口队列，按三段批次形成可追溯认知；外部通过回复准备与定向查询取得适用信息，实际使用反馈调节保留强度；当前状态由外部管理，多个未来目标由系统保存与提醒；梦境修复认知并形成稳定自我摘要，专注时只积压原始输入，结束后依入口顺序回到正常学习。角色如何认识世界和自身由本系统管理，如何表达与具体行动由外部宿主决定。

## 持久接入与批次运行的产品选择补充（推荐方案已批准）

**状态：本节五组推荐涉及的产品选择已获用户批准；其他产品问题及未采纳替代不因此获准。** 对应[整体技术契约](../architecture/durable-ingress-and-batch-runtime.md)；集中批准决定在其[批准表](../architecture/durable-ingress-and-batch-runtime.md#decisions)，数值及定义仅在[配置补充](../architecture/configuration.md#ingress-runtime-configuration-draft)维护。采用配置§11.14.6完整显式合成配置及绑定格式；本节替代选项均未采纳。实施状态及本次用户转交授权见CURRENT_TASK。

### 短批次、安静尾部与正常容量

本次采用仅启用THRESHOLD：按正常三段推进，在目标候选达到T时取最旧T项。未满目标和最新辅助继续保留，不因为入口安静或回流已清空而强制学习。下表选定值仍须显式提供，不能直接进入代码默认值。

可选EXPLICIT_SHORT须有独立授权的学习触发身份、稳定trigger_key且配置启用；当目标候选不足T时取最旧的全部非空目标候选，最新辅助保持其角色。若只有最新辅助而无目标候选，返回NO_TARGET，不把最新段偷偷变目标；达到T时与正常批次取法一致。不因触发而等待未来消息补齐已冻结材料。

可选IDLE_TAIL是允许安静尾部转目标的**独立正常学习事件**：空闲判定取本入口最后一条已确认接收的时间及受控时钟，达到配置间隔且无活跃批次后，在冻结前把本入口最旧至多T条未消费输入作为目标，剩余紧邻至多R条作最新辅助，可以为空。目标仍非空，不借另一入口，不重新纳入已失败／拒学终结目标。重启不复用旧单调时间戳，推荐重新等待完整空闲间隔，避免时钟回拨或停机时长导致立即批量触发；事件按入口和已确认输入水位去重。

短批和空闲事件冻结后遵守相同范围、引用与三终态。材料预算不足不自动截断正文、跳过最旧消息或缩小既定辅助范围，显示CONTEXT_LIMIT；本范围没有修改已初始化配置的入口，不能把“以后调整配置”当作当前可执行恢复。具体持续影响与替代见下方超限选择。没有目标不调用模型。

| 选择 | 推荐及影响 | 替代 |
| --- | --- | --- |
| 显式短批 | 已批准关闭；启用分支只用于显式不同测试配置，不能自动改变选定配置 | 启用上述EXPLICIT_SHORT，可提前处理目标候选，但不冲刷只有最新辅助的尾部 |
| 空闲尾部 | 已批准关闭；安静入口可长期保留未学习尾部，状态页明确显示 | 启用上述IDLE_TAIL并选定间隔，增加调用频率，最新辅助可能为空；或以后另定义带独立权限的手动尾部事件，本范围不提供Web按钮 |
| 普通容量 | 已批准只将normal_soft_limit作为软水位与调度告警，除合法终结不自动淘汰任何未消费输入 | 若要普通运行容量淘汰，另定义目标选择、终态、来源保护与可见缺口；不借此限制专注暂存或误删在途数据 |

### 上下文超限反例与已选方案

**保留的超限反例（未执行，非当前推荐配置）：** E=4096、H=2、T=8、R=2、材料限额6144字节、模拟输入单位限额8192，短批／空闲尾部关闭。当前推荐值及静态核算另见[配置候选](../architecture/configuration.md#runtime-compatible-budget-candidate)，不能拿它替换本反例的前提。新入口无历史，依次接收10条不同事件ID、每条正文恰为1024个ASCII字符的文本事件，其余用最小合法身份、null时间、空引用／媒体／extensions；未来夹具须断言每条完整事件编码小于4096，其他存储／profile条件合法。若采用未采纳的宽接收策略，十条均可获持久接收回执，首次目标为seq1–8、最新辅助为9–10。仅目标正文已有8192字节，超过6144；含最新辅助的正文为10240字节，已超过8192输入单位，尚未计入任何模板／标签。当前模拟计量为Provider消息text的UTF-8字节总和，不当作真实token数。

因此首次冻结返回CONTEXT_LIMIT，没有可发送的冻结批次、没有Provider调用、没有业务终态，10条仍未消费。新输入不改变最旧8条及其紧邻辅助；重启恢复同一不可变配置也不改变预算，切换模式／回流或多次调度不能解决。**这是同一数据库内可持续、无本范围解除入口的队首阻塞**，并非等一会儿就会恢复的临时资源竞争。后续新接收仍可持久增加积压并最终遇到物理资源不足，其他入口在共享基础设施正常时可独立推进。Web须显示“已接收、未学习、上下文预算阻塞”，不能显示普通失败已丢弃或建议一个不存在的配置按钮。

| 已批准：新库初始化时强制接收限额／窗口预算相容 | 采用[确定配置候选](../architecture/configuration.md#runtime-compatible-budget-candidate)及其绑定的固定合成格式；按完整H＋T＋R和合法事件最坏材料检查，不相容配置整组拒绝。数值与上界已获批准，执行验证尚待完成，[单条空间／触发／辅助的代价](#runtime-compatible-budget-impact)明确列出；不是解析时自动改值，不保证资源可用、真实模型适配或旧库解堵 |
| 未采纳：保留原数值及实际冻结时拒绝 | 保持宽接收承诺与固定窗口；承认合法接收不保证能学习，同库可以持续阻塞。无自动丢弃／超时跳过，输入仍保留；必须由用户接受无当前解除能力的代价，不能将其描述成推荐方案已保证进展 |
| 另选：冻结前按预算取最旧非空目标前缀 | 将T改为上限、在冻结前确定可容纳的最长FIFO前缀，固定历史及紧邻最新辅助仍完整保留；冻结后范围永不改变。须新批准这种短批触发／切分语义，调用频率和历史演进会变化；不暗开原EXPLICIT_SHORT或IDLE_TAIL。最旧单条加固定辅助仍放不下时仍阻塞，若要求普遍可推进仍需至少该最小窗口的接收相容约束 |
| 另行扩展：已有同库的配置变更或受控迁移 | 可保留全部正文及FIFO，在未冻结工作前使用获批新配置；但需要持久版本发布、权限、失败原子性和在途冻结保留，或保全原身份／回执／输入的迁移与切换方案。本次无这些能力，不能以新建空库丢下旧输入冒充解堵 |

前三项是互斥行为；本次已批准第一项的确定候选及完整显式参数集，现有合法参数范围／材料硬上限不因此扩大。不自行批准丢弃、跳过目标、正文截断、缩减已冻结辅助、将系统超限记为FAILED_DROPPED，或以多个模型调用拆一批绕过原冻结和终结协议。初始化后不可改约束也意味着：即使另一个新库的参数更合适，旧库输入不会自动迁入或解堵。

新增验收预期（执行证据见[CURRENT_TASK](../work/CURRENT_TASK.md)）：按已批准相容方案，上例配置在任何建库／接收前即被完整解析拒绝；测试相容显式配置的最坏合法满窗口、单事件边界、模板开销及不同平台，并断言超出接收限额的新输入安全拒绝。上述10次接收后持续阻塞及可变目标前缀行为仅为未采纳替代的技术比较，不作为本次实现分支。

### 已批准合成参数的产品影响

数值定义及上界代入唯一见[配置候选](../architecture/configuration.md#runtime-compatible-budget-candidate)，格式与最小事件账目唯一见[合成材料协议](../architecture/durable-ingress-and-batch-runtime.md#synthetic-window-material)。推荐仍是固定阈值窗口，绝不自动改成可变前缀；其他四组决定、审计增量、日志权限及分层恢复方案均已获本次明确批准。

| 变化 | 可供用户判断的影响 |
| --- | --- |
| 完整接收事件限额从反例4096降为1024字节 | 不等于正文可写1024字节：同一最小字段例留下779字节普通ASCII正文空间；3字节汉字可容纳259字。较长主体／事件ID、显示名、真实时间及引用继续占同一限额。某些原本各字段均合法的长身份／引用组合会整体超限拒绝，不能缩短标识、丢引用或截正文后确认接收 |
| 固定目标从8条变为2条，最新辅助从2条变为1条 | 无历史的新入口首次达到阈值需要3条新输入，而反例需要10条；持续有输入、参与者和预算始终可用且每批一次生成时，稳态每2条目标形成一批，相比每8条约增加至4倍批次频率。实际调用／费用还受失败、有限尝试、模式与账户窗口约束，不能承诺固定吞吐或费用 |
| 历史辅助从2条变为1条 | 每次成功或普通失败按原规则最多保留本批目标末1条，敏感拒学仍清历史；最新辅助也最多1条。窗口更短、可用上下文更少；是否满足未来真实认知需求尚未验证，不能以合成结果判断质量 |
| 材料限额调整为现有硬上限8192字节 | 给完整固定模板／引用／编码留足静态空间，没有扩大硬上限，也没有增加模型步骤；模拟输入8192／输出1024仍是明确预算。Base64材料可逆但不代表真实模型理解质量，实际模型需要另审模板／计量 |
| 短批与空闲尾部仍关闭 | 只有最新辅助或不足固定目标的安静尾部仍可长期未学习；预算相容只消除该候选格式下的大小矛盾，不改变正常触发事件或保证所有输入最终学习 |

新接收超限须在承诺接收前明确拒绝；已确认输入仍按原保留、FIFO和三终态处理。候选不迁移已有同库数据，也不让反例库在重启后自动换参数；初始化后的配置不可改、故障解除缺口及生产前置不变。选用当前推荐配置和选用保留反例是不同产品选择，二者不能共同宣称“原宽接收限额不变且完整窗口都可发”。

### 入梦收尾、发布后开放与异常

推荐进入准备状态即拒绝新普通业务／发送并将新原始输入转专注暂存；已经开始的模型调用可在总收尾期限内取得结果并本地提交，但不再发新普通attempt或工具模型步骤。确定从未发送且无业务写效果的冻结工作可安全停放，已开始工作须取得明确本地终结证据。UNKNOWN、未决写、部分调用后无法结案或资源未结束导致FAULTED，不强行进梦。

Provider初始门控／预算／容量阻止不是学习失败。对于能证明从未发送且原逻辑请求已关闭的工作，推荐在NORMAL恢复后的明确重新准入事件中至多申请一次新逻辑请求，持久保存admission_generation及旧阻止关联；一次事件不得反复刷新预算或周期换键重试。事件身份按work_id及模式开放epoch或可信内部显式事件ID去重；无明确事件继续等待。曾发出调用、未知或已失败终结批次不适用该例外。

推荐内部整理和发布均确认完成后开放普通业务，实例标DRAINING、各入口分别回流；已清空入口不等待最慢入口，页面说明尚未吸收全部暂存输入。业务开放不能直接读取未移交暂存正文，也不表示回流每条都已形成记忆。回流未清空时不启动下一轮专注梦境，避免未定义的嵌套run和回流归属。

| 选择 | 推荐及影响 | 替代 |
| --- | --- | --- |
| 在途收尾 | 仅已开始调用及本地提交收尾；不为进入梦境放宽发送门控。未结束时保守故障可见 | 可以另定义允许完整旧认知run继续发模型的排空模式，但须重定发送竞争边界及预算，不能沿用此草案就默认放行 |
| 业务开放点 | 发布和退出模式事务均确认后开放，回流独立推进；服务可用性与新鲜度分开 | 等全部入口移交后开放将引入全局积压等待，偏离当前推荐，须用户明确改选并同步模式表；不以此替换已定入口隔离 |
| 崩溃／中止 | 已持久结果只本地恢复；没有可靠完成证据则FAULTED保持关闭，原暂存和上次稳定发布保留 | 自动重跑梦境、按检查点继续模型、UNKNOWN按普通失败结案或人工恢复都需要独立异常操作契约与有限成本规则 |
| 管理操作 | 本次只有Web只读观察，无强制停止、清空积压、解锁、重放失败或费用结清按钮 | 若业务上必须人工解除门控，应先预览run／epoch／未决调用／发布状态，采用单独管理权限、expected revision、幂等键、明确确认和同事务审计；Provider未知费用仍不可被批次结案清零。该操作尚未批准／包含 |

上述管理缺口是实际可用性边界：原提交确认、Provider本地恢复结束或资源释放只解除对应未知／占用，不自动把持久FAULTED改成NORMAL；暂无故障解除操作时可持续关闭。存储全校验超过原预算也可能持续不能启动，运行检查点不能接续它，详见[分层启动](../architecture/durable-ingress-and-batch-runtime.md#runtime-startup-layers)。不能把运维重启描述为已经批准的配置修改、未知费用结案或门控解锁。

非专注梦境不因本次专注门控实现而自动完整支持。测试可证明普通业务不会被非专注标识无故关闭，但真实非专注认知整理与外部发布协调仍需其独立业务契约。
