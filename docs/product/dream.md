## 16. 梦境、专注隔离与入口缓存回流

<a id="source-line-756"></a>

### 16.1 梦境职责

梦境是低频认知整理阶段，不生成伪造经历。它检查来源、矛盾、支持关系和保留价值，修复修改、遗忘、删除及恢复的下游影响，并在外部监管 prompt 约束下更新稳定 persona。

梦境可内部整理生成未来目标、复核已有目标的认知依据，但不监控实际执行，不改写外部管理的当前状态。角色仍只有一个统一认知主体，因此专注梦境是实例级业务隔离；消息积压和回流仍按具体入口独立组织。

<a id="source-line-762"></a>

### 16.2 内部整理与发布

```text
进入梦境阶段
  → 按专注配置设置业务访问门控
  → 检查当前认知、来源状态、共同根输入和修订
  → 分别评估相信程度、保留强度及真实依赖
  → 对象级修正、遗忘、到期删除、关联影响整理
  → 形成必要的目标或高维建议
  → 按外部监管prompt提炼并检查稳定persona
  → 发布成功的整理结果／摘要，记录运行结果
  → 结束梦境；各入口积压按正常路径回流
```

内部梦境可以使用完成整理所需的模型和内部工具。“梦境缓存不请求”是禁止积压输入触发正常学习、媒体理解或外部业务交互，不是禁止梦境本身的内部 provider 调用。

建议只发布经过成功处理和检查的结果；persona 候选不合格时继续保留上一份已发布摘要并显示失败。全局大事务不是既定要求，但不得把半份 persona 当成已完成摘要。

<a id="source-line-780"></a>

### 16.3 专注模式的入口门控

专注模式在 Web 初始化时可选择。正式进入专注梦境后，所有外部业务请求一律拒绝；唯一的业务输入例外是原始缓存消息接收。Web 只读运行状态仍可访问。

有限首次初始化管理的已批准例外见[文本学习契约§5.1](../architecture/model-driven-text-learning.md#initial-persona-retry)，该限定细化只在集中正文维护。

被拒绝的请求必须明确返回“正在梦境中”，不得用空记忆、空 persona、假成功或旧上下文包伪装成成功服务。拒绝不会暗中将请求排入梦境缓存，也不会承诺醒来后自动执行。

建议使用稳定业务状态如 `DREAMING`，具体 HTTP 状态和字段在接口阶段确定。输入接收可以同时返回“已进入梦境缓存、尚未学习”的回执；这不表示普通请求已恢复。

| 能力 | 专注梦境期间 |
| --- | --- |
| 原始消息／感知／自身实际输出和行动事件的接收 | 允许，进入该入口梦境缓存，不学习 |
| 第一类回复准备 | 拒绝，明确正在梦境中；不返回旧persona与缓存包 |
| 第二类普通记忆查询 | 拒绝 |
| 独立深度召回、来源读取 | 拒绝 |
| 实际使用反馈 | 拒绝，不暗中更新保留强度或排队执行 |
| 当前状态写入 | 拒绝，不借消息缓存绕过外部状态管理接口 |
| 目标注入、状态修改、截止修改 | 拒绝，不以积压消息形式偷偷执行管理操作 |
| 外部学习触发、配置写入等业务操作 | 拒绝；不启动新的普通学习 |
| Web运行状态与进度查看 | 允许，只读，不视为记忆召回或使用 |
| 梦境所需的内部认知整理与模型调用 | 允许，受梦境自身预算和监管约束 |

普通消息中可以描述外部发生过的行动、状态或目标，但积压消息日后学习不等于重放曾被拒绝的状态写入、目标注入或使用反馈命令。

与外部进行的主动业务交互、目标通知和意图投递在专注期暂停，不让普通调度器一边声明隔离一边继续向宿主发起交互。运行回执与明确的梦境状态拒绝不属于主动行为。梦境跨过提醒时刻后的补发或合并策略待时序契约决定；暂停本身不删除目标，也不自动延长截止。

<a id="source-line-805"></a>

### 16.4 每入口独立的梦境缓存

专注期到达的输入按原入口进入梦境专用序列，不进入正在用于认知整理的正常批次。每个群聊、直播间各自排队；不建立混合所有平台的一个全局消息总结队列。

梦境序列没有业务层条数上限，不因普通缓存容量滚动淘汰，不设填满后自动学习，也不调用 provider 补充媒体理解。外部已经给出的理解结果可作为输入原样保存；缺失的理解等待醒来后正常处理。

原文、引用、角色、入口、事件时间、接收时间和媒体关联完整保留。梦境暂存和已有普通批次持有的媒体都算业务引用，不能被无引用文件清理误删。

无条数上限不表示物理内存、磁盘或进程永远不会失败。建议使用可增长的隔离暂存介质，而不是把无限积压等同于无限驻留内存；本设计不擅自添加一个自动删旧输入的隐藏阈值。真实存储失败必须如实拒绝接收并显示故障，不能返回已接收后无记录丢弃。持久化、重启和资源告警策略仍需工程确定。

<a id="source-line-815"></a>

### 16.5 梦境结束后按入口回流

梦境结束后，每个入口分别将梦境序列中的消息按该入口的接收顺序弹出，送入正常输入／媒体处理和三段式队列。不得把全部梦境积压拼成一份超大总结，也不得把多个入口合成一个批次。

回流重新使用正常批次规则：构建 S3／S2／S1，明确只总结 S2；成功、普通失败或敏感拒学分别按[第6节](batches-and-learning.md#section-06)终结。普通失败丢弃目标但保留尾部，敏感拒学清空历史辅助段；回流不是对失败批次的业务重试。

在正常队列能够接收并确认取得该消息及媒体引用后，才从梦境序列解除其暂存所有权。这里是内部队列移交，不是额外建立外部投递重试服务。建议按消息标识防止切换中重复消费或先删后丢。

保留梦境前正常队列中尚未终结的输入，随后才是梦境期到达的输入。回流期间的新实时输入不得越过本入口尚未移交的旧积压；可暂时追加到同入口待回流队尾。不同入口可以分别回流、分别清空，不以最慢入口的积压作为其他入口推进的条件。

入口内顺序以接收序列为准，同时保留原始发生时间。回流时间不改变事件时间，不把昨晚的活动描述成刚刚发生。

<a id="source-line-827"></a>

### 16.6 清空的准确含义与业务恢复

“梦境缓存清空”指消息已移交到正常处理路径，不保证每条已经形成记忆。正常队列末尾仍可有 S1 辅助材料或未满的 S2，按正常学习事件继续处理；不因梦境序列已经清空就强制把最新段越界总结。

梦境与回流是两个可区分的运行阶段。建议在内部梦境结束并发布结果后恢复普通请求，回流同时推进；回复准备只能返回当时已发布信息与本入口正常队列，不能直接读取尚在梦境序列中的正文。这个恢复开放时点是具体实现建议，需在模式契约固定，不将其偷换为“所有入口积压清空才结束梦境”。

恢复服务后的其他入口待处理提示，计入正常待处理输入与尚未移交的梦境积压，仍只给数量和时间。已普通失败终结或敏感拒学终结的目标不再计为待处理，另以运行风险记录表示。

即使服务恢复，也不宣称已吸收全部梦境期消息。回流学习可以更新自我认知，但稳定 persona 仍等下一次梦境更新，不在每批回流时重新生成。

### 16.7 模式切换与可观测性

建议区分：正常运行、准备进入专注、专注梦境中、梦境结束后回流、故障。模式标识可由实现命名，但用户必须能看到梦境是否还在进行、各入口积压、回流进度、失败批次和上次成功摘要时间。

专注门控生效时要固定安全边界，避免普通学习结果在梦境同时修改认知。建议停止启动新的普通批次，让已经执行的批次先按既定终态收尾，再开始专注整理；期间新输入改投梦境序列。切换和异常终止的具体提交边界需要工程契约，不允许借切换清空未处理队列。

Web状态查看不解锁业务调用，不把查看行为计算为实际使用。是否提供管理员显式终止／恢复按钮及权限，需要管理操作契约；不在“Web可查看”中隐含任意写入权限。

<a id="source-line-845"></a>

### 16.8 来源支持、循环和恢复影响

来源遗忘后，依赖它的记忆在后续梦境暂时失去该份支持并降低保留强度。来源删除或修正时，重新评估评价；还有独立依据时不机械删除全部结论。

对象实际达到阈值恢复后，内部 agent 根据当前认知决定恢复哪些关联影响，不从审计读取旧正文，不把深度召回本身视为恢复。

相同根来源、角色自述和 persona 复述不能互相制造独立证据。影响遍历应防循环、去重，并区别同一缺失事件的重复扣减与后续时间衰减。共享完整来源仍遵守对象级遗忘／删除的边界。

<a id="source-line-853"></a>

### 16.9 非专注梦境与异常

未开启专注选项时，不默认启用“业务全面拒绝、输入转专用序列”的行为；仍执行认知整理与低频 persona 更新，外部请求与发布快照协调的具体方式属于实现契约，不承诺全局实时一致。

梦境中断或失败不能清空已接收的梦境缓存，也不能发布半份 persona。继续使用上次成功摘要、何时解除门控及怎样恢复回流，需要明确失败退出流程。故障可以使服务继续返回不可用，但必须在Web如实显示，不能卡住后一直假报正在正常整理。
