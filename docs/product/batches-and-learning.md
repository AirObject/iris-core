## 6. 独立入口队列、三段式批次与终结规则

<a id="source-line-207"></a>

### 6.1 一个具体入口，一套缓存总结队列

每个群聊、私聊、直播间等具体入口独立拥有正常缓存、三段边界、当前学习批次、历史辅助缓冲和梦境暂存队列。同一平台下的不同群聊也不得共用一条学习队列。

平台配置可以共用，队列内容和运行游标不能共用。一个入口达到阈值、总结失败、敏感拒学或回流积压，不清理、不推进其他入口的队列，也不要求其他入口一起凑满批次。

独立意味着语义、顺序和生命周期隔离，不承诺无限并行计算资源。实现可以串行调度或共享 provider；跨入口实时一致性仍暂缓。单个入口内部必须保持输入顺序、批次归属和轮转正确性。

<a id="source-line-215"></a>

### 6.2 三段的定义与方向

正常队列采用三段式。为了消除“前缓冲／后缓冲”在时间顺序与队列位置上的歧义，以明确的段名和角色表达：

| 段 | 含义 | 在当前批次中的用途 | 是否作为本轮总结目标 |
| --- | --- | --- | --- |
| S3：历史辅助段 | 上一轮目标中段最新的一部分，即留给下一轮的“后缓冲” | 为中段提供较早的上下文；不参与新输入的 FIFO 流动 | 否 |
| S2：目标总结段 | 本轮需要分析并决定是否形成记忆的输入集合 | 唯一的本轮总结目标，可以形成零条或多条记忆 | 是 |
| S1：最新辅助段 | 本批次快照中已经到达、位于目标中段之后的较新消息 | 提供较新的上下文；后续随正常队列流动成为未来批次的目标 | 否 |

按时间从旧到新，学习材料的排列为：

```text
[S3 历史辅助段] → [S2 本轮目标总结段] → [S1 最新辅助段]
  只辅助理解          只总结这里           只辅助理解
```

“本轮中段尾部成为下一轮后缓冲”指 `S3_next = tail(S2_snapshot, 历史辅助条数)`。它在下一轮的时间顺序中位于目标段之前，不是又变成未来消息，也不是再次进入待总结目标。

<a id="source-line-234"></a>

### 6.3 输入推进与批次冻结

新输入先进入本入口 S1。S1 达到配置长度后，较旧消息按入口顺序转入 S2。S2 达到批次条件，或其他合法学习事件触发时，固定本次三段快照与目标消息 ID；尚未出现的消息不属于这次上下文。

各平台可分别在 Web 配置历史辅助长度、最新辅助长度以及正常队列／目标批次参数。参数作用于本平台各独立入口，不把消息跨入口合并。具体默认数量与 token 预算由参数配置确定，不从参考代码复制常量。

学习开始后，本轮的 S3、S2、S1 快照不变。期间新输入可继续进入本入口正常待处理区，但不进入本轮目标、不扩展本轮来源，也不被本轮结束操作误删。实现必须按快照消息标识移除，而不是对运行中的整个 S2 执行无条件清空。

同一入口不允许两个批次同时消费相同的 S2 目标消息。仅出现在辅助段不算被本轮处理；相同原始消息在不同批次中承担不同角色时，仍使用同一来源标识。

<a id="source-line-244"></a>

### 6.4 学习指令中的范围约束

提供给内部学习 agent 的材料必须显式标明三段角色，并明确：只总结 S2；S3 和 S1 仅用于理解指代、关系、语气及事件语境。

辅助段可以帮助解释目标，但不能独立把与 S2 无关的内容提取为本轮记忆。每条本轮直接学习结果应能追到目标段中的实际锚点；其解释所引用的辅助内容另行标识。一般派生推理或梦境形成的新认知走各自来源路径，不借本轮缓存总结越过范围。

S1 出现在本轮来源中，不代表它已经完成学习；S3 再次被读到，也不是增加了一份独立证据。普通失败后留下的 S3 应保留“来自失败批次、仅供辅助”的状态，不伪装成已成功总结。

<a id="source-line-252"></a>

### 6.5 保护、容量与正式记忆的边界

缓存不是正式记忆，普通查询和深度召回均不检索缓存。正常运行的回复准备只可提供请求所属入口的近期输入，历史辅助段不必因存在于学习材料就全部对外返回。

暂采用与三段职责一致的提供范围：本入口 S2 与 S1 是近期输入候选，S3 为内部学习辅助。外部 context 编排和具体长度预算仍由宿主管理。专注梦境时不提供任何缓存正文。

正在处理且尚未终结的批次受到保护，不因正常容量到达而淘汰，可暂时超过普通队列条数。批次成功、普通失败终结或敏感拒学终结后，按相应规则释放缓存保护。保护到终结不等于保证每批输入都成功变成记忆。

<a id="source-line-260"></a>

### 6.6 成功终结：包括零记忆结果

成功完成分析并提交结果后，本轮标记成功。结果可以为零条，不建立额外长期保留机制，也不把零条结果误判为调用失败。

普通轮转为：旧 S3 解除队列引用；从本轮 S2 快照末尾保留配置数量的消息作为新 S3；本轮 S2 其他部分解除队列引用。S1 及快照之后到达的新输入保持待处理身份，按正常规则继续流动。

正式记忆已保存的来源快照、其他对象及媒体引用不因队列轮转消失。移出队列和删除正式记忆是不同操作。

<a id="source-line-268"></a>

### 6.7 普通学习失败：失败终结，但保留历史衔接

学习调用经底层有限重试仍失败时，将该批次标记为普通失败终态，不在业务层继续重试、不把整批重新放回待分析队列。

缓存按已经结束一轮分析的方式轮转：丢弃本轮目标的正常队列保留，仍将该轮 S2 快照最新的一部分作为下一轮 S3。清除该轮独占的未提交中间结果；没有成功提交的候选记忆不能成为正式认知。

保留尾部仅是为下轮新目标提供上下文，不是补做失败批次，也不意味着失败内容已经被记住。保留消息携带失败来源状态；即使以后借其他合法来源形成相似认知，也不能回写本轮为学习成功。

计数和面板必须区分“批次已终结并释放缓存”和“学习成功”。失败批次移出待处理范围，另计失败数量和时间缺口，不永久显示为仍待学习，也不伪装为零记忆成功。

<a id="source-line-278"></a>

### 6.8 明确敏感拒学：终结并切断本轮历史衔接

只有 provider 明确因敏感信息拒绝本轮学习时，执行敏感拒学终态。不能用普通超时、格式异常或输入正文关键词代替该信号。

清理本轮独占的未提交缓存内容、候选记忆和暂存来源；不保留本轮 S2 尾部。解除旧 S3 的本入口队列引用，使下一轮 S3 为空，避免旧历史辅助段被误当作这轮应保留的结果。

清除范围受所有权约束：S1 作为本轮上下文被引用，但仍属于后续待处理输入，不因被引用就变成本轮独占；后续到达的新输入、其他入口、其他批次、共享来源和已提交对象不被顺带删除。清空的是下一轮历史辅助槽位，不是擦除整个入口的未来待处理消息。

记录“突然失忆风险”，只保存批次、入口、原因和时间范围等必要元信息，不复制被清理正文。媒体不即时删除，解除相关业务引用后继续走定时清理。

媒体理解阶段的局部敏感拒绝仍按[第5节](input-and-media.md#section-05)替换为“敏感信息无法访问”，不触发整轮终结和历史缓冲清空。

### 6.9 三种终结结果对照

| 结果 | 批次状态 | 本轮正式结果 | 本轮目标段 | 下一轮 S3 | S1／后到输入 | 业务重试 |
| --- | --- | --- | --- | --- | --- | --- |
| 成功且有记忆 | 成功 | 发布可审查的记忆及来源 | 结束并正常轮转 | 保留本轮 S2 最新部分 | 保留，继续排队 | 不需要 |
| 成功且零记忆 | 成功、结果为空 | 不产生正式记忆 | 与成功相同 | 与成功相同 | 保留，继续排队 | 不需要 |
| 普通调用失败且底层重试耗尽 | 失败终结 | 不发布失败轮未提交结果 | 按完成批次方式轮转丢弃 | 保留本轮 S2 最新部分，注明失败来源 | 保留，继续排队 | 不建立 |
| 明确敏感拒学 | 敏感拒学终结 | 清理该轮独占未提交内容 | 终结并丢弃 | 为空，不保留本轮尾部 | 保留仍属后续的输入 | 不建立 |

### 6.10 滚动示例

以下数字仅演示关系，不是默认配置。设历史辅助长度为2，某轮按时间排列为：

```text
S3 = [m1, m2]
S2 = [m3, m4, m5, m6]
S1 = [m7, m8]
```

本轮只总结 m3—m6。成功或普通失败后，新 S3 为 [m5, m6]；m7、m8 继续等待未来成为目标。普通失败时 [m5, m6] 不具有已成功学习的含义。

若明确敏感拒学，新 S3 为空；不回退保留 [m1, m2]，也不误删仍待处理的 [m7, m8]。学习期间到达的 m9、m10 不在本轮冻结快照中，三种终结均不得把它们当作本轮目标处理。

<a id="source-line-313"></a>

### 6.11 终态与提交完整性

批次终态至少区分成功、普通失败丢弃、敏感拒学丢弃。成功结果为空是成功的一个结果属性，不是第四种异常。一次终结只能应用一次轮转和一次引用释放。

建议同一批次采用提交后发布、按 ID 消费和幂等终结，避免数据库写入一半却对外报告全轮失败，或恢复进程后再次删除保留尾部。提交介质损坏、服务崩溃等故障不应伪装为 provider 的普通拒绝，需按系统故障处理；具体恢复机制待工程设计。

## 7. 学习与内部自治

<a id="source-line-323"></a>

### 7.1 触发事件

学习可由本入口目标队列达到阈值、关注信号、内部 agent 主动请求等事件触发。系统提供默认学习事件和接口，允许决定关注哪些事件以及何时开展学习。不同入口独立判断触发，不为满足批次长度而混合消息。专注梦境时暂停普通学习触发，积压进入梦境序列；醒来后按正常条件处理。

学习事件与传输重试不是同一个概念：新目标输入可以触发一次新学习；普通失败后保留的历史尾部只辅助新目标，不能以重复触发事件为名将整个失败批次重新放入目标区，建立未声明的重放机制。建议提供触发去重、运行预算和暂停状态，具体参数不固定。

<a id="source-line-329"></a>

### 7.2 加工与分类

内部 agent 使用冻结的三段输入、可用记忆、自我认知及当前稳定 persona，只针对 S2 目标判断哪些信息值得形成记忆。S3与S1提供解释上下文，不能独立提取为本轮记忆。可以同时保留目标中不同人的说法、角色自己的推断和事件记录。

“某人说过X”的相信程度评价发言是否发生；“X成立”的相信程度评价X本身。两者可分别形成记忆，不相互替代。

系统可以保持未知、争议或并行解释，在新材料出现后修正。它能提出询问意图，由外部决定如何询问。

<a id="source-line-337"></a>

### 7.3 权限与持续反馈

学习可以更新长期自我认知、形成目标及评价，但不直接改写外部管理的当前状态，也不在每轮学习后生成新的稳定 persona。稳定 persona 的常规更新集中在梦境阶段。

自我认知和 persona 会影响关注与解释；经历反过来影响自我。这个反馈允许角色成长，但不使自己的结论变成自己的独立证据。

同一来源被反复总结、外部复述角色的话语、persona 再次表达同一观点，都需要识别共同源头，不按重复次数制造独立证据。
